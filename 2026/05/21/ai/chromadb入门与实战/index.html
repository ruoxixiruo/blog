ChromaDB 入门与实战

发表于 2026-05-21 分类于 ai
1，ChromaDB 介绍

ChromaDB 是一个开源的向量数据库，专为 AI 应用设计，尤其适合与大语言模型（LLM）配合使用。它提供了高效存储和检索向量嵌入的能力，是构建 RAG（检索增强生成）应用的核心组件。

  • 核心特性

    • 开源免费：Apache 2.0 协议，可自托管
    • API 简洁：Python / JavaScript 客户端，几行代码即可上手
    • 集成生态：与 LangChain、LlamaIndex、OpenAI 等无缝对接
    • 支持多种嵌入：可搭配任何 embedding 模型使用
    • 支持元数据过滤：在向量搜索的同时按 metadata 条件过滤
    • 轻量部署：可嵌入模式（嵌入式应用）或客户端/服务器模式

  • 适用场景

    • RAG（检索增强生成）
    • 语义搜索 / 相似度匹配
    • 去重与聚类
    • 推荐系统

4.4 get vs query 的区别

ChromaDB 提供了两种获取数据的方式：get() 和 query()，用途完全不同。

get() query()
用途 精确查找，按条件筛数据 语义搜索，找最相似的
检索方式 按 ID 或 metadata 精确匹配 向量相似度（ANN 近似搜索）
必须参数 不传参数返回全部 query_texts 或 query_embeddings
过滤 where 精确筛选 where 可配合向量搜索
排序 无排序，按添加顺序返回 按相似度（距离升序）排列
返回结构 平铺列表 [结果1, 结果2] 嵌套列表 [[结果1, 结果2]]

简单说：知道要找什么（已知 ID 或精确条件）→ get()；想搜和某段文本语义相似的 → query()。

9，注意事项
  • Embedding 模型一致性：查询时使用的 embedding 函数必须和添加数据时一致，否则相似度计算无意义
  • 内存占用：大量数据时注意 PersistentClient 的数据目录空间
  • ID 唯一性：集合内每个文档的 id 必须唯一
  • 批量操作性能：批量添加大量文档时，建议每批 100-1000 条
  • 距离度量：cosine 适合语义相似度，l2 适合数值相似度，ip 适合向量方向匹配
  • 数据持久化：EphemeralClient 数据在程序结束后丢失，生产环境应使用 PersistentClient 或 HttpClient
