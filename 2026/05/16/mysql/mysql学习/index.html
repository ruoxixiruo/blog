1，MySQL 简介

MySQL 是开源的关系型数据库管理系统（RDBMS），由瑞典 MySQL AB 开发，后被 Oracle 收购。

核心特点：

  • 关系型：数据以表的形式存储，表之间通过外键关联
  • 支持 SQL：遵循 SQL 标准，兼容性好
  • ACID 事务：InnoDB 引擎支持完整的事务
  • 高性能：B+ 树索引、查询缓存（8.0 已移除）、自适应哈希
  • 高可用：主从复制、组复制、InnoDB Cluster
  • 插件式存储引擎：InnoDB（默认）、MyISAM、Memory、Archive 等
  • 跨平台：Linux、Windows、macOS

存储引擎对比：

特性 InnoDB MyISAM Memory
事务支持 ✅ ACID ❌ ❌
行级锁 ✅ ❌ 表锁 ❌ 表锁
外键 ✅ ❌ ❌
崩溃恢复 ✅ 有 ❌ 无 ❌
全文索引 ✅ 5.6+ ✅ ❌
数据存储 表空间 文件系统 内存
适用场景 通用/高并发 只读/日志 临时表/缓存

MySQL 版本：

  • 5.7：JSON 支持、Generated Columns、GIS 增强
  • 8.0：窗口函数、CTE、原子 DDL、降序索引、不可见索引、直方图统计

7，多表联查（JOIN）

JOIN 是 SQL 中最重要的技能之一，用于从多张表中联合查询数据。

JOIN 执行原理：

  • Nested Loop Join：外层循环遍历驱动表，内层循环在另一表中匹配。小表做驱动表。
  • Block Nested Loop Join：将驱动表分批读入 join buffer，减少内层扫描次数。
  • Index Nested Loop Join：被驱动表的连接字段有索引，每次查找能走索引。
  • Hash Join（8.0.18+）：对驱动表建哈希表，被驱动表逐行探测匹配。
8，子查询

子查询 vs JOIN：子查询逻辑清晰，但 JOIN 通常性能更好（可用索引）。优先用 JOIN，逻辑复杂时用子查询。

11，索引原理

索引是提升查询性能最核心的手段。MySQL 默认使用 InnoDB 存储引擎，索引结构为 B+ Tree。

B+ Tree 特点：

  1. 所有数据存放在叶子节点，非叶子节点只存键值
  2. 叶子节点之间有双向指针，形成有序链表，方便范围查询
  3. 每个节点大小=一页（16KB），填满后分裂
  4. 树的高度通常 24 层（千万级别数据只需 34 层）

聚集索引（Clustered Index / 主键索引）：

  • InnoDB 的主键索引就是聚集索引
  • 叶子节点存放完整行数据
  • 一张表只有一个聚集索引
  • 建议用自增 INT/BIGINT 作主键（顺序插入，减少页分裂）

二级索引（Secondary Index / 辅助索引）：

  • 非主键的索引都是二级索引
  • 叶子节点存放的是主键值（不是行数据）
  • 通过二级索引查到主键后，再到主键索引查完整数据——这个过程叫回表

覆盖索引：查询的列全部包含在索引中，不需要回表。

联合索引：多列组合成索引，遵循最左前缀原则。

索引创建原则：

  1. WHERE、JOIN ON、ORDER BY、GROUP BY 涉及的列建索引
  2. 区分度高的列适合建索引（性别不适合，手机号适合）
  3. 频繁更新的列不适合建索引（索引也需要维护）
  4. 联合索引优于多个单列索引（减少回表）
  5. 避免过多的索引（占用空间、影响写入性能）
  6. 长字符串字段用前缀索引
  7. 超大表考虑分区表或分库分表
12，EXPLAIN 执行计划

EXPLAIN 是 SQL 优化最重要的工具。它在查询前输出 MySQL 将如何执行这条查询。

输出列详解：

列名 含义
id SELECT 序号，id 越大越先执行，相同则从上到下
select_type 查询类型（SIMPLE/PRIMARY/SUBQUERY/DERIVED/UNION）
table 访问的表
partitions 命中分区
type 访问类型（最重要），从好到差
possible_keys 可能用到的索引
key 实际使用的索引
key_len 使用的索引长度（字节）
ref 与索引比较的列或常量
rows 预估扫描行数（越少越好）
filtered 按条件过滤后的行数占比
Extra 额外信息（重要）

type 访问类型（从优到差）：

  • NULL：不需要访问表（如 SELECT 1+1）
  • system：表只有一行
  • const：主键或唯一索引等值查询，最多一行
  • eq_ref：JOIN 时用主键或唯一索引关联，每行只匹配一行
  • ref：非唯一索引等值查询，匹配多行
  • range：索引范围扫描（>, <, BETWEEN, LIKE 'X%'）
  • index：全索引扫描（遍历整个索引树）
  • ALL：全表扫描（最差，必须优化）

Extra 重要信息：

Extra 值 说明
Using index 覆盖索引，不需要回表（好）
Using where 使用 WHERE 过滤
Using index condition 使用了索引条件下推（ICP）
Using temporary 使用了临时表（GROUP BY 无索引时），需要优化
Using filesort 文件排序（ORDER BY 无索引时），需要优化
Using join buffer JOIN 用了 join buffer
Impossible WHERE WHERE 条件永远为假

EXPLAIN FORMAT=JSON：输出更详细的信息（查询成本等）。

EXPLAIN ANALYZE（8.0.18+）：真正执行查询，输出实际时间和行数。

15，查询成本计算

MySQL 优化器基于成本（Cost）选择执行计划。成本 = IO 成本 + CPU 成本。

成本计算公式（InnoDB）：

  • IO 成本：读一页的成本 = 1.0（默认）
  • 内存成本：读一行的成本 = 0.2（默认）
  • 总成本 = IO 成本 + CPU 成本

MySQL 选择总成本最低的执行计划。当优化器选错的执行计划时，可以考虑：

  • 更新统计信息：ANALYZE TABLE t;
  • 使用 hint 强制走某个索引：SELECT * FROM t FORCE INDEX(idx_name) WHERE ...
  • 调整成本常量（不推荐）

17，事务与锁

事务四大特性（ACID）：

特性 说明
原子性 Atomicity 事务中所有操作要么全部成功，要么全部回滚（undo log）
一致性 Consistency 事务前后数据保持完整性约束（redo log + undo log）
隔离性 Isolation 并发事务间互不干扰（锁 + MVCC）
持久性 Durability 事务提交后数据永久保存（redo log）

事务隔离级别：

级别 脏读 不可重复读 幻读 实现方式
READ UNCOMMITTED ✅ ✅ ✅ 无锁读取
READ COMMITTED ❌ ✅ ✅ MVCC每次读最新快照
REPEATABLE READ（默认） ❌ ❌ ❌* MVCC版本链 + 间隙锁
SERIALIZABLE ❌ ❌ ❌ 所有读加共享锁

锁的类型：

锁 说明
共享锁（S 锁 / 读锁） SELECT … FOR SHARE，允许其他事务读，不允许写
排他锁（X 锁 / 写锁） SELECT … FOR UPDATE / UPDATE / DELETE，不允许其他事务读写
意向锁（IS/IX） 表级锁，表明事务将在行上加 S/X 锁
记录锁（Record Lock） 锁定单个索引记录
间隙锁（Gap Lock） 锁定索引记录间的间隙，防止幻读（RR 隔离级别）
临键锁（Next-Key Lock） Record Lock + Gap Lock，InnoDB 默认的锁定方式

死锁：两个事务互相等待对方释放锁。

18，MVCC 多版本并发控制

MVCC（Multi-Version Concurrency Control）是 InnoDB 实现高并发读写的核心机制，读不阻塞写，写不阻塞读。

核心原理：

  • 每行有隐藏字段：DB_TRX_ID（最近修改的事务ID）、DB_ROLL_PTR（回滚指针指向 undo log 中的旧版本）
  • 通过 undo log 维护多版本数据链
  • 通过 Read View 判断某版本是否可见

Read View 可见性判断：
一个数据版本对当前事务可见的条件是：

  • 该版本的 DB_TRX_ID 等于当前事务 ID（自己改的可见）
  • 该版本的 DB_TRX_ID 小于 Read View 中最小活跃事务 ID（在快照前已提交，可见）
  • 该版本的 DB_TRX_ID 大于最大活跃事务 ID（在快照后开启，不可见）

不同隔离级别下 Read View 的生成时机：

  • READ COMMITTED：每次语句执行时生成新的 Read View
  • REPEATABLE READ：事务开始时生成一次 Read View，整个事务复用
19，主从复制

主从复制是 MySQL 高可用和读写分离的基础。

工作原理（三步走）：

  1. Master 将数据变更记录到二进制日志（binary log）
  2. Slave 的 I/O 线程将 Master 的 binlog 拷贝到中继日志（relay log）
  3. Slave 的 SQL 线程重放 relay log 中的事件，将变更应用到自身数据
