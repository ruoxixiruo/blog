2，APIView.dispatch() —— 请求入口源码

APIView 继承 Django 的 View，重写了 dispatch() 方法和 as_view() 方法。

关键设计点：

  1. as_view() 中自动给所有 DRF 视图加上 @csrf_exempt，因为 REST API 不依赖 CSRF Cookie
  2. dispatch() 的执行顺序是固定的：包装 Request → 认证 → 权限 → 限流 → handler → 渲染
  3. perform_authentication() 只有一行 request.user，真正的认证逻辑在 Request 对象里
3，Request 对象源码 —— 如何触发认证

DRF 的 Request 是对 Django HttpRequest 的封装，最核心的能力是懒认证——访问 request.user 时才触发认证。

设计精髓：

  • 懒加载：user、auth、data 都是延迟计算的，只有在真正需要时才触发
  • 遍历策略：遍历所有 authenticator/parser，找到第一个能处理的
  • 属性代理：通过 __getattr__ 把 DRF Request 上没有的属性代理到原始 Django HttpRequest，保证兼容性
4，认证组件源码 —— 以 TokenAuthentication 为例

认证组件设计要点：

  1. 所有认证器返回统一接口：(user, auth) / None / raise AuthenticationFailed
  2. BaseAuthentication.authenticate() 的三个返回值语义清晰
  3. 多个认证器按顺序尝试，第一个返回非 None 的胜出
  4. SessionAuthentication 额外做了 CSRF 检查
