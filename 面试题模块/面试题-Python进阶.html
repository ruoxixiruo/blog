Python 进阶

1. async/await 的本质是什么?

async def 定义一个协程函数,调用它返回一个 coroutine 对象,不会立即执行。await 挂起当前协程,把控制权交还给事件循环(Event Loop),让其他协程运行。

async def fetch(url):       # 只是"定义"了一个协程
    data = await http.get(url)  # await 让出控制权,等 IO 完成再回来
    return data

coro = fetch(url)           # 返回 coroutine 对象,还没执行!
result = await coro         # await 才开始执行

就像餐厅里只有一个服务员(单线程),一个客人看菜单(IO 等待)的时候,服务员不会傻站着等,而是去服务其他客人。await 就是"服务员,我去看菜单了,你先忙别的"。

扩展:Python 3.11 引入了 asyncio.TaskGroup,比 gather 更安全--一个任务失败会自动取消其他任务。协程本质是用户态协作式调度,不会像线程那样被操作系统随机切换,所以不存在竞态条件(但有协程间的逻辑交错)。

2. asyncio 事件循环是怎么工作的?

事件循环就像一个任务调度器,维护一个待执行协程队列:

while True:
    取一个 ready 的协程
    执行到 await → 挂起,注册回调(IO 完成时唤醒)
    检查 IO 事件 → 完成的把对应协程放回 ready 队列
    取下一个 ready 的协程

async def main():
    # create_task 立即调度,不阻塞
    task1 = asyncio.create_task(fetch_data(url1))
    task2 = asyncio.create_task(fetch_data(url2))
    result1, result2 = await task1, await task2  # 并发等待

asyncio.run(main())

create_task 把协程包装成 Task 放进事件循环,多个 Task 并发跑。如果不用 create_task 直接 await,就变成顺序执行了。

扩展:asyncio.Queue 是协程间通信的安全队列,支持生产者-消费者模式。asyncio.Semaphore 限制并发数,常用于限流。loop.run_in_executor() 把同步阻塞代码丢到线程池执行,不阻塞事件循环。

3. asyncio.gather() vs asyncio.wait() 的区别?

gather wait
返回值 结果列表(有序) (done, pending) 集合
异常处理 一个失败默认全部抛异常 不自动传播异常
取消 一个被取消全部取消 更精细控制
灵活性 简单直接 可设 FIRST_COMPLETED 等
  • gather(*tasks):有序、可取消、返回结果列表，一个失败默认全部受影响
  • wait(tasks):更灵活，可设FIRST_COMPLETED/FIRST_EXCEPTION/ALL_COMPLETED，返回(done, pending)

扩展:3.11+推荐TaskGroup()替代gather，用async with管理任务生命周期，异常处理更优雅。

4. 为什么协程里不能用 time.sleep()?

time.sleep()阻塞整个线程，卡死事件循环，其他协程全部饿死。必须用await asyncio.sleep(n)交还控制权。同步阻塞操作用await asyncio.to_thread()丢到线程池。

扩展:任何同步阻塞操作都会卡事件循环;IO用异步库(aiohttp/asyncpg),CPU密集用run_in_executor;3.9+asyncio.to_thread()。

5. dataclass 解决了什么问题?

dataclass一个装饰器自动生成__init__/__repr__/__eq__，替代手写样板代码。和Pydantic区别：dataclass是原生轻量方案，Pydantic多了运行时验证和JSON序列化。

from dataclasses import dataclass

@dataclass
class User:
    id: int
    name: str
    email: str = ""  # 默认值

# 自动生成 __init__、__repr__、__eq__
u1 = User(1, "张三")
u2 = User(1, "张三")
assert u1 == u2  # True,值比较

和 Pydantic 的区别:dataclass 是 Python 原生轻量方案,Pydantic 多了运行时数据验证和 JSON 序列化。FastAPI 大量使用 Pydantic 做请求体校验。

扩展:field(default_factory=list)解决可变默认值;frozen=True创建不可变实例;3.12+kw_only=True强制关键字参数。

6. match/case 比 if-elif 强在哪?(Python 3.10+)

match/case匹配数据结构，支持解构列表/字典、守卫条件(if)、OR模式(|)、通配符(_)，比一堆isinstance+if-elif清晰得多。

match command:
    case ["quit"]:
        print("退出")
    case ["go", direction] if direction in ("north", "south"):
        print(f"向{direction}走")
    case {"cmd": "login", "user": name, "pwd": _}:
        print(f"用户{name}登录")
    case _:
        print("未知命令")

支持解构列表/字典、守卫条件(if)、OR 模式(|)、通配符(_)。比写一堆 isinstance + 层层 if-elif 清晰得多。

扩展:适合AST/JSON解析等场景;3.11+优化执行速度;_是通配符也会被赋值。

7. __new__ 和 __init__ 的区别?

  • __new__:创建对象(分配内存),是类方法,返回实例。先执行
  • __init__:初始化对象(设置属性),是实例方法,返回 None。后执行
class Singleton:
    _instance = None
    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance  # 单例模式核心

单例模式用 __new__ 拦截对象的创建,确保只创建一个实例。

扩展:__new__ 返回的如果不是当前类的实例,__init__ 不会被调用。不可变类型(int、str、tuple)的实例在 __new__ 阶段就确定了值,所以修改不可变类型需要用 __new__。现代方案中,单例更适合用模块级变量或依赖注入。

8. 什么是上下文管理器(Context Manager)?

上下文管理器是with的背后机制，保证资源正确获取和释放，即使抛异常也执行__exit__。contextlib.contextmanager装饰器可用生成器更简洁地实现。

扩展:__exit__返回True可吞掉异常;ExitStack管理多个动态上下文;closing()给只有close()的对象加with支持。

9. 什么是 TypeVar 和泛型?

泛型让函数/类的结构不变但适配不同类型，TypeVar保证类型安全和精确推断。

TypeVar核心价值:让返回值类型与输入类型保持一致，类型检查器可自动推断。

from typing import TypeVar, List

# 没有泛型:返回值类型跟输入没关系
def first_old(items: List) -> ???:  # 不知道该返回什么类型
    return items[0]

# 有泛型:返回值和输入类型一致
T = TypeVar('T')
def first(items: List[T]) -> T:
    return items[0]

# 类型检查器能自动推断:
# first([1, 2, 3]) → 返回 int
# first(["a", "b"]) → 返回 str
# 调用方知道精确类型,IDE 自动补全也更准

# 1 无约束(最常见)
T = TypeVar('T')
def get_first(items: list[T]) -> T: ...

# 2 有约束(只能是某些类型)
Num = TypeVar('Num', int, float)  # 只能是 int 或 float
def add(a: Num, b: Num) -> Num:
    return a + b

# 3 上界约束(必须是某类的子类)
from typing import TypeVar
T = TypeVar('T', bound='Animal')  # 必须是 Animal 或其子类
def make_sound(animal: T) -> str: ...

# 4 协变/逆变(高级用法,了解即可)
# covariant=True:子类型可以替换父类型
# contravariant=True:父类型可以替换子类型

from typing import TypeVar, Generic, List

T = TypeVar('T')

# 通用分页响应
class PageResponse(Generic[T]):
    items: List[T]
    total: int
    page: int

# 使用时
user_page: PageResponse[User]    # 用户分页
order_page: PageResponse[Order]  # 订单分页
# TypeVar 保证了 items 里的类型和外面声明的类型一致

# 老语法
from typing import TypeVar
T = TypeVar('T')
def first(items: list[T]) -> T: ...

# Python 3.12 新语法--直接在函数签名里写泛型
def first[T](items: list[T]) -> T:
    return items[0]

# 带约束
def add[T: (int, float)](a: T, b: T) -> T:
    return a + b

扩展:Python 的类型注解是运行时不会检查的--它只在静态分析(MyPy/Pyright)阶段生效。但 FastAPI 巧妙地"借用"了类型注解--在运行时读取类型信息用于参数验证、序列化和生成 OpenAPI 文档。这也是 FastAPI 为什么能"写注解自动生成文档"的原因。另外,Protocol(协议类)和 TypedDict 是泛型之外另外两个重要的类型工具--Protocol 定义接口约束(鸭子类型的形式化),TypedDict 定义字典结构。

10. async def 和普通 def 有什么区别?

async def 普通 def
调用返回值 返回 coroutine 对象,不立即执行 立即执行,返回结果
内部能否 await 可以 不可以
执行模型 可暂停/恢复(协作式调度) 一口气跑完
调用方式 必须 await 或在事件循环中 直接调用 
async def fetch():
    return "data"

coro = fetch()         # → <coroutine object> 还没执行!
result = await fetch() # → "data" 真正执行
result2 = fetch()      # ❌ 忘记 await,返回协程对象而不是数据

11. asyncio.create_task() 和直接 await 有什么区别?

直接 await(顺序执行):
  result1 = await fetch(url1)  # → 耗时 1s
  result2 = await fetch(url2)  # → 再耗时 1s
  总耗时: 2s  ← 串行!

create_task(并发执行):
  task1 = create_task(fetch(url1))  # → 立即调度,不阻塞
  task2 = create_task(fetch(url2))  # → 立即调度,不阻塞
  result1 = await task1             # → 等第一个完成
  result2 = await task2             # → 等第二个完成
  总耗时: 1s  ← 并行!

create_task 把协程包装成 Task 放进事件循环调度队列,多个 Task 并发跑。如果不用 create_task 直接 await,就变成串行执行了--这是异步编程最常见的性能陷阱。

12. 什么是 asyncio.run()?为什么不能嵌套调用?

asyncio.run()做三件事：创建事件循环→运行协程→关闭循环。一个线程只能有一个事件循环，内部不能再调asyncio.run()。

13. 如何在异步代码中调用同步阻塞函数?

错误做法(阻塞事件循环):
  async def main():
      time.sleep(5)       # ❌ 整个事件循环卡住 5 秒
      requests.get(url)   # ❌ 阻塞!

正确做法:
  async def main():
      await asyncio.sleep(5)  # ✅ 非阻塞等待
      async with aiohttp.ClientSession() as session:  # ✅ 异步 HTTP
          await session.get(url)

      # 必须调同步代码时 → 丢到线程池
      result = await asyncio.to_thread(requests.get, url)  # Python 3.9+
      # 或
      loop = asyncio.get_running_loop()
      result = await loop.run_in_executor(None, requests.get, url)

关键原则：异步代码里不能直接调阻塞函数，必须交给线程池(asyncio.to_thread()或run_in_executor())执行。

15. 解释 __await__ 和 __aenter__ / __aexit__

  • __await__:定义对象如何被 await,返回一个迭代器(至少 yield 一次)
  • __aenter__ / __aexit__:定义异步上下文管理器的进入和退出(async with)
  • __aiter__ / __anext__:定义异步迭代器(async for)
class AsyncDB:
    async def __aenter__(self):
        self.conn = await create_connection()
        return self.conn
    async def __aexit__(self, *args):
        await self.conn.close()

async with AsyncDB() as db:   # 自动管理连接生命周期
    data = await db.query("SELECT ...")

16. 异步编程常见陷阱和最佳实践

五大陷阱:

  1. 忘记 await:coro = fetch() 只是创建协程对象,没执行!必须 await fetch()
  2. 同步阻塞函数直接调用:time.sleep(5) 卡死整个事件循环,必须用 asyncio.sleep
  3. asyncio.run() 嵌套:事件循环已在运行时不能再创建
  4. 共享数据无保护:await 点之间协程可能交错,需用 asyncio.Lock() 保护
  5. Task 资源泄漏:创建的 Task 没被 await,可能被 GC 但代码还在跑

最佳实践清单:

  • 用 asyncio.run() 作为唯一入口
  • 用 create_task 实现并发,不要串行 await 多个独立操作
  • Python 3.11+ 用 TaskGroup 管理任务组(一个失败自动取消其他)
  • 阻塞调用放线程池:asyncio.to_thread() 或 run_in_executor()
  • 用 Semaphore 限制并发数,避免资源耗尽
  • 用 asyncio.wait_for() 或 asyncio.timeout() 设置超时
  • 正确处理 CancelledError,确保清理资源

17. Python 如何实现协程间的通信?

协程间通信用 asyncio.Queue——线程安全、支持异步 put/get。

import asyncio

async def producer(queue):
    for i in range(10):
        await queue.put(i)
        await asyncio.sleep(0.1)

async def consumer(queue):
    while True:
        item = await queue.get()
        print(f'处理: {item}')
        queue.task_done()

async def main():
    queue = asyncio.Queue(maxsize=5)  # 限制队列长度
    await asyncio.gather(
        producer(queue),
        consumer(queue)
    )

Queue 的 get() 在队列空时挂起协程,put() 在队列满时挂起。这与多线程 Queue 不同(后者是阻塞等待)。

扩展:生产者-消费者模式用 join() 等待所有任务完成;PriorityQueue 按优先级消费;LifoQueue 后进先出。

18. 如何诊断异步代码的性能瓶颈?

核心工具:asyncio 内置调试模式 + aiodebug 库。

import asyncio

# 开启调试模式
asyncio.run(main(), debug=True)

# 输出示例:
# Executing <Task finished name='Task-1' coro=<slow_func>> took 0.503 seconds

关键诊断点: - 慢回调警告:超过 100ms 的同步操作会告警(可调 loop.slow_callback_duration) - 阻塞事件循环:用 asyncio.to_thread() 包装同步函数 - 协程泄漏:asyncio.all_tasks() 查看活跃任务数 - 任务堆积:Queue.qsize() 监控队列积压

扩展:生产环境可用 opentelemetry 追踪异步调用链;aiomonitor 提供 REPL 实时调试;uvloop 性能比原生 asyncio 快 2-4 倍。

19. Python 项目如何排查内存泄漏？

Python 内存泄漏的三大来源：

1. 循环引用 → gc.collect() 解决
2. C 扩展泄漏 → 第三方库持有 Python 对象
3. 全局集合持续膨胀 → dict/set/list 无限增长

排查步骤：

# Step1: tracemalloc 定位大内存分配
import tracemalloc
tracemalloc.start()

# 业务代码
import your_module

snapshot = tracemalloc.take_snapshot()
top = snapshot.statistics('lineno')
for stat in top[:10]:
    print(stat)

# Step2: objgraph 可视化引用链
import objgraph
objgraph.show_most_common_types(limit=10)  # 什么对象最多
objgraph.show_backrefs(objgraph.by_type('YourClass')[0], maxdepth=5)

最常见泄漏：全局 dict 缓存无上限增长、logging.Handler 未释放、观察者模式未注销回调。

扩展：tracemalloc 是 Python 3.4 内置；生产环境可用 objgraph 定期打快照对比；内存泄漏修复后用 weakref（弱引用）从源头防止持有。
