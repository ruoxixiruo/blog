FastAPI

1. FastAPI 和 Flask / Django 的区别?

特性 FastAPI Flask Django
异步支持 原生 async/await 需扩展(Quart)或线程池 3.1+ 部分支持
性能 极高(Starlette + uvloop) 一般 一般
数据校验 Pydantic 自动校验 需手动或插件 DRF Serializer
API 文档 自动生成 Swagger/ReDoc 需插件 DRF 自带
类型提示 一等公民 可选 可选
适用场景 API 服务、微服务、AI 服务 小型应用、原型 全栈大型应用

一句话总结:Django 像精装修大 house,Flask 像毛坯房自己装,FastAPI 像现代公寓--省心、快速、类型安全。

扩展:FastAPI 基于 Starlette(ASGI 框架)和 Pydantic(数据校验),这两者分别提供高性能 HTTP 处理和类型安全。2025 年 FastAPI 已成为 Python 新项目的 API 开发首选,GitHub Star 增长最快。

2. FastAPI 为什么这么快?

请求 → ASGI Server (Uvicorn + uvloop)
     → Starlette (高性能 HTTP 处理)
     → Pydantic (Rust 核心编译型校验)
     → 业务逻辑 (async/await 协程)
  • Starlette:高性能 ASGI 框架做底层,异步非阻塞
  • uvloop:替代 asyncio 默认事件循环(基于 libuv,接近 Node.js 性能)
  • Pydantic v2:编译型校验(Rust 核心),比纯 Python 快 5-50 倍
  • 并发模型:async/await 协程,单线程处理成千上万连接

实际压测中,FastAPI 的性能可以和 Node.js、Go 的 Web 框架掰手腕。

扩展:uvloop 只能在 Linux/macOS 上用(基于 libuv),Windows 上自动退化为 asyncio 原生事件循环。Pydantic v2 用 Rust 重写了核心校验逻辑,是 v1 性能飞跃的关键。

3. 路径参数和查询参数有什么区别?

@app.get("/users/{user_id}")          # 路径参数:RESTful,必传
async def get_user(user_id: int):     # 自动校验类型
    ...

@app.get("/users")                     # 查询参数:可选,有默认值
async def list_users(page: int = 1, size: int = 10):
    ...

路径参数是 URL 的一部分(/users/42),用于标识资源。查询参数在 ? 后面(/users?page=1&size=10),用于过滤、排序、分页--同一个资源的不同"视图"。

扩展:FastAPI 支持路径参数枚举:@app.get("/items/{category}") 中 category: ItemCategory(枚举类型)会自动生成下拉选择的 Swagger 文档。查询参数还可以用 Query() 添加校验(min_length、regex 等)。

4. Pydantic 在 FastAPI 中的作用?

Pydantic 是 FastAPI 的「安检员」和「翻译官」:

请求 JSON → Pydantic 反序列化 + 校验(不通过返回 422)
          → 业务逻辑处理
          → Pydantic 序列化 → JSON 响应

from pydantic import BaseModel, Field

class UserCreate(BaseModel):
    name: str = Field(..., min_length=2, max_length=50)   # 自动校验长度
    age: int = Field(..., ge=0, le=150)                    # 自动校验范围
    email: str                                             # 自动校验格式

@app.post("/users")
async def create_user(user: UserCreate):   # 入参自动校验 + 转换
    return user.model_dump()               # 出参自动序列化

请求体自动校验,不符合规则直接返回 422 错误给客户端。自动生成 JSON Schema,Swagger 文档同步更新。告别手写 if not isinstance(age, int) 的苦日子。

扩展:Pydantic v2 新增 model_validate() 和 model_dump() 替代 v1 的 parse_obj() 和 dict()。BaseModel 支持嵌套模型、可选字段(Optional[str] = None)、联合类型(str | int)。computed_field 可以定义计算属性(不来自输入,但出现在输出中)。

5. 依赖注入(Depends)是什么?怎么用?

FastAPI 的招牌功能--通过 Depends() 把公共逻辑抽成「依赖函数」,需要的地方注入即可:

请求进入 → FastAPI 解析依赖树
         → get_db() 提供数据库连接
         → get_current_user(get_db) 验证身份
         → 视图函数(user, db)
         → 依赖清理(yield 后的 finally 部分)

async def get_db():
    db = SessionLocal()
    try:
        yield db          # yield 前的在请求前执行
    finally:
        db.close()        # yield 后的在请求结束后执行

@app.get("/users/me")
async def read_me(
    db = Depends(get_db),               # 注入数据库连接
    user = Depends(get_current_user)    # 注入当前用户
):
    return user

依赖可以嵌套--get_current_user 依赖 token,read_me 依赖 get_current_user 和 get_db。FastAPI 自动解析依赖树,按顺序执行。

扩展:依赖可以带参数(Depends(partial_func)),可以声明为类(class CommonQueryParams)。Security() 是加强版 Depends(),专门用于认证场景,支持 OAuth2 作用域。依赖结果可以被缓存--同一次请求中多次请求同一个依赖不会重复执行。

6. 中间件(Middleware)和依赖(Depends)的区别?

中间件 依赖
作用范围 全局,每个请求都经过 按路由/路由组注入
执行时机 请求处理前/后,包裹整个应用 在执行视图函数前
典型用途 CORS、日志、请求计时、异常捕获 鉴权、DB 连接、权限校验
实现 @app.middleware("http") Depends() 
请求 → 中间件 → 路由匹配 → 依赖 → 视图函数 → 依赖清理 → 中间件返回

中间件是「门卫」--所有请求进来都要过。依赖是「前台」--按需分配给特定接口。

扩展:中间件中可以修改请求和响应,但要注意性能--每个请求都多一层。依赖通过 yield 实现类似中间件的请求/响应包装,但仅在指定路由生效。异常处理:依赖中的异常会传播到视图,中间件可以全局捕获。

7. FastAPI 的事件生命周期?

# FastAPI 官方推荐(0.93+)
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    # startup: 初始化 DB 连接池、加载 ML 模型
    await init_db()
    yield
    # shutdown: 关闭连接、释放资源
    await close_db()

app = FastAPI(lifespan=lifespan)

FastAPI 没有 Flask 的 before_request / after_request 钩子。替代方案是用依赖的 yield 模式(类似 try-finally)实现请求级别的设置和清理。

扩展:FastAPI 0.93+ 用 lifespan 替代废弃的 @app.on_event("startup"),可显式控制事件顺序。

8. 怎么处理 CORS?

from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://example.com"],  # 指定域名,生产环境不要用 ["*"]
    allow_methods=["GET", "POST"],
    allow_headers=["*"],
    allow_credentials=True,
)

扩展:allow_origins=["*"] 与 allow_credentials=True 不能同时使用,需凭证时必须指定域名。

10. FastAPI 怎么做后台任务?

from fastapi import BackgroundTasks

@app.post("/register")
async def register(email: str, background_tasks: BackgroundTasks):
    background_tasks.add_task(send_email, email, "欢迎注册")
    return {"msg": "注册成功"}  # 立即返回,发邮件在后台执行

后台任务在响应返回之后执行。适合发邮件、写日志等不阻塞用户的操作。

扩展:BackgroundTasks 任务在进程内,进程崩溃则丢失;持久化/重试/定时需用 Celery 或 ARQ。

11. WebSocket 怎么支持?

from fastapi import WebSocket

@app.websocket("/ws")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()         # 接受连接
    while True:
        data = await websocket.receive_text()
        await websocket.send_text(f"你说了: {data}")

FastAPI 原生支持 WebSocket,不需要额外插件。适合聊天、实时推送、协作编辑等场景。

扩展:长连接需管理连接数和心跳;Nginx 需配置 Upgrade 头支持;多实例广播用 Redis Pub/Sub。

12. FastAPI 怎么做请求限流?

FastAPI 没有内置限流,常用方案:

  • slowapi:基于 limits 库,用法类似 flask-limiter,依赖注入使用
  • Redis + 滑动窗口:自己实现或使用 fastapi-limiter,分布式限流更准确
  • 依赖注入方式:写一个 rate_limit 依赖,在需要的路由注入
from slowapi import Limiter
limiter = Limiter(key_func=get_remote_address)

@app.get("/api/limited")
@limiter.limit("5/minute")    # 每分钟 5 次
async def limited_endpoint(request: Request):
    ...

扩展:网关层限流(Nginx/Kong/APISIX)比应用层高效,两者配合使用是最佳实践。

13. 怎么上传文件?

from fastapi import UploadFile, File

@app.post("/upload")
async def upload(file: UploadFile = File(...)):
    contents = await file.read()                      # 读到内存(小文件)
    # 或流式写磁盘(大文件)
    with open(f"uploads/{file.filename}", "wb") as f:
        while chunk := await file.read(1024 * 1024):   # 每次读 1MB
            f.write(chunk)
    return {"filename": file.filename, "size": file.size}

UploadFile 是异步文件接口,支持流式读取,不会一次加载全部内容到内存。

扩展:小文件在内存,大文件溢写到磁盘;多文件用 List[UploadFile];需校验大小和类型。

14. FastAPI 怎么部署?

Nginx(反向代理 + 静态文件 + SSL 终结)
   ↓
Gunicorn(进程管理,多 worker)
   ↓ UvicornWorker(ASGI worker)
FastAPI 应用

# 单进程开发:uvicorn main:app --reload
# 多进程生产:gunicorn -k uvicorn.workers.UvicornWorker -w 4 main:app

推荐用 Gunicorn + UvicornWorker 管理多进程,Nginx 在前做反代。Docker 部署时别忘了 --host 0.0.0.0。

扩展:worker数 = (2 * CPU核数) + 1;静态文件交Nginx/CDN;HTTPS证书在Nginx/Ingress处理。

15. FastAPI 怎么组织大型项目?

app/
├── main.py              # 入口:创建 app、注册路由、挂载中间件
├── api/v1/              # 路由层(薄层,只做路由分发和参数解析)
│   ├── users.py
│   └── items.py
├── models/              # SQLAlchemy / SQLModel 数据库模型
├── schemas/             # Pydantic 请求/响应模型
├── services/            # 业务逻辑层(核心逻辑在这里)
├── dependencies/        # 可复用的 Depends 依赖
└── core/
    ├── config.py        # 配置管理(pydantic-settings)
    └── database.py      # 数据库引擎和连接

路由用 APIRouter 分模块,然后在 main.py 中 app.include_router(users.router)。核心原则:路由薄薄一层,逻辑下沉到 service 层。

扩展:APIRouter 支持 prefix 和 tags 自动分组到 Swagger;多版本API用不同前缀共存。

16. FastAPI 中如何做接口版本管理?

FastAPI 支持 URL 路径前缀(APIRouter(prefix='/api/v1'))、请求头版本、查询参数。 常用路径前缀:最直观、路由清晰、可同时运行多版本。

17. FastAPI 如何处理大量并发请求?

核心:异步架构 + 连接池 + 限流 + 水平扩展。

# 1. 数据库连接池
from sqlalchemy.ext.asyncio import create_async_engine

engine = create_async_engine(
    "postgresql+asyncpg://...",
    pool_size=20,        # 常驻连接
    max_overflow=10,     # 峰值额外连接
    pool_pre_ping=True   # 连接健康检查
)

# 2. Redis 连接池
from redis.asyncio import Redis
redis = Redis(connection_pool=ConnectionPool(max_connections=100))

# 3. 并发限制
from asyncio import Semaphore
semaphore = Semaphore(100)  # 最多 100 并发

@app.get("/api/data")
async def get_data():
    async with semaphore:
        return await fetch_from_db()

其他优化:uvicorn worker数=(2*CPU核数+1)、用 uvloop 替代 asyncio、静态资源走 CDN、慢操作丢给 Celery。

扩展:压测工具用 locust 或 wrk;监控用 Prometheus + Grafana;瓶颈通常是数据库而非 FastAPI 本身。

18. FastAPI 如何做请求追踪?

请求追踪通过 request_id 贯穿全链路。用中间件生成 ID 并注入日志。

import uuid
from fastapi import Request
import structlog

@app.middleware("http")
async def add_request_id(request: Request, call_next):
    request_id = request.headers.get("X-Request-ID") or str(uuid.uuid4())
    request.state.request_id = request_id

    # 绑定到 structlog 上下文
    structlog.contextvars.bind_contextvars(request_id=request_id)

    response = await call_next(request)
    response.headers["X-Request-ID"] = request_id
    return response

# 日志自动带 request_id
logger = structlog.get_logger()
logger.info("处理请求", path=request.url.path)  # 自动带 request_id 字段

日志格式推荐 JSON(结构化),对接 ELK 或 Datadog。跨服务传递时把 X-Request-ID 放到 HTTP 头或 gRPC metadata。

扩展:分布式追踪用 OpenTelemetry+Jaeger;structlog 比标准库 logging 更适合结构化日志;生产环境必须做请求追踪。

19. FastAPI 如何做接口版本管理？

FastAPI 不强制版本策略，常用三种方式：

# 方式1: 路径版本（最直观）
@app.get("/v1/items")
def list_items_v1(): ...

@app.get("/v2/items")
def list_items_v2(): ...

# 方式2: Header 版本（RESTful 风格）
from fastapi import Header
@app.get("/items", headers={"API-Version": "2024-01"})
def list_items(v: str = Header(..., alias="API-Version")):
    if v == "2024-01":
        return v1_impl()
    return v2_impl()

推荐：路径版本更清晰，Nginx 路由也好配置。版本迭代时旧版本用 Deprecated=True 标记：

from fastapi import Deprecations
app = FastAPI(deprecated=True)  # 全局标记，或在路由层

扩展：FastAPI 基于 OpenAPI，Swagger UI 自动显示版本差异；Netflix/Zalando 等公司用路径版本；Google/AWS 用 Header 版本。
