MyBatis

1. MyBatis 的执行流程?

MyBatis 查询全流程:

SqlSessionFactory
  └─ openSession() → SqlSession(一次数据库会话)
       └─ getMapper() → 动态代理的 Mapper 接口
            └─ Executor(执行器,缓存/事务管理)
                 └─ StatementHandler(创建 JDBC Statement)
                      ├─ ParameterHandler → 把参数设到 SQL 的 ? 上
                      └─ JDBC 执行 SQL
                           └─ ResultSetHandler → 把 ResultSet 映射为 Java 对象

每个组件的职责: - SqlSession:和数据库的一次会话,用完要关。相当于 JDBC 的 Connection - Executor:执行器,管理缓存(一二级缓存)和事务 - StatementHandler:创建 PreparedStatement,调用 ParameterHandler 设参数 - ResultSetHandler:把 JDBC 的 ResultSet 转成 Java 对象(List/Map/单个对象)

扩展:MyBatis 用 JDK 动态代理实现"只写接口不写实现"。openSession(ExecutorType.BATCH) 可开启批量模式。

2. #{} 和 ${} 的区别?

#{}:
  SELECT * FROM user WHERE id = #{id}
  → SELECT * FROM user WHERE id = ?   (占位符,预编译)
  → 传入 id=5 → 安全!
  攻击者传入 id="1 OR 1=1" → 数据库把"1 OR 1=1"当作一个值来比较 → 无效攻击

${}:
  SELECT * FROM user WHERE id = ${id}
  → SELECT * FROM user WHERE id = 1 OR 1=1   (直接拼进去!)
  → SQL 注入成功!全表数据暴露
对比 #{} ${}
处理方式 预编译,? 占位符 直接字符串替换
SQL 注入 安全 危险
使用场景 绝大多数情况 动态表名/字段名/ORDER BY
特性 防注入 危险--直接拼

为什么 ${} 还存在:因为 #{} 会把参数当作"值",表名和列名不能用 ? 占位符。ORDER BY #{column} 变成 ORDER BY 'name'(加了引号!),排序失效。这种场景只能 ${},但必须白名单校验。

扩展:动态 SQL 必须用 ${} 时要加白名单过滤(如 ORDER BY 只允许特定字段名)。

3. 一级缓存和二级缓存?

一级缓存(SqlSession 级别,默认开启):
  SqlSession A: SELECT * FROM user WHERE id=1 → 查数据库
  同一会话中: SELECT * FROM user WHERE id=1 → 直接返回缓存(不查数据库)
  commit/close/update → 清空缓存

二级缓存(Mapper 级别,需手动开启):
  SqlSession A: SELECT * FROM user WHERE id=1 → 查数据库 → 缓存到 Mapper
  SqlSession B: SELECT * FROM user WHERE id=1 → 直接返回二级缓存(不查数据库)
  A 提交了 update → 清空这个 Mapper 的二级缓存
对比 一级缓存 二级缓存
作用域 SqlSession Mapper/namespace
默认 开启 关闭
适用 同一会话内去重 跨会话共享

为什么生产少用二级缓存: - 多个 Mapper 之间的交叉更新它不知道(A 表更新了,B 表的缓存不会失效) - Redis 更灵活(跨服务共享、精确过期控制、独立管理) - 分布式环境下一致性难以保证

扩展:MyBatis + Spring 整合后每次查询都是新的 SqlSession,一级缓存几乎无实际作用。Redis 是更优的跨进程缓存方案。

4. MyBatis 的分页实现?

逻辑分页(RowBounds)--不推荐:
  SELECT * FROM user  → 查出 100 万条数据
  → Java 内存里截取第 10-20 条
  → 100 万条传输到应用服务器 → 内存爆炸!

物理分页(PageHelper)--生产用:
  SELECT * FROM user LIMIT 10, 20  → 只查 10 条
  → PageHelper 拦截原始 SQL → 自动拼 LIMIT → 只查需要的数据

PageHelper 原理:MyBatis 插件机制--拦截 Executor 的 query 方法,在 SQL 执行前判断是否有分页参数,有则自动拼接数据库方言的 LIMIT(MySQL: LIMIT offset, size,Oracle: ROWNUM)。

扩展:PageHelper 查询后紧跟 SELECT COUNT(*)。大数据量关联查询时 COUNT(*) 可能很慢,可考虑 ES 分页。

5. resultType 和 resultMap 的区别?

对比 resultType resultMap
适用 列名 = 属性名(或驼峰转换后一致) 列名 ≠ 属性名、嵌套对象
简便性 简单 复杂但强大
关联映射 不支持 association(一对一)、collection(一对多)
继承 不支持 支持 extends 复用 
<!-- 简单场景用 resultType -->
<select id="findById" resultType="User">
    SELECT id, user_name AS userName FROM user WHERE id = #{id}
</select>

<!-- 复杂场景用 resultMap -->
<resultMap id="orderMap" type="Order">
    <id property="id" column="id"/>
    <association property="user" javaType="User">  <!-- 一对一 -->
        <id property="id" column="user_id"/>
    </association>
    <collection property="items" ofType="OrderItem"> <!-- 一对多 -->
        <id property="id" column="item_id"/>
    </collection>
</resultMap>

扩展:MyBatis 3.5+ 支持 @One/@Many 注解做关联映射。N+1 查询可用 fetchType 延迟加载优化。

6. MyBatis-Plus 的核心功能?

MyBatis-Plus 核心能力:

1 自动 CRUD
   继承 BaseMapper<User> → 自带 insert/update/deleteById/selectList
   常用单表操作零 SQL!

2 条件构造器(QueryWrapper)
   new QueryWrapper<User>().eq("status", 1).like("name", "张").orderByDesc("age")
   → 链式拼条件,不用在 XML 里写 if 判断

3 分页插件
   Page<User> page = new Page<>(1, 10);
   userMapper.selectPage(page, null);
   → 物理分页 + 自动 COUNT

4 乐观锁
   @Version 注解修饰字段 → update 时自动拼 version = version+1

5 逻辑删除
   @TableLogic → delete 变成 update deleted=1,查询自动加 deleted=0

6 代码生成器
   根据数据库表反向生成 Entity/Mapper/Service/Controller

扩展:LambdaQueryWrapper 用 Lambda 写条件避免字符串写错。复杂 join/子查询仍需 XML。

7. Mapper 接口的工作原理?为什么接口方法不能重载?

MyBatis 在启动时通过 JDK 动态代理为每个 Mapper 接口生成代理对象。调用接口方法时:

  1. 代理对象拦截方法调用
  2. 通过 namespace = 接口全类名 + id = 方法名 找到对应的 XML 中 SQL
  3. 执行 SQL 并返回结果
UserMapper 接口(没有实现类)
      │
      ▼ JDK 动态代理
MapperProxy 拦截所有方法调用
      │
      ▼ 方法名 = findById
查找 namespace="com.xxx.UserMapper" + id="findById"
      │
      ▼
执行 SQL → 映射结果 → 返回

为什么不能重载? MyBatis 通过 namespace + id(即全类名 + 方法名)唯一确定一条 SQL,没有参数类型信息。如果两个方法同名(重载),MyBatis 不知道该执行哪个 SQL。

扩展:注解和 XML 方式可混合使用,但建议统一用一种。

8. MyBatis 动态 SQL 有哪些标签?各自作用?

标签 作用 示例场景
<if> 条件判断 可选查询条件
<where> 自动去掉第一个 AND/OR,无子元素时不生成 WHERE 包裹所有条件
<set> 自动去掉末尾逗号 动态更新
<foreach> 遍历集合 IN 查询、批量插入
<choose>/<when>/<otherwise> 多选一(类似 switch) 优先级条件
<trim> 前缀/后缀处理(最通用) 自定义替换逻辑
<bind> 创建变量(OGNL 表达式) 模糊查询自动加 % 
<select id="findUsers" resultType="User">
    SELECT * FROM user
    <where>
        <if test="name != null">AND name LIKE #{name}</if>
        <if test="age != null">AND age = #{age}</if>
        <foreach collection="ids" item="id" open="AND id IN (" close=")" separator=",">
            #{id}
        </foreach>
    </where>
</select>

扩展:<where> 和 <set> 底层都是 <trim> 实现。<bind> 可统一不同数据库的语法差异。

9. MyBatis 插件(拦截器)机制?可以拦截哪些对象?

MyBatis 插件基于责任链模式 + JDK 动态代理,可以拦截 4 个核心对象:

拦截对象 可拦截的方法 典型应用
Executor update/query/commit/rollback 分页插件(PageHelper)、读写分离
StatementHandler prepare/parameterize/batch SQL 改写、加 limit
ParameterHandler setParameters 参数加密/脱敏
ResultSetHandler handleResultSets 结果加密/解密、字段脱敏 
@Intercepts({
    @Signature(type = Executor.class, method = "query", args = {MappedStatement.class, Object.class, RowBounds.class, ResultHandler.class})
})
public class MyPlugin implements Interceptor {
    public Object intercept(Invocation invocation) throws Throwable {
        System.out.println("SQL 执行前");
        Object result = invocation.proceed();  // 放行
        System.out.println("SQL 执行后");
        return result;
    }
}

扩展:多个插件的执行顺序由配置顺序决定(第一个包装最外层)。插件链不要太长,每个查询都过一遍有性能开销。

10. 实体类属性名和表字段名不一致怎么办?

方案 做法 优点 缺点
SQL 别名 SELECT user_name AS userName 简单直接 每个 SQL 都要写,繁琐
ResultMap <result column="user_name" property="userName"/> 精确控制,一次定义 每个字段都要映射
驼峰自动转换 mapUnderscoreToCamelCase=true 一口配置,全项目生效 只处理 user_name → userName 这种映射 
<!-- 最推荐:配置文件开启驼峰转换 -->
<setting name="mapUnderscoreToCamelCase" value="true"/>
<!-- user_name 自动映射到 userName,搞定 90% 的场景 -->

扩展:Spring Boot:mybatis.configuration.map-underscore-to-camel-case=true 一行配置搞定驼峰映射。

11. MyBatis 的懒加载怎么实现?

MyBatis 懒加载 = 代理对象 + 延迟触发。关联查询不会立刻执行,而是返回一个 CGLIB/Javassist 代理对象,只有当你真正调用这个对象的 getter 方法时,才去数据库查。

lazyLoadingEnabled=true 启用,MyBatis 为关联对象生成代理对象,首次 getter 触发 SQL。适合不确定是否需要关联数据的场景,避免不必要 JOIN。注意循环触发懒加载退化为 N+1。

12. MyBatis 插件机制与原理？

MyBatis 通过 拦截器链 实现插件扩展，四大对象可被拦截：

Executor (CRUD)
  ↓
StatementHandler (SQL预编译+参数设置)
  ↓
ParameterHandler (参数填充)
  ↓
ResultSetHandler (结果集映射)

插件编写（以分页插件为例）：

@Intercepts({
    @Signature(type = StatementHandler.class,
               method = "prepare",
               args = {Connection.class}),
    @Signature(type = ResultSetHandler.class,
               method = "handleResultSets",
               args = {Statement.class})
})
public class PageInterceptor implements Interceptor {
    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        // 拦截 SQL，改写为带 LIMIT
        Object target = invocation.getTarget();
        if (target instanceof StatementHandler rs) {
            String sql = rs.getBoundSql().getSql();
            sql = sql + " LIMIT " + page.getOffset() + "," + page.getLimit();
            Field sqlField = BoundSql.class.getDeclaredField("sql");
            sqlField.setAccessible(true);
            sqlField.set(rs.getBoundSql(), sql);
        }
        return invocation.proceed();  // 继续执行
    }
}

扩展：@Intercepts 注解注册到 Spring 容器后自动生效；多插件时按 order 顺序执行；插件不要拦截太多方法（性能损耗）；PageHelper 是最常用的第三方分页插件。
