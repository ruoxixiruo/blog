Claude Code 面试学习文档

AI 编程助手该当"副驾驶"还是"专职司机"？从零搞懂 Claude Code 的定位、架构与实战。

1. Claude Code 是什么？

1.1 一句话定位

Claude Code 是 Anthropic 官方推出的 AI 编程 Agent CLI 工具，将 Claude 模型能力直接嵌入终端。它能读文件、改文件、跑命令、提交 git、搜索网页——是一个真正能执行任务的 Agent，而非代码补全插件。

类比：Copilot 是旁边提醒"这块木板裁短一点"的师傅；Claude Code 是你吼一句"帮我把客厅装好"，他搬材料、做木工、刷墙的全包工头。Copilot 帮你写一行，Claude Code 帮你干完整个活儿。

  • 官网：https://docs.anthropic.com/claude-code
  • 定位：专业级 AI 编程 Agent
  • 核心标签：真正的 Agent、能执行任务、持久上下文、安全可控

1.2 AI 编程工具分层

┌────────────────────────────────────────────────────────────┐

│  Level 1：代码补全（GitHub Copilot）                         │

│    → 本质：能独立干活的初级工程师                            │
│                                                            │
│  Claude Code 位于 Level 3，当前最强专业级 AI 编程工具        │
└────────────────────────────────────────────────────────────┘

1.3 Claude Code 与 Vibe Coding

Vibe Coding：你只管描述想要的"感觉"，AI 负责写代码。你更像产品经理而非程序员。

Claude Code 四大核心优势：

1. Agent 能力 — 交代任务全程搞定，可创建文件/运行命令/安装依赖/提交 git
2. 持久上下文 — 理解项目全貌（文件结构、代码关系），记住之前决策
3. 安全可控 — /allow 权限体系 + ask 模式，危险操作需人工批准
4. 工具集成 — 深度集成文件系统、Shell、Git，支持 TS/Python/Go/Rust

3. 安装与配置

3.1 安装

# macOS / Linux
npm install -g @anthropic-ai/claude-code

# 或通过 npx（无需安装）
npx @anthropic-ai/claude-code

# 验证安装
claude --version

3.2 环境变量配置

# 必须配置：Anthropic API Key
export ANTHROPIC_API_KEY=sk-ant-api03-xxxxx

# 可选：模型选择
export CLAUDE_MODEL=claude-sonnet-4-20250514
# 可选值：claude-opus-4-20250514 / claude-sonnet-4-20250514

# 可选：工作目录（默认当前目录）
export CLAUDE_WORKING_DIR=/path/to/project

# 可选：日志级别
export CLAUDE_LOG_LEVEL=info  # debug / info / warn

3.3 claude_desktop_config.json（配置模板）

面试话术：配置文件的精髓在于分层权限设计和模型路由——日常开发用 Sonnet（快且便宜），复杂任务自动切 Opus（强但贵）。

{
  "permissions": {
    "allow": [
      "Bash(lint)",
      "Bash(eslint)",
      "Bash(npm run test)",
      "Bash(npm run build)",
      "Read(project)",
      "Edit(project)"
    ],
    "deny": [
      "Bash(rm -rf /)",
      "Bash(rm -rf node_modules)",
      "Edit(system)"
    ]
  },
  "features": {
    "autoRunTests": true,
    "confirmGitCommit": true,
    "autoGitCommit": false
  },
  "model": {
    "default": "claude-sonnet-4",
    "override": {
      "complex-task": "claude-opus-4"
    }
  }
}

4. 核心命令与交互模式

4.1 启动方式

# 在项目目录中启动（自动读取项目上下文）
claude

# 指定工作目录
claude --dir /path/to/project

# 指定任务（one-shot 模式）
claude "帮我创建一个 React 登录页面"

# 从会话恢复
claude --resume session-abc123

# 使用特定模型
claude --model opus

4.2 核心命令速查

Claude Code 内置命令：

/clear          → 清除当前会话上下文
/exit           → 退出 Claude Code
/compact        → 压缩上下文（减少 token 消耗）
/allowed        → 查看当前权限列表
/approve [code]  → 批准 ask 模式的操作
/deny [code]    → 拒绝 ask 模式的操作
/help           → 显示帮助信息
/version        → 显示版本信息
/config         → 配置 Claude Code

# 项目内命令
/read <file>    → 读取文件
/edit <file>    → 编辑文件
/commit         → 提交 git 变更
/branch <name>  → 创建分支
/diff           → 查看变更
/status         → git 状态

5. Tool Use 工具集

5.1 文件操作

# 读取文件（支持大文件分片读取）
read(path="src/App.tsx")
read(path="src/main.ts", offset=1, limit=100)  # 分片读取

# 写入文件（覆盖）
write(path="src/newfile.ts", content="...")

# 编辑文件（精确替换）
edit(path="src/App.tsx",
     oldText="const name = 'old';",
     newText="const name = 'new';")

# 删除文件 → 危险操作，需要 ask 模式批准

# 创建目录
mkdir(path="src/components", recursive=true)

5.2 Shell 执行

exec(command="npm install", timeoutMs=60000)
exec(command="npm run build", workdir="/path/to/project")
exec(command="npm run test -- --coverage", timeoutMs=120000)

# 交互式命令（需要 PTY）
exec(command="python manage.py shell", pty=true)

# 后台执行
exec(command="python server.py", background=true, yieldMs=5000)

5.3 Git 操作

# 查看状态
exec(command="git status")

# 查看变更
exec(command="git diff")

# 提交变更
exec(command="git add . && git commit -m 'feat: add login page'")

# 创建分支
exec(command="git checkout -b feature/login-page")

# 查看日志
exec(command="git log --oneline -10")

5.4 Web 工具

# 搜索网页
web_search(keyword="React 19 new features", freshness="month")

# 获取网页内容
web_fetch(url="https://react.dev/blog", maxChars=10000)

# 使用浏览器（复杂交互页面）
browser(action="open", url="https://github.com")

browser(action="screenshot") # 截图

5.5 Tool Use 协议：大脑-身体分离

Claude 模型本身不能直接操作文件或执行命令——它只有"思考"能力。所有操作都通过 Tool Use 协议，由 CLI 层代为执行。这是理解 Claude Code 架构的关键。


┌─────────────────────────────────────────────────────────────────┐
│              Tool Use 协议：Brain-Body 分离架构                    │
│                                                                 │
│                        ┌──────────────┐                         │
│                        │  用户输入     │                         │
│                        │ (自然语言)    │                         │
│                        └──────┬───────┘                         │
│                               │                                 │
│                               ▼                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │               BRAIN（大脑）— Anthropic API                │   │
│  │                                                         │   │
│  │  Claude 模型 分析意图 → 决定调用哪些工具 → 生成 Tool Call │   │
│  │                                                         │   │
│  │  可用工具定义（Tool Schema）：                            │   │
│  │    read(path, offset?, limit?)                          │   │
│  │    write(path, content)                                 │   │
│  │    edit(path, oldText, newText)                         │   │
│  │    exec(command, timeoutMs?, workdir?)                  │   │
│  │    web_fetch(url, maxChars?)                            │   │
│  │    web_search(keyword, freshness?)                      │   │
│  │    glob(pattern)     grep(pattern, path?)               │   │
│  └───────────────────────┬─────────────────────────────────┘   │
│                          │ Tool Use 协议 (JSON-RPC)             │
│                          ▼                                      │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │               BODY（身体）— Claude Code CLI               │   │
│  │                                                         │   │
│  │  执行具体操作：                                           │   │
│  │    ├── 文件系统：实际读写文件、精确字符串替换              │   │
│  │    ├── Shell：生成子进程执行命令、捕获 stdout/stderr       │   │
│  │    ├── Web：发起 HTTPS 请求、解析 HTML                    │   │
│  │    └── Git：执行 git 命令、管理分支和提交                 │   │
│  │                                                         │   │
│  │  安全层：权限检查（ask/allow/deny）在工作目录边界内执行     │   │
│  └───────────────────────┬─────────────────────────────────┘   │
│                          │                                      │
│                          ▼                                      │
│                  ┌──────────────┐                              │
│                  │  执行结果返回 │                               │
│                  │ (stdout/text) │                               │
│                  └──────┬───────┘                              │
│                         │                                       │
│                         ▼                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Claude 模型 收到结果 → 判断下一步 → 继续或返回最终答案    │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  关键设计原则：                                                  │
│  - 模型只做推理和决策，永远不直接触碰文件系统                      │
│  - CLI 层只做执行，不做"理解"，所有语义理解回传模型               │
│  - 权限检查在 CLI 层完成，模型无法绕过                            │
└─────────────────────────────────────────────────────────────────┘

面试要点：这个"大脑-身体"分离设计是 Claude Code 安全模型的基础。模型无法绕过 CLI 层直接访问系统，所有操作都必须经过权限检查。

6. 安全机制与权限管理

6.1 权限体系

Claude Code 权限层级（从松到严）：

┌────────────────────────────────────────────────────────────┐
│                   权限层级                                  │
│                                                            │
│  /allow all          → 允许所有操作（信任模式）            │
│                      ⚠️ 仅完全信任环境适用                 │
│                                                            │
│  ask 模式（默认）     → 每次操作前询问用户                  │
│                      ✅ 推荐日常使用                       │
│                                                            │
│  /allow [pattern]    → 允许匹配 pattern 的操作            │
│                      → 例：/allow Bash(npm install)       │
│                      → 例：/allow Edit(project)           │
│                                                            │
│  /deny [pattern]     → 拒绝匹配 pattern 的操作            │
│                      → 例：/deny Bash(rm -rf)             │
│                                                            │
│  /deny all           → 拒绝所有操作                        │
└────────────────────────────────────────────────────────────┘

6.2 ask 模式详解

ask 模式工作流程：

Claude 需要执行操作 → 发送 ask 请求 → 等待用户批准

ask 请求示例：
  [ask] 操作：Bash(npm install)
  [ask] 目标：安装项目依赖
  [ask] 代码：A1B2C3
  请输入 /approve A1B2C3 或 /deny A1B2C3

用户批准：
  /approve A1B2C3
  → Claude 执行操作

用户拒绝：
  /deny A1B2C3
  → Claude 停止操作，解释原因

批量批准（approve all）：
  /approve
  → 批准所有待处理的 ask 请求

6.3 权限 Pattern 语法

# 文件操作权限
/allow Read(all)            # 允许读取所有文件
/allow Edit(project)        # 允许编辑项目文件
/allow Write(safe)          # 允许写入安全路径（不含危险目录）
/allow Write(project)       # 允许在项目目录写入

# Shell 命令权限
/allow Bash(npm *)          # 允许所有 npm 命令
/allow Bash(npm install)    # 仅允许 npm install
/allow Bash(npm run test)   # 仅允许测试
/deny  Bash(rm *)           # 禁止所有 rm 命令

# 组合权限
/allow Read(project), Edit(project)
/deny  Write(system), Bash(rm -rf *)

# 查看当前权限
/allowed

6.4 安全最佳实践

面试必背：安全机制核心——"默认最小权限，逐级放开"。

生产环境安全建议：

1. 初始配置使用 ask 模式 — 不要一上来就 /allow all

2. 分层权限配置
   /allow Bash(npm *)        # 允许 npm 操作
   /allow Read(all)          # 允许读取
   /allow Edit(project)      # 允许编辑项目文件
   /deny  Bash(rm -rf *)     # 禁止 rm -rf
   /deny  Bash(curl *)       # 禁止网络请求（防止数据外泄）

3. 敏感操作必须人工确认
   → 删除文件
   → 提交代码到 main/master
   → 执行数据库操作
   → 访问外部网络

4. 定期检查权限配置
   → /allowed 查看当前权限
   → 移除不再需要的权限

11. 高频面试题

Q1：Claude Code 的定位是什么？与 Copilot 有什么区别？

面试话术：

Claude Code 是专业级 AI 编程 Agent，GitHub Copilot 是代码补全工具。Copilot 像导航提醒"前方有测速"，Claude Code 像自动驾驶——能直接帮你开一段路，但每个路口会问你要不要拐弯（ask 模式）。

核心区别： - Copilot：IDE 中代码补全建议，输入时触发，无持久上下文 - Claude Code：自然语言对话执行任务，持久上下文，能执行 Shell/Git 等命令

三个关键词：Agent 定位、持久化上下文、安全权限体系。

Q2：Claude Code 的安全机制是如何设计的？

面试话术：

三层防御体系： 1. 工作目录边界隔离：CLI 默认只能操作当前项目目录，系统目录不可达 2. ask 模式 + Pattern 权限：ask（默认）每次操作需用户批准；/allow//deny 精确控制操作粒度 3. 透明审计：所有操作实时显示，危险操作二次确认，会话历史可导出

核心设计思想：Default Deny——默认最小权限，逐级显式授权。用户全程可见。

Q3：Claude Code 如何管理长会话的上下文？

面试话术：

四种机制配合： - 自动上下文压缩：token 超过 80% 阈值时自动触发，保留关键信息、移除冗余对话、生成摘要 - 手动压缩：/compact 按需触发 - 会话持久化：本地保存，--resume 恢复 - 文件上下文：已读取的关键文件内容保留在压缩后的上下文中

这个机制直接关系到对话质量和成本控制的平衡。

Q4：Claude Code 的工具调用原理是什么？

面试话术：

通过 Tool Use 协议实现"大脑-身体"分离架构，五步流程： 1. 用户自然语言指令 → Claude 模型分析意图 2. 判断需要调用哪些工具（read/write/exec/git 等），生成结构化 Tool Call 3. ask 模式下弹出请求等用户批准 4. 批准后 CLI 层执行工具调用，拿到结果 5. 结果返回模型，基于结果继续下一步或返回最终答案

核心理解：Claude 模型本身不能操作文件——它只负责推理和决策（大脑），CLI 层负责实际执行（身体），两者通过 JSON-RPC 协议通信。权限检查在 CLI 层完成，模型无法绕过。这类似于浏览器的进程隔离。

Q5：Claude Code 适合哪些场景？不适合哪些场景？

面试话术：

适合： - 🟢 功能开发（CRUD、API、组件） - 🟢 代码重构（拆分、合并、迁移） - 🟢 调试（分析错误日志、定位问题） - 🟢 技术调研（生成 POC、验证方案） - 🟢 测试编写（单元测试、集成测试）

不适合： - 🔴 安全敏感代码（密码、支付）——需要人工安全审查 - 🔴 复杂算法（需要数学证明的）——超出 LLM 能力边界 - 🔴 需要深度业务背景的任务——不了解公司内部逻辑 - 🔴 超长项目（上下文膨胀）——超过一定长度后质量下降

Q6：如何使用 Claude Code 进行代码审查？

面试话术：

三步走：

# 1. 精准提问（告诉它关注什么）
claude "审查 src/api/user.ts 这个文件，重点关注安全和性能"

# 2. Claude 输出审查报告
# - 安全问题（SQL注入、XSS、输入验证）
# - 性能问题（N+1查询、不必要的重计算）
# - 代码质量问题（命名、职责分离、异常处理）

# 3. 让它顺便修了
claude "按审查报告修复所有高风险和中风险问题"

Q7：Claude Code 与 OpenClaw 在定位上有何不同？

面试话术：

  • Claude Code：专注编程——"程序员的生产力工具"
  • OpenClaw：多领域 Agent 平台——"个人效率的瑞士军刀"

两者互补：Claude Code 处理编程任务，OpenClaw 协调多领域工作流（查日历 + 看文档 + 写邮件）。

学习建议：Claude Code 面试核心围绕三个关键词——Agent 定位（vs 补全工具）、安全机制（三层防御/权限体系）、工程实践（Tool Use 协议/上下文管理/子 Agent）。建议按顺序理解：先搞清楚 Agent 工具的定位优势，再深入安全机制和 Tool Use 原理，最后掌握高级用法（子 Agent/上下文压缩/多会话协作）。

与面试岗位的关联：Claude Code 主要出现在AI 工程化/工具开发/全栈/开发效率方向面试中，常与以下话题联合考察：Vibe Coding 理念、AI Agent 原理、Prompt Engineering、GitHub Copilot 对比、AI 辅助开发的工程实践等。
