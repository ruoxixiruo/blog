Flask

1. Flask 的请求上下文和应用上下文?

Flask用上下文管理请求局部变量，不同请求互不干扰。请求上下文(request/session)每请求独立，应用上下文(current_app/g)跟应用绑定，g存请求级临时数据。底层用LocalProxy+LocalStack实现线程/协程隔离。

扩展:基于Werkzeug的Local/LocalStack,本质是线程/协程局部存储;with app.app_context():可在非请求环境中激活。

2. Flask 的请求钩子有哪些?

请求钩子让你在请求的不同阶段"插手":

请求到达 → before_request → 路由分发 → 视图函数
                                  ↓
                          after_request → 响应返回
                                  ↓
                          teardown_request(出错也执行)
  • before_request:请求到达未进视图，适合权限检查
  • after_request:视图处理完返回前，适合添加响应头
  • teardown_request:响应后清理，出错也执行
  • errorhandler:捕获指定异常，返回自定义错误页

扩展:before_first_request 2.3+已废弃;蓝图有自己的before_request;2.0+支持异步视图。

3. Flask 和 Django 的区别?

特性 Flask Django
定位 微框架 全栈框架
ORM 自选SQLAlchemy等 自带
项目结构 完全自由 固定结构
用户系统 需Flask-Login 自带
后台管理 需Flask-Admin 自带Admin
适用场景 小型/API/微服务 大型/快速开发

扩展:FastAPI 在 API 场景上是 Flask 的现代替代--自带异步、自动生成文档、类型校验。如果新建纯 API 项目,FastAPI 比 Flask 更合适。Flask + SQLAlchemy 在中小型项目中仍然经典。

4. Flask 的 Blueprint 是什么?

蓝图 = 模块化路由。把相关路由打包成一个模块,然后在主应用里"挂载"。

app = Flask(__name__)

# 各模块独立定义
user_bp = Blueprint('user', __name__, url_prefix='/user')
order_bp = Blueprint('order', __name__, url_prefix='/order')

# 统一注册
app.register_blueprint(user_bp)
app.register_blueprint(order_bp)

Blueprint将应用拆分为独立模块，每个模块定义路由后通过app.register_blueprint()注册，支持URL前缀和子域名。

扩展:url_prefix统一加前缀;大型项目每个Blueprint对应一个Python package。

5. url_for() 的作用?

根据视图函数名反向生成URL，避免硬编码路径。改路由规则后url_for('profile', username='zhangsan')自动更新。

扩展:Blueprint中用url_for('user.login');配合url_for('static', filename='app.js')生成带版本静态URL。

6. g 对象的生命周期?

g是一次请求内的全局临时存储，请求到达创建，请求结束销毁，跨请求不共享。

扩展:g的安全来自Flask上下文机制确保每请求独立实例;不要存大对象或应持久化的数据。

7. session 在 Flask 中如何工作?

Flask session数据存在客户端Cookie中，通过itsdangerous签名防篡改（未加密，敏感数据别存）。Cookie有4KB限制。需服务端存储用Flask-Session扩展存Redis/数据库。

扩展:SECRET_KEY泄露可伪造session;JWT更适合跨域API场景。

8. Flask 的大型项目如何组织?

大型项目用工厂模式+Blueprint组织：Blueprint拆路由，工厂函数创建App，配置拆到config.py。

推荐结构(工厂模式 + Blueprint):

myapp/
├── app/                    # 应用包
│   ├── __init__.py         # 工厂函数 create_app()
│   ├── models/             # 数据模型(按业务拆)
│   │   ├── user.py
│   │   └── order.py
│   ├── views/              # 视图(Blueprint)
│   │   ├── auth.py         # /auth 下的路由
│   │   ├── order.py        # /order 下的路由
│   │   └── admin.py
│   ├── services/           # 业务逻辑层
│   ├── utils/              # 工具函数
│   └── config.py           # 配置类
├── migrations/             # Flask-Migrate 迁移文件
├── tests/
└── run.py                  # 入口

工厂模式(create_app):

# app/__init__.py
def create_app(config_name='default'):
    app = Flask(__name__)
    app.config.from_object(config[config_name])

    # 注册扩展
    db.init_app(app)
    migrate.init_app(app, db)

    # 注册 Blueprint
    from app.views.auth import auth_bp
    app.register_blueprint(auth_bp, url_prefix='/auth')

    return app

核心思想:Blueprint 拆路由,工厂函数创建 App,配置拆到 config.py。

9. Flask-SQLAlchemy 的 session 和事务怎么处理?

Flask-SQLAlchemy的db.session每请求独立：请求创建，结束销毁。成功commit，异常rollback。

提交与回滚:

@app.route('/order', methods=['POST'])
def create_order():
    try:
        order = Order(user_id=1, amount=99)
        db.session.add(order)
        db.session.commit()   # 手动提交
        return jsonify({'msg': 'ok'})
    except Exception:
        db.session.rollback() # 异常回滚
        return jsonify({'msg': 'error'}), 500

常见坑：忘记commit数据不落库；过早commit后续出错无法回滚；跨请求共享session线程不安全。

扩展:可写装饰器统一处理事务;db.session.flush()可在提交前获取自增ID。

10. Flask 的异常处理和日志怎么设计?

自定义异常类+全局errorhandler，别都扔给500。日志用logging+RotatingFileHandler，别用print。

# 自定义异常类
class AppError(Exception):
    def __init__(self, message, code=400, http_status=400):
        self.message = message
        self.code = code
        self.http_status = http_status

# 全局异常处理器
@app.errorhandler(AppError)
def handle_app_error(error):
    return jsonify({'code': error.code, 'msg': error.message}), error.http_status

@app.errorhandler(404)
def handle_404(error):
    return jsonify({'code': 404, 'msg': '资源不存在'}), 404

@app.errorhandler(500)
def handle_500(error):
    app.logger.exception('服务器内部错误')  # 记录完整堆栈
    return jsonify({'code': 500, 'msg': '服务器内部错误'}), 500

日志设计:

import logging
from logging.handlers import RotatingFileHandler

# 生产环境配置
handler = RotatingFileHandler('app.log', maxBytes=10*1024*1024, backupCount=5)
handler.setFormatter(logging.Formatter(
    '%(asctime)s [%(levelname)s] %(module)s:%(lineno)d - %(message)s'
))
app.logger.addHandler(handler)

# 请求日志中间件
@app.before_request
def log_request():
    app.logger.info(f'{request.method} {request.path} ip={request.remote_addr}')

日志原则:用logging不用print;生产环境写文件带轮转;关键操作记录request_id方便追踪。

扩展:生产环境用结构化日志(JSON)对接ELK;before_request中生成g.request_id追踪链路。

11. Flask 中如何处理跨域请求(CORS)?

Flask 推荐用 flask-cors 扩展:CORS(app) 允许所有来源。 原理:服务器加 Access-Control-Allow-Origin 响应头。 复杂请求先触发 OPTIONS 预检请求。

12. Flask 如何实现请求级缓存?

请求级缓存在单次请求内复用数据,避免重复查询。Flask 用 g 对象 + 装饰器实现。

from flask import g, request

def request_cache(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        cache_key = (func.__name__, args, tuple(kwargs.items()))
        if not hasattr(g, '_cache'):
            g._cache = {}
        if cache_key not in g._cache:
            g._cache[cache_key] = func(*args, **kwargs)
        return g._cache[cache_key]
    return wrapper

@app.route('/user/<int:user_id>')
@request_cache
def get_user(user_id):
    return User.query.get(user_id)  # 同一请求多次调用只查一次

g 对象生命周期:请求开始创建,请求结束销毁,天然适合请求级缓存。

扩展:与 Redis 缓存不同,请求级缓存无需序列化、无网络开销;适合同一请求内多次调用相同函数的场景。

13. Flask 应用如何做健康检查?

生产环境 K8s/负载均衡需要健康检查端点。Flask 提供简单 /health 接口即可。

@app.route('/health')
def health():
    # 检查数据库连接
    try:
        db.session.execute('SELECT 1')
        return {'status': 'healthy', 'db': 'ok'}, 200
    except Exception as e:
        return {'status': 'unhealthy', 'error': str(e)}, 503

@app.route('/ready')
def ready():
    # 就绪检查:应用已启动且能处理请求
    return {'ready': True}, 200

健康检查(liveness)与就绪检查(readiness)分开:liveness 判断进程存活,readiness 判断能否处理请求。K8s 配置 livenessProbe 和 readinessProbe 分别调用。

扩展:健康检查不要做复杂操作(如查大表),响应必须快;可加入 Redis/MQ 连接检查;返回 JSON 格式便于监控解析。

14. Flask 如何实现请求限流？

Flask 本身无内置限流，靠扩展或中间件实现：

# 方式1: flask-limiter（最常用）
from flask import Flask
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

app = Flask(__name__)
limiter = Limiter(get_remote_address, app=app)

# 全局限流
@app.route("/api")
@limiter.limit("100/minute")  # 每分钟100次
def api():
    return {"ok": True}

# 分布式限流(Redis后端)
limiter = Limiter(get_remote_address, app=app,
                  storage_uri="redis://localhost:6379")

原理：Redis 存计数器，INCR + EXPIRE 实现滑动窗口限流。

扩展：Nginx 层也可用 limit_req_zone 做限流；429 Too Many Requests 是标准响应码；限流粒度可到用户维度（配合 JWT token）。
