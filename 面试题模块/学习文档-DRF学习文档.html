DRF 面试学习文档

1. 先搞懂：DRF 到底是个啥？

打个比方

用原生 Django 写接口就像从零开始做披萨——揉面、调酱、烤制，每一步都得自己来。DRF 则是一条自动化后厨流水线：配置几个参数，面团自动揉、酱料自动配、烤箱自动控温。还自带门禁（认证）、权限牌（权限）、排队系统（限流）。

DRF 是什么？

DRF（Django REST Framework）是基于 Django 的 Web API 框架，提供完整工具集快速构建 RESTful API。

Versioning版本标签：v1/v2 菜单API 版本管理

RESTful API 设计原则

  • 资源导向：URL 用名词（/users/），不用动词
  • HTTP 方法语义化：GET 查询、POST 创建、PUT 全量更新、PATCH 部分更新、DELETE 删除
  • 无状态：每个请求包含所有必要信息，服务器不保存客户端状态
  • 统一接口：标准 HTTP 方法、状态码、媒体类型

2. 请求和响应 —— API 的"门面"

2.1 Request 对象 —— 比原版 Django 更聪明

DRF 的 Request 扩展了 Django HttpRequest，自动解析 JSON、Form、文件等格式：

from rest_framework.request import Request

# 核心属性
request.data          # 解析后的请求体（POST/PUT/PATCH），自动适配 JSON/Form/Multipart
request.query_params  # GET 查询参数（等同于 request.GET）
request.user          # 认证后的用户对象
request.auth          # 认证凭据
request.FILES         # 上传的文件

# 内容协商
request.accepted_renderer  # 客户端期望的渲染格式
request.content_type       # 请求的 Content-Type

2.2 Response 对象 —— 自动选最合适的格式

from rest_framework.response import Response

# Response 根据 Accept 头自动选择渲染格式（JSON/HTML 等）
return Response(data, status=status.HTTP_201_CREATED)
return Response({'error': 'msg'}, status=status.HTTP_400_BAD_REQUEST)

2.3 常用状态码

from rest_framework import status

status.HTTP_200_OK                    # 成功
status.HTTP_201_CREATED               # 创建成功
status.HTTP_204_NO_CONTENT            # 删除成功（无返回内容）
status.HTTP_400_BAD_REQUEST           # 请求参数错误
status.HTTP_401_UNAUTHORIZED          # 未认证
status.HTTP_403_FORBIDDEN             # 无权限
status.HTTP_404_NOT_FOUND             # 资源不存在
status.HTTP_405_METHOD_NOT_ALLOWED    # 方法不允许
status.HTTP_500_INTERNAL_SERVER_ERROR # 服务器错误

2.4 内容协商 (Content Negotiation)

DRF 根据请求 Accept 头决定响应格式。客户端要求 JSON 则返回 JSON，要求 HTML 则渲染 Browsable API 页面。

3. 序列化器 (Serializer) —— DRF 的灵魂

用大白话说

序列化器是数据翻译官，做三件事：

  • 序列化：Python 对象 → JSON（返回给客户端）
  • 反序列化：JSON → Python 对象（客户端发来的数据存库）
  • 校验：字段类型对不对？必填字段漏没漏？

3.1 Serializer vs ModelSerializer —— 手动挡 vs 自动挡

对比项Serializer（手动挡）ModelSerializer（自动挡）
定义方式手动声明每个字段自动根据 Model 生成字段
使用场景非模型数据、复杂校验标准 CRUD、Model 直接关联
create/update需手动实现自动实现

面试话术："能用 ModelSerializer 就先用它，省事；复杂逻辑再退化到 Serializer 手动控制。"

3.2 ModelSerializer 基础用法

from rest_framework import serializers
from .models import Article

class ArticleSerializer(serializers.ModelSerializer):
    author_name = serializers.CharField(source='author.username', read_only=True)

    class Meta:
        model = Article
        fields = ['id', 'title', 'content', 'author_name', 'created_at']
        # exclude = ['author']  # 与 fields 二选一
        read_only_fields = ['created_at']

    # 字段级别校验
    def validate_title(self, value):
        if len(value) < 5:
            raise serializers.ValidationError("标题至少5个字符")
        return value

    # 对象级别校验（多字段联合）
    def validate(self, attrs):
        if attrs.get('title') == attrs.get('content'):
            raise serializers.ValidationError("标题和内容不能相同")
        return attrs

3.3 SerializerMethodField —— 自定义计算字段

class ArticleSerializer(serializers.ModelSerializer):
    comment_count = serializers.SerializerMethodField()

    class Meta:
        model = Article
        fields = '__all__'

    def get_comment_count(self, obj):
        return obj.comments.count()

3.5 自定义 create 和 update

class UserSerializer(serializers.ModelSerializer):
    password = serializers.CharField(write_only=True)

    class Meta:
        model = User
        fields = ['id', 'username', 'email', 'password']

    def create(self, validated_data):
        password = validated_data.pop('password')
        user = User(**validated_data)
        user.set_password(password)
        user.save()
        return user

    def update(self, instance, validated_data):
        password = validated_data.pop('password', None)
        instance = super().update(instance, validated_data)
        if password:
            instance.set_password(password)
            instance.save()
        return instance

3.6 序列化器校验流程

                    序列化器校验流水线
  ┌─────────────────────────────────────────────────────────┐
  │                                                         │
  │  ① 字段类型校验（CharField.max_length 等内置约束）       │
  │     │  失败 → 立即返回错误，不继续                        │
  │     ▼  通过                                              │
  │  ② 字段级别的 validators 列表                           │
  │     │  失败 → 立即返回错误，不继续                        │
  │     ▼  通过                                              │
  │  ③ validate_<field_name>()  单字段自定义校验             │
  │     │  失败 → 立即返回错误，不继续                        │
  │     ▼  通过                                              │
  │  ④ validate()  对象级别校验（多字段联合）                 │
  │     │  失败 → 返回错误                                   │
  │     ▼  通过                                              │
  │  ✓ 校验通过，进入 create() / update()                    │
  │                                                         │
  └─────────────────────────────────────────────────────────┘

每一步不通过就直接返回错误，不给后续步骤机会。类比安检：先查身份证（类型校验），再看身份证是否过期（验证器），再比对姓名和脸是否一致（validate）。

4.2 @api_view（函数视图）

from rest_framework.decorators import api_view
from rest_framework.response import Response

@api_view(['GET', 'POST'])
def article_list(request):
    if request.method == 'GET':
        articles = Article.objects.all()
        serializer = ArticleSerializer(articles, many=True)
        return Response(serializer.data)

    elif request.method == 'POST':
        serializer = ArticleSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=201)
        return Response(serializer.errors, status=400)

4.3 APIView（类视图，自定义空间大）

from rest_framework.views import APIView
from rest_framework.response import Response

class ArticleListView(APIView):
    def get(self, request):
        articles = Article.objects.all()
        serializer = ArticleSerializer(articles, many=True)
        return Response(serializer.data)

    def post(self, request):
        serializer = ArticleSerializer(data=request.data)
        if serializer.is_valid(raise_exception=True):
            serializer.save()
            return Response(serializer.data, status=201)

4.5 ViewSet —— 一个类搞定所有操作

from rest_framework.viewsets import ModelViewSet
from rest_framework import mixins

# ModelViewSet = List + Create + Retrieve + Update + Destroy
class ArticleViewSet(ModelViewSet):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer
    filterset_fields = ['category', 'author']
    search_fields = ['title', 'content']
    ordering_fields = ['created_at']

# 自定义 ViewSet（仅部分操作）
class ArticleReadOnlyViewSet(mixins.ListModelMixin,
                             mixins.RetrieveModelMixin,
                             viewsets.GenericViewSet):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer

# ViewSet 中自定义 action
from rest_framework.decorators import action

class ArticleViewSet(ModelViewSet):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer

    @action(detail=True, methods=['post'])
    def publish(self, request, pk=None):
        article = self.get_object()
        article.is_published = True
        article.save()
        return Response({'status': 'published'})

    @action(detail=False, methods=['get'])
    def top_articles(self, request):
        top = self.get_queryset().order_by('-views')[:10]
        serializer = self.get_serializer(top, many=True)
        return Response(serializer.data)

5. 路由 (Routers) —— 让 URL 自动生成

大白话

不用 Router，每个 URL 得手写 path('articles/', view)。用 Router，一个 ViewSet 自动生成 6 个 URL。好比原来手动写菜单，现在菜单自动打印。

5.1 SimpleRouter

from rest_framework.routers import SimpleRouter

router = SimpleRouter()
router.register('articles', ArticleViewSet)

urlpatterns = router.urls
# 生成的路由：
# GET    /articles/         → list
# POST   /articles/         → create
# GET    /articles/{pk}/    → retrieve
# PUT    /articles/{pk}/    → update
# PATCH  /articles/{pk}/    → partial_update
# DELETE /articles/{pk}/    → destroy
# POST   /articles/{pk}/publish/  → 自定义 action

5.2 DefaultRouter

from rest_framework.routers import DefaultRouter

router = DefaultRouter()
# 额外提供 API 根视图（/api/），列出所有可用端点

6. 认证 (Authentication) —— "你是谁"

打个比方

认证是门口保安查工牌——确认身份。进去后能进哪些办公室、碰哪些文件，那是权限的事。

  │  (user,  (不识别此认证)    AuthenticationFailed  (user,         │
  │   auth)                       (token 过期等)      auth)          │
  │     │         │                 │                  │             │
  │     │         ▼                 ▼                  │             │
  │     │    ┌───────────────┐  ┌───────────────┐      │             │
  │     │    │  认证类 [1]    │  │  立即返回 401  │      │             │
  │     │    │ authenticate()│  │  不再尝试后续   │      │             │
  │     │    └───────┬───────┘  └───────────────┘      │             │
  │     │         (...) 循环                          │             │
  │     │            │                                  │             │
  │     │            ▼ 全部返回 None                    │             │
  │     │       ┌──────────────────┐                   │             │
  │     │       │ request.user =   │                   │             │
  │     │       │ AnonymousUser    │                   │             │
  │     │       └──────────────────┘                   │             │
  │     │                                              │             │
  │     ▼                                              ▼             │
  │  ┌──────────────────────────────────────────────────────┐       │
  │  │  认证成功！                                          │       │
  │  │  request.user = user, request.auth = auth             │       │
  │  │  停止遍历后续类，进入权限检查                          │       │
  │  └──────────────────────────────────────────────────────┘       │
  │                                                                  │
  └─────────────────────────────────────────────────────────────────┘

三种返回结果

authenticate() 返回值含义后续行为
(user, auth) 元组认证成功停止遍历，设置 request.user 和 request.auth
None不适用（跳过）继续尝试下一个认证类
抛出 AuthenticationFailed认证失败立即终止，返回 401，不再尝试后续类

关键规则

  1. 顺序决定优先级：列表前面的先执行
  2. 首个成功即停止：返回 (user, auth) 则后续不再执行
  3. None 是"跳过"：表示"这不归我管"
  4. 异常是"否决"：抛出 AuthenticationFailed 直接 401
  5. 全部跳过则匿名：request.user = AnonymousUser

源码验证

@property
def user(self):
    if not hasattr(self, '_user'):
        self._authenticate()
    return self._user

def _authenticate(self):
    for authenticator in self.authenticators:
        try:
            user_auth_tuple = authenticator.authenticate(self)
        except exceptions.APIException:
            self._not_authenticated()
            raise

        if user_auth_tuple is not None:
            self._authenticator = authenticator
            self.user, self.auth = user_auth_tuple
            return

    self._not_authenticated()  # 所有类都返回 None

场景 A：请求带 Authorization: Bearer <jwt_token>
  → ① JWT 验证成功 → (user, token) → ②③ 不执行
  → request.user = user ✅

  → ① JWT 没找到 Bearer token → None
  → ② Session 有效 → (user, None) → ③ 不执行

场景 C：请求带 Authorization: Basic <base64>
  → ① 格式不对 → None
  → ② 无 Session → None
  → ③ Basic 验证成功 → (user, None)
  → request.user = user ✅

场景 D：请求带过期 JWT token
  → ① token 过期 → 抛出 AuthenticationFailed
  → 立即 401，②③ 不执行 ❌

场景 E：请求无任何认证信息

from rest_framework.authentication import BaseAuthentication
from rest_framework.exceptions import AuthenticationFailed

class MyTokenAuthentication(BaseAuthentication):
    def authenticate(self, request):
        token = request.META.get('HTTP_AUTHORIZATION', '')
        if not token.startswith('Bearer '):
            raise AuthenticationFailed('无效的认证信息')
        token_key = token[7:]
        user = self._verify_token(token_key)  # 自定义验证逻辑
        return (user, token_key)  # 返回 (user, auth)

    def authenticate_header(self, request):
        return 'Bearer'

from rest_framework.permissions import BasePermission

class IsOwnerOrReadOnly(BasePermission):
    def has_permission(self, request, view):
        # 视图级别：是否允许访问此视图
        if request.method in SAFE_METHODS:
            return True
        return request.user and request.user.is_authenticated

    def has_object_permission(self, request, view, obj):
        # 对象级别：是否允许操作此对象（仅 retrieve/update/destroy 时调用）
        if request.method in SAFE_METHODS:
            return True
        return obj.author == request.user

has_permission()（视图级） → has_object_permission()（对象级）

has_object_permission 只在 retrieve/update/destroy 等操作单个对象时调用。

14.2 常用钩子方法（ViewSet 中）

class ArticleViewSet(ModelViewSet):
    queryset = Article.objects.all()
    serializer_class = ArticleSerializer

    def get_queryset(self):
        # 自定义查询集
        return Article.objects.filter(author=self.request.user)

    def get_serializer_class(self):
        # 不同 action 用不同序列化器
        if self.action == 'list':
            return ArticleListSerializer
        return ArticleDetailSerializer

    def get_serializer_context(self):
        # 传递额外上下文
        context = super().get_serializer_context()
        context['request'] = self.request
        return context

    def perform_create(self, serializer):
        # save 前做额外处理
        serializer.save(author=self.request.user)

    def perform_destroy(self, instance):
        # 自定义删除（软删除）
        instance.is_deleted = True
        instance.save()

16. 高频面试题

Q1：DRF 的请求生命周期？

HTTP 请求
  → Django 中间件
  → URL 路由匹配
  → 认证 (Authentication)     —— 401 未认证
  → 权限 (Permission)          —— 403 无权限
  → 限流 (Throttling)          —— 429 请求过多
  → 视图 dispatch()
    → get_queryset()
    → get_serializer()
    → is_valid() 校验
    → save() / .data
  → 渲染 (Renderer)
  → HTTP 响应

面试话术："DRF 请求先经 Django 中间件和路由匹配，然后依次执行认证、权限、限流三道安检，进入视图层——获取查询集、序列化、校验、持久化，最后渲染为客户端期望的格式返回。"

Q2：Serializer 和 ModelSerializer 的区别？

  • Serializer：手动定义字段，需自己实现 create() 和 update()
  • ModelSerializer：根据 Model 自动生成字段，自动实现 create() 和 update()
  • 选择：能用 ModelSerializer 就用，复杂逻辑再退化到 Serializer

Q3：认证和权限的区别？

  • 认证：确认"你是谁"，返回 (user, auth)
  • 权限：确认"你能做什么"，在认证之后执行
  • 未认证 401，无权限 403

Q4：多个认证类的调用顺序是怎样的？（高频）

  • 按 authentication_classes 列表顺序依次调用 authenticate()
  • 返回 (user, auth)：认证成功，立即停止
  • 返回 None：不适用，继续下一个
  • 抛出 AuthenticationFailed：失败，立即 401
  • 全部返回 None：request.user = AnonymousUser
  • 配置建议：最快的放前面（JWT > Session）

Q5：如何实现 JWT 认证？

  • 使用 djangorestframework-simplejwt
  • /api/token/ 获取 access_token + refresh_token
  • 请求带 Authorization: Bearer <access_token>
  • access_token 过期后用 refresh_token 刷新

Q6：ViewSet 和 Generic View 的区别？

  • Generic View：每个视图处理单个操作（如 ListCreateAPIView）
  • ViewSet：一个类包含所有 CRUD，配合 Router 自动生成 URL
  • ViewSet 用 @action 添加自定义操作

Q7：如何做接口分页？

  • PageNumberPagination：基于页码，直观
  • LimitOffsetPagination：基于偏移量，灵活
  • CursorPagination：基于游标，大数据量最优（无 COUNT）

Q8：DRF 如何处理异常？

  • 自带 exception_handler 处理 APIException 及子类
  • 可自定义 EXCEPTION_HANDLER 统一格式化响应
  • serializer.is_valid(raise_exception=True) 自动抛出 ValidationError

Q9：如何优化 DRF 接口性能？

  1. 数据库层：select_related（FK JOIN）、prefetch_related（M2M）
  2. 字段控制：only() / defer() 减少查询字段
  3. 分页：大数据量用 CursorPagination
  4. 缓存：热点数据用 Django cache 或 Redis
  5. 序列化器：按场景用不同 Serializer，避免过度查询

Q10：如何实现 API 版本管理？

  • URLPathVersioning（推荐）：/api/v1/articles/
  • QueryParameterVersioning：?version=v1
  • AcceptHeaderVersioning：Accept Header 中指定
  • 通过 get_serializer_class() 等方法切换版本逻辑

Q11：Serializer 的校验顺序？

1. 字段类型校验（如 CharField 的 max_length）
2. 字段的 validators 列表
3. validate_<field_name>()  字段级别校验
4. validate()              对象级别校验（多字段联合）

    filterset_fields = ['category', 'status']   # 精确匹配
    search_fields = ['title', 'content']         # 模糊搜索（icontains）
    ordering_fields = ['created_at', 'views']    # 排序

Q16：如何写单元测试？

from rest_framework.test import APITestCase
from django.urls import reverse

class ArticleAPITest(APITestCase):
    def setUp(self):
        self.user = User.objects.create_user(username='test', password='123')
        self.client.force_authenticate(user=self.user)

    def test_list_articles(self):
        url = reverse('article-list')
        response = self.client.get(url)
        self.assertEqual(response.status_code, 200)

    def test_create_article(self):
        url = reverse('article-list')
        data = {'title': 'Test', 'content': 'Content'}
        response = self.client.post(url, data, format='json')
        self.assertEqual(response.status_code, 201)
