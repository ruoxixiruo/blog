Spring Cloud Gateway 面试学习文档

📅 整理日期：2026-06-14 | 🎯 目标：系统掌握 Spring Cloud Gateway 核心原理与面试高频考点

1. Gateway 概述

1.1 定位

Spring Cloud Gateway 是 Spring 官方推出的第二代 API 网关，基于 Spring 5、Project Reactor 和 Spring Boot 2.x，使用 WebFlux + Netty 实现异步非阻塞 I/O。

核心职责：微服务架构的统一入口，集中处理路由、认证、限流、熔断、监控等横切关注点。

面试话术：Gateway 基于 Netty 实现异步非阻塞，单线程可处理海量连接，这是对比 Zuul 1.x（同步阻塞 Servlet 模型）的根本性能优势。

1.2 Gateway vs Zuul 对比

对比项 Spring Cloud Gateway Zuul 1.x Zuul 2.x
I/O 模型 异步非阻塞（Netty） 同步阻塞（Servlet） 异步非阻塞
性能 高（~30k RPS） 低（~5k RPS） 中高
背压支持 ✅（Project Reactor） ❌ ✅
Spring 生态集成 ✅ 原生 ⚠️ 需适配 ⚠️ 需适配
配置灵活性 ✅ YAML/Java DSL ⚠️ 硬编码多 ✅
过滤器类型 GatewayFilter + GlobalFilter Pre/Post Filter Inbound/Outbound
官方维护 ✅ Spring 官方 ❌ Netflix 停止维护 ⚠️ 社区维护
学习曲线 中 低 中高

1.3 核心特性

  • 基于 Spring Framework 5、Project Reactor、Spring Boot 2.x
  • 支持任何请求属性上的路由匹配
  • Predicate + Filter 链式处理
  • 集成 Spring Cloud DiscoveryClient（Nacos/Eureka）
  • 集成 Resilience4j 熔断
  • 基于 Redis 的分布式限流
  • 路径重写、WebSocket 路由

1.4 请求处理流程

                   +-------------------------------------------------------+
                   |             Gateway Request Flow                       |
                   +-------------------------------------------------------+

     Client                Gateway                           Downstream
       |                      |                                   |
       |   HTTP Request       |                                   |
       +--------------------->|                                   |
       |                      |                                   |
       |               +------+------+                            |
       |               |  Handler    |  1. traverse RouteDefs     |
       |               |  Mapping    |     match Predicates       |
       |               +------+------+                            |
       |                      |                                   |
       |               +------+------+                            |
       |               |  Web        |  2. assemble Filter chain  |
       |               |  Handler    |     GlobalFilter            |
       |               +------+------+   + GatewayFilter           |
       |                      |                                   |
       |               +------+------+                            |
       |               |  Pre        |  3. pre-filters            |
       |               |  Filters    |     auth / ratelimit       |
       |               +------+------+     add headers            |
       |                      |                                   |
       |                      |   Proxied Request                 |
       |                      +---------------------------------->|
       |                      |                                   |
       |                      |   Response                        |
       |                      |<----------------------------------+
       |                      |                                   |
       |               +------+------+                            |
       |               |  Post       |  4. post-filters           |
       |               |  Filters    |     logging / metrics      |
       |               +------+------+     modify response        |
       |                      |                                   |
       |   HTTP Response      |                                   |
       |<---------------------+                                   |
       |                      |                                   |

关键点：过滤器链分 Pre（请求转发前）和 Post（响应返回前）两个阶段，通过 ServerWebExchange 在过滤器间共享上下文。

2. 核心三组件：Route / Predicate / Filter

2.1 定义

概念 说明
Route（路由） 网关基本构建块，由 ID、目标 URI、Predicate 集合、Filter 集合组成
Predicate（断言） Java 8 Predicate，匹配 HTTP 请求属性（路径、方法、Header 等），决定请求走哪条路由
Filter（过滤器） GatewayFilter 实例，在转发前 / 返回后修改请求和响应

2.2 路由匹配与 Filter 链架构

                 +---------------------------------------------+
                 |    Routing & Filter Chain Architecture       |
                 +---------------------------------------------+

     Incoming Request
           |
           v
    +----------------------------------------------------+
    |             Route Predicate Matching                |
    |                                                    |
    |   Route-0: [Path=/api/orders/**] ---> MATCH?      |
    |   Route-1: [Path=/api/users/**]  ---> MATCH? [X]  |
    |   Route-2: [Path=/api/**]        ---> (skipped)   |
    |                                                    |
    |   Rule: first-match wins, order matters            |
    +------------------------+---------------------------+
                             | Route-1 matched
                             v
    +----------------------------------------------------+
    |              Filter Chain Assembly                  |
    |                                                    |
    |   +------------------------------------------+     |
    |   |  Mixed & sorted by Order (low -> high)   |     |
    |   |                                          |     |
    |   |  GlobalFilter[]  +  GatewayFilter[]      |     |
    |   |                                          |     |
    |   |  Example order:                          |     |
    |   |    -100 -- AuthGlobalFilter               |     |
    |   |       0 -- GatewayMetricsFilter           |     |
    |   |       1 -- StripPrefix (GatewayFilter)    |     |
    |   |      50 -- AddRequestHeader (GatewayFilter)|    |
    |   |   10150 -- ReactiveLoadBalancerClientFilter|    |
    |   |                                          |     |
    |   |  PRE:  execute in order  (small -> large) |    |
    |   |  POST: execute in reverse (large -> small)|    |
    |   +------------------------------------------+     |
    +------------------------+---------------------------+
                             |
                             v
                    Downstream Service

注意：Route 定义顺序决定匹配优先级，先定义的先匹配，匹配即停止。同一 Route 内多个 Predicate 是 AND 关系（全部满足才命中）。

2.3 Predicate 组合示例

spring:
  cloud:
    gateway:
      routes:
        - id: complex-route
          uri: https://example.org
          predicates:
            - Path=/api/users/**
            - Method=GET
            - Header=X-Request-Id, \d+          # regex match
            - Query=version, v[12]              # version=v1 or v2

3.2 Java DSL 配置

@Configuration
public class GatewayConfig {

    @Bean
    public RouteLocator customRouteLocator(RouteLocatorBuilder builder) {
        return builder.routes()
            .route("user-service-route", r -> r
                .path("/api/users/**")
                .filters(f -> f
                    .stripPrefix(1)
                    .addRequestHeader("X-Gateway", "SCG")
                )
                .uri("lb://user-service")
            )
            .route("order-service-route-v1", r -> r
                .weight("order-group", 80)
                .uri("lb://order-service-v1")
            )
            .route("order-service-route-v2", r -> r
                .weight("order-group", 20)
                .uri("lb://order-service-v2")
            )
            .build();
    }

    @Bean
    public GlobalFilter customGlobalFilter() {
        return (exchange, chain) -> {
            exchange.getRequest().mutate()
                .header("X-Request-Id", UUID.randomUUID().toString())
                .build();
            return chain.filter(exchange);
        };
    }
}

6. 自定义谓词和过滤器

6.1 自定义 RoutePredicateFactory

// match by request header X-Api-Version
@Component
public class VersionRoutePredicateFactory
        extends AbstractRoutePredicateFactory<VersionRoutePredicateFactory.Config> {

    public VersionRoutePredicateFactory() {
        super(Config.class);
    }

    @Override
    public Predicate<ServerWebExchange> apply(Config config) {
        return exchange -> {
            String version = exchange.getRequest()
                .getHeaders()
                .getFirst("X-Api-Version");
            return version != null && version.equals(config.getVersion());
        };
    }

    @Data
    public static class Config {
        private String version;
    }
}

# usage
spring:
  cloud:
    gateway:
      routes:
        - id: version-route
          uri: https://example.org
          predicates:
            - Version=1.0

6.2 自定义 GatewayFilterFactory

// log request elapsed time
@Component
public class RequestTimeGatewayFilterFactory
    extends AbstractGatewayFilterFactory<RequestTimeGatewayFilterFactory.Config> {

    private static final String START_TIME = "startTime";

    public RequestTimeGatewayFilterFactory() {
        super(Config.class);
    }

    @Override
    public GatewayFilter apply(Config config) {
        return (exchange, chain) -> {
            exchange.getAttributes().put(START_TIME, System.currentTimeMillis());
            return chain.filter(exchange).then(
                Mono.fromRunnable(() -> {
                    Long startTime = exchange.getAttribute(START_TIME);
                    if (startTime != null) {
                        long duration = System.currentTimeMillis() - startTime;
                        log.info("Request {} took {} ms",
                            exchange.getRequest().getPath(), duration);
                    }
                })
            );
        };
    }

    @Data
    public static class Config {
        private boolean enabled = true;
    }
}

7. 全局过滤器

7.1 GatewayFilter vs GlobalFilter

GatewayFilter：作用于指定路由，在 YAML 的 filters 节点引用。
GlobalFilter：作用于所有路由，@Component 注解自动注册。

7.2 内置 GlobalFilter 及执行顺序

                  +---------------------------------------------+
                  |        Filter Chain Execution Order          |
                  +---------------------------------------------+

    +---------------------------------------------------------------+
    |                    PRE (Request Direction)                     |
    |                    small order ----------------> large         |
    |                                                                |
    |   -1: NettyWriteResponseFilter                                |
    |   -100: AuthGlobalFilter (custom)                             |
    |    0: GatewayMetricsFilter                                    |
    |    1: StripPrefix (GatewayFilter)                             |
    |   50: AddRequestHeader (GatewayFilter)                        |
    | 10000: WebClientHttpRoutingFilter                             |
    | 10150: ReactiveLoadBalancerClientFilter                       |
    |                                                                |
    +------------------------------+--------------------------------+
                                   |  Proxy Request
                                   v
                              Downstream Service
                                   |
                                   v
                                Response
    +------------------------------+--------------------------------+
    |                   POST (Response Direction)                    |
    |                   large order ----------------> small          |
    |                                                                |
    |   (executed in reverse order of PRE: large -> small)          |
    |                                                                |
    | 10150: ReactiveLoadBalancerClientFilter (post)                |
    | 10000: WebClientHttpRoutingFilter (post)                      |
    |   50: AddRequestHeader (post)                                 |
    |    1: StripPrefix (post)                                      |
    |    0: GatewayMetricsFilter (post)                             |
    |   -100: AuthGlobalFilter (post)                               |
    |   -1: NettyWriteResponseFilter (post)                         |
    |                                                                |
    |   KEY: GlobalFilter and GatewayFilter are merged into ONE     |
    |        chain, sorted by getOrder().                           |
    |        PRE: small->large, POST: large->small.                 |
    +---------------------------------------------------------------+

        ServerHttpRequest request = exchange.getRequest();

            .build();

        return chain.filter(exchange.mutate().request(mutatedRequest).build());
    }

    @Override
    public int getOrder() { return -100; }

8. 限流

8.1 令牌桶算法

Gateway 基于 Redis + Lua 脚本 实现令牌桶限流：令牌以固定速率（replenishRate）补充到桶中，桶有容量上限（burstCapacity），请求到达时消耗令牌，令牌不足则拒绝（HTTP 429）。

使用 Redis 的原因：Gateway 多实例部署时，令牌状态需全局共享，Lua 脚本保证原子性。

8.2 配置

spring:
  cloud:
    gateway:
      routes:
        - id: rate-limit-route
          uri: lb://user-service
          predicates:
            - Path=/api/users/**
          filters:
            - name: RequestRateLimiter
              args:
                redis-rate-limiter.replenishRate: 10
                redis-rate-limiter.burstCapacity: 20
                redis-rate-limiter.requestedTokens: 1
                key-resolver: "#{@userKeyResolver}"

8.3 限流维度（KeyResolver）

// rate-limit by IP
@Bean
public KeyResolver ipKeyResolver() {
    return exchange -> Mono.just(
        exchange.getRequest().getRemoteAddress().getAddress().getHostAddress()
    );
}

// rate-limit by user
@Bean
public KeyResolver userKeyResolver() {
    return exchange -> {
        String userId = exchange.getRequest().getHeaders().getFirst("X-User-Id");
        return Mono.just(userId != null ? userId : "anonymous");
    };
}

13. Spring Cloud Gateway vs Zuul

13.1 核心差异

对比项 Spring Cloud Gateway Zuul 1.x Zuul 2.x
I/O 模型 异步非阻塞（Netty + WebFlux） 同步阻塞（Servlet） 异步非阻塞（Netty）
性能 高（~30k RPS） 低（~5k RPS） 中高（~20k RPS）
背压支持 ✅（Project Reactor） ❌ ✅
Spring 生态集成 ✅ 原生 ⚠️ 需适配 ⚠️ 需适配
配置方式 YAML/Java DSL XML/Groovy XML/Groovy
过滤器类型 GatewayFilter + GlobalFilter Pre/Post Filter Inbound/Outbound
官方维护 ✅ Spring 官方 ❌ Netflix 停止维护 ⚠️ 社区维护
启动速度 快 中 中
内存占用 低 中 中

13.2 阻塞 vs 非阻塞

  Zuul 1.x (sync-blocking):               Spring Cloud Gateway (async-nonblocking):

  Request --> Tomcat Thread --+           Request --> Netty EventLoop --+
                              |                                        |
                          [BLOCK]                                  [REACT]
                              |                                        |
                          ZuulFilter                             WebFlux Filter
                          (sync chain)                           (async chain)
                              |                                        |
                          [BLOCK]                                  [AWAIT]
                              |                                        |
                       Downstream Call                         Downstream Call
                       (sync HTTP)                             (async HTTP)
                              |                                        |
                          [BLOCK]                                  [AWAIT]
                              |                                        |
                          Response                                Response

  1 request = 1 thread                    Few EventLoop threads serve many
  Thread pool exhausted -> down           Event-driven + non-blocking I/O

13.3 迁移清单

Zuul 1.x -> Spring Cloud Gateway migration:

1. Dependencies:
   - Remove spring-cloud-starter-netflix-zuul
   - Add spring-cloud-starter-gateway
   - Remove spring-boot-starter-web (conflicts with WebFlux)

2. Config migration:
   - Zuul routes -> Gateway routes (different YAML format)
   - ZuulFilter -> GatewayFilter + GlobalFilter

3. Filter rewrite:
   - Sync return -> async return Mono<Void>
   - ThreadLocal not available -> use ServerWebExchange context

4. Verification:
   - Load test for performance comparison
   - Regression test all routing rules

14. 高频面试题

Q1：核心组件和工作原理？

三组件：Route（路由定义）、Predicate（匹配条件）、Filter（请求/响应拦截）。

流程：请求到达 -> Handler Mapping 匹配 Route（按 Predicate）-> 组装 Filter 链（GlobalFilter + GatewayFilter 合并排序）-> Pre Filter 阶段 -> 转发下游服务 -> Post Filter 阶段 -> 响应返回。

Q2：与 Zuul 的区别？

核心：Gateway 异步非阻塞（Netty），Zuul 1.x 同步阻塞（Servlet）。Gateway 性能约 6 倍于 Zuul 1.x，且 Spring 官方维护。详见第 13 章对比表。

Q3：GatewayFilter 和 GlobalFilter 的区别？

对比项 GatewayFilter GlobalFilter
作用范围 单个路由（YAML filters 节点引用） 所有路由（@Component 自动注册）
执行顺序 与 GlobalFilter 混合排序，按 Order 值 按 Order 值排序
典型场景 路径重写、Header 修改 认证、日志、限流

Q4：如何自定义全局过滤器实现认证？

实现 GlobalFilter + Ordered 接口，filter() 返回 Mono<Void>。认证失败调用 setComplete() 中断链，认证成功将用户信息写入请求头传递给下游（详见 7.3 节代码）。

Q5：如何实现限流？

内置 RequestRateLimiter GatewayFilter，基于 Redis + Lua 令牌桶算法。通过 KeyResolver 按 IP/用户/接口维度限流。详见第 8 章。

Q6：如何与 Nacos 集成实现动态路由？

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>

spring:
  cloud:
    nacos:
      discovery:
        server-addr: nacos-server:8848
      config:
        server-addr: nacos-server:8848
        file-extension: yaml
    gateway:
      discovery:
        locator:
          enabled: true

流程：Nacos 存储路由配置 -> Gateway 监听变更 -> RouteDefinitionWriter 更新路由 -> ApplicationEventPublisher 刷新缓存。

Q7：过滤器执行顺序？

GlobalFilter 和 GatewayFilter 合并为一条链，按 Ordered.getOrder() 排序。Pre 阶段 order 小的先执行，Post 阶段逆序（order 大的先执行）。详见 7.2 节流程图。

Q8：如何处理超时？

spring:
  cloud:
    gateway:
      httpclient:
        connect-timeout: 1000
        response-timeout: 5s
      routes:
        - id: timeout-route
          uri: lb://user-service
          predicates:
            - Path=/api/users/**
          filters:
            - name: CircuitBreaker
              args:
                name: userCircuitBreaker
                fallbackUri: forward:/fallback/timeout

Q9：如何支持 WebSocket？

spring:
  cloud:
    gateway:
      routes:
        - id: websocket-route
          uri: ws://websocket-service:8080
          predicates:
            - Path=/ws/**

URI 使用 ws:// / wss://，内置 WebSocketRoutingFilter 自动处理，支持 STOMP/SockJS。

Q10：如何与 Sentinel 集成？

<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
<dependency>
    <groupId>com.alibaba.cloud</groupId>

  cloud:
    sentinel:
      transport:
        dashboard: sentinel-dashboard:8080

Sentinel Dashboard 中配置流控规则（QPS 阈值）、熔断规则（慢调用比例/异常比例）和热点规则。

学习建议：Spring Cloud Gateway 面试聚焦三个关键词：异步非阻塞（WebFlux/Netty）、过滤器链（GlobalFilter/GatewayFilter 合并排序）、微服务网关场景（限流/熔断/认证/灰度）。建议先理解 WebFlux 响应式模型，再深入 Gateway 过滤器机制，最后掌握与 Nacos/Sentinel/Resilience4j 的集成。
