Python 异步编程面试指南

1. 基础概念

1.1 什么是异步编程？

异步编程是一种并发模型：程序在等待 I/O（网络、文件、数据库）时不阻塞线程，转而执行其他任务，待 I/O 就绪后再回来处理结果。核心思想是让出控制权，而非空等。

1.2 Python 异步编程的演进

版本 特性
Python 3.4 引入 asyncio 模块，@asyncio.coroutine + yield from 语法
Python 3.5 引入 async/await 语法糖（PEP 492）
Python 3.7 asyncio.run() 成为标准入口，API 基本稳定
Python 3.8 Task 可直接取消，to_thread() 预览
Python 3.9 asyncio.to_thread() 正式发布
Python 3.10 asyncio.TaskGroup 正式加入
Python 3.11 TaskGroup 异常处理增强，asyncio.timeout() 上下文管理器
Python 3.12 性能优化，更完善的 Task 调试支持

1.3 核心术语

术语 含义
协程 (Coroutine) 可暂停和恢复的函数，用 async def 定义
事件循环 (Event Loop) 异步程序的核心调度器，驱动协程执行
Future 代表一个未来的结果，底层可等待对象
Task 对协程的封装，用于并发调度
可等待对象 (Awaitable) 可用 await 等待的对象：协程、Task、Future

2.1 事件循环工作原理


                    ┌─────────────────────────────────────────┐
                    │              EVENT LOOP                  │
                    │                                          │
  ┌─────┐           │   ┌──────────┐      ┌──────────┐        │
  │就绪 │──入队────►│   │  Task A  │      │  Task B  │        │
  │任务 │           │   │ (运行中) │      │ (挂起)   │        │
  └─────┘           │   └────┬─────┘      └────┬─────┘        │
                    │        │                  │              │
                    │        │ 遇到 await       │ 等待 I/O    │
                    │        ▼                  │              │
                    │   ┌─────────┐            │              │
                    │   │ 挂起 A  │            │              │
                    │   │ 注册IO  │            │              │
                    │   └────┬────┘            │              │
                    │        │                  │              │
                    │        ▼                  ▼              │
                    │   ┌──────────────────────────────────┐   │
                    │   │         I/O Selector              │   │
                    │   │    (epoll / kqueue / IOCP)        │   │
                    │   │                                    │   │
                    │   │  poll() ──► 返回就绪的 fd 列表     │   │
                    │   └──────────────┬───────────────────┘   │
                    │                  │                        │
                    │                  ▼                        │
                    │   ┌──────────────────────────────┐       │
                    │   │  将就绪 Task 重新入队         │       │
                    │   │  取出下一个 Task 执行          │       │
                    │   └──────────────────────────────┘       │
                    │                                          │
                    │  循环执行直到所有 Task 完成               │
                    └─────────────────────────────────────────┘

工作流程:
1. 取出就绪队列中的 Task，执行到 await
2. Task 挂起时，将 I/O fd 注册到 Selector
3. Selector 阻塞等待 I/O 事件（或超时）
4. I/O 就绪 → 对应 Task 重新入队
5. 回到步骤 1

2.2 协程的执行模型

async def fetch_data():
    # 1. 发起网络请求（非阻塞）
    response = await http_client.get("https://api.example.com")
    # 2. 等待网络 I/O 时，控制权交还事件循环
    # 3. 网络响应到达，事件循环恢复此协程
    # 4. 继续执行
    data = await response.json()
    return data

关键点： - await 是协程让出控制权的挂起点 - 挂起期间事件循环可执行其他协程 - 单线程内实现并发，无线程切换开销

4. 协程 vs 线程 vs 多进程

协程 vs 线程 调度对比


═══════════════════════════════════════════════════════════════
  协程 (协作式调度)                   线程 (抢占式调度)
───────────────────────────────────────────────────────────────
                                      OS 内核
  Event Loop (用户态)                   │
  │                                     │  时间片中断
  │  Task A ──await──► Task B          │  ┌───┐
  │    ▲                  │            │  │ T1├── 强制切换 ──► T2
  │    │    主动让出      ▼            │  └───┘
  │    └─────────────────┘            │   ▲      │
  │                                     │   │      ▼
  │  切换由代码控制                     │   └──────┘
  │  切换开销: ~100 ns                  │  切换开销: ~1-10 us
  │  无需锁（单线程）                   │  需要锁保护共享数据
  │  单核即可承载万级协程               │  受 GIL 限制
───────────────────────────────────────────────────────────────

  多进程 (并行)                        适用场景速查
───────────────────────────────────────────────
  CPU Core 1 ── Process A              I/O 密集型 ──► 协程
  CPU Core 2 ── Process B              CPU 密集型 ──► 多进程
  CPU Core N ── Process N              简单并发   ──► 线程池
  每个进程独立 GIL + 独立内存空间
═══════════════════════════════════════════════════════════════
维度 协程 (asyncio) 多线程 (threading) 多进程 (multiprocessing)
并发模型 协作式（单线程） 抢占式（多线程） 并行（多进程）
切换开销 极小（用户态） 较大（内核态切换） 最大（进程切换）
GIL 限制 不受 GIL 限制 受 GIL 限制 不受 GIL 限制
适用场景 I/O 密集型 I/O 密集型（简单场景） CPU 密集型

数据共享 天然共享（同一线程） 需要锁保护 需要进程间通信

面试回答模板：

Python 的异步编程主要针对 I/O 密集型 场景。在单线程内通过协程切换实现并发，避免了线程切换的开销和 GIL 的限制。对于 CPU 密集型任务，应该使用多进程；简单的 I/O 并发也可以用线程池。协程的最大优势是可以支撑非常高的并发量，比如同时处理几万个网络连接。

5. 高频面试题与标准答案

Q1: async def 和普通 def 有什么区别？

async def async_func():       # 返回协程对象
    return 42

def normal_func():            # 直接返回结果
    return 42

# 调用方式
async_func()     # 返回 coroutine 对象，函数体不会执行！
await async_func()  # 真正执行，得到 42
normal_func()    # 直接得到 42

核心区别： - async def 调用后返回协程对象，函数体不立即执行 - 必须通过 await 或事件循环来驱动执行 - async def 内部可使用 await 关键字

Q2: await 只能用在 async def 里面吗？

是的，但有例外：

# ❌ 错误：普通函数中使用 await
def foo():
    result = await some_coro()  # SyntaxError!

# ✅ 正确：async 函数中使用 await
async def foo():
    result = await some_coro()

# ✅ 特殊例外：使用 asyncio.run()
async def main():
    await coro()

asyncio.run(main())  # Python 3.7+，在事件循环中驱动 main()

await 必须出现在 async def 内部（或异步调用链中），不能出现在普通函数里。

Q3: asyncio.create_task() 和 await 直接调用有什么区别？

async def main():
    # 方式1: await 直接调用 — 串行执行
    result1 = await fetch(1)  # 等待完成
    result2 = await fetch(2)  # 然后执行
    # 总耗时 = fetch(1) + fetch(2)

    # 方式2: create_task — 并发执行
    task1 = asyncio.create_task(fetch(1))  # 立即开始调度
    task2 = asyncio.create_task(fetch(2))  # 立即开始调度
    result1 = await task1  # 等待结果
    result2 = await task2
    # 总耗时 ≈ max(fetch(1), fetch(2))

关键区别： - await 直接调用：串行执行 - create_task()：并发执行，立即注册到事件循环

Q4: asyncio.gather() 和 asyncio.wait() 的区别？

# gather: 收集结果，按顺序返回
results = await asyncio.gather(coro1(), coro2(), coro3())
# results = [result1, result2, result3] — 按参数顺序

# wait: 返回两个集合，支持细粒度控制
done, pending = await asyncio.wait(
    [coro1(), coro2(), coro3()],
    return_when=asyncio.FIRST_COMPLETED  # ALL_COMPLETED / FIRST_EXCEPTION
)
维度 gather wait
返回值 结果列表（按传入顺序） (done, pending) 两个集合
取消 一个失败可用 return_exceptions=True 继续执行其他 手动取消 pending
控制粒度 较粗 更细（可指定完成条件）
推荐场景 收集所有结果 需要超时、部分取消等精细控制

Q5: 什么是 asyncio.run()？Python 3.7 之前怎么运行？

# Python 3.7+
asyncio.run(main())  # 创建新事件循环，运行 main，然后关闭

# Python 3.7 之前
loop = asyncio.get_event_loop()
try:
    loop.run_until_complete(main())
finally:
    loop.close()

asyncio.run() 不能在已运行的事件循环中嵌套调用，否则抛出 RuntimeError。

Q6: 如何在异步代码中调用同步阻塞函数？

import asyncio

def blocking_io():       # 同步阻塞函数
    import time
    time.sleep(3)         # 阻塞！会卡住事件循环
    return "done"

async def main():
    # ❌ 错误：直接调用会阻塞事件循环
    # result = blocking_io()

    # ✅ 方法1: asyncio.to_thread (Python 3.9+，推荐)
    result = await asyncio.to_thread(blocking_io)

    # ✅ 方法2: run_in_executor
    loop = asyncio.get_running_loop()
    result = await loop.run_in_executor(None, blocking_io)

    # ✅ 方法3: 指定线程池
    from concurrent.futures import ThreadPoolExecutor
    executor = ThreadPoolExecutor(max_workers=4)
    result = await loop.run_in_executor(executor, blocking_io)

面试加分回答：

直接在协程中调用同步阻塞函数是最常见的错误之一。它会阻塞整个事件循环，导致所有其他协程都无法执行。正确做法是通过 asyncio.to_thread() 或 run_in_executor() 将阻塞操作放到线程池中执行。

Q7: asyncio.sleep(0) 有什么用？

async def main():
    await asyncio.sleep(0)
    # 主动让出控制权，让事件循环有机会处理其他就绪的协程
    # 类似线程中的 Thread.yield()

应用场景：长时间计算中避免"饿死"其他协程；确保事件循环有时机处理信号和回调。

Q8: 如何实现异步上下文管理器？

# 方法1: 类实现 __aenter__ / __aexit__
class AsyncResource:
    async def __aenter__(self):
        print("获取资源")
        return self

    async def __aexit__(self, exc_type, exc_val, exc_tb):
        print("释放资源")
        return False

async with AsyncResource() as resource:
    await resource.do_something()

# 方法2: @asynccontextmanager 装饰器
from contextlib import asynccontextmanager

@asynccontextmanager
async def get_db_connection():
    conn = await create_connection()
    try:
        yield conn
    finally:
        await conn.close()

Q9: 如何取消一个异步任务？

async def main():
    task = asyncio.create_task(long_running_task())

    task.cancel()  # 发送取消请求

    try:
        await task
    except asyncio.CancelledError:
        print("任务已被取消")

注意： - cancel() 只是发送取消请求，不立即终止 - 协程需在 await 点才能响应取消 - CancelledError 不应被静默吞掉（Python 3.9+ 默认不屏蔽）

Q10: 解释 __await__ 和 __aenter__ / __aexit__

class MyAwaitable:
    def __await__(self):
        # 返回迭代器，实现自定义 awaitable 对象
        yield  # 必须至少 yield 一次
        return 42  # await 结果

async def main():
    result = await MyAwaitable()  # result = 42
  • __await__：定义如何被 await，返回一个迭代器
  • __aenter__ / __aexit__：异步上下文管理器的进入和退出协议
  • __aiter__ / __anext__：异步迭代器协议

6. 常见陷阱与最佳实践

陷阱 1: 忘记 await

async def main():
    coro = fetch_data()      # ❌ 只创建了协程对象，没有执行！
    print(coro)               # 

    result = await fetch_data()  # ✅ 正确执行

陷阱 2: 在异步代码中调用同步阻塞函数

async def main():
    time.sleep(5)    # ❌ 阻塞整个事件循环！
    await asyncio.sleep(5)  # ✅ 非阻塞等待
    requests.get(url)      # ❌ 阻塞！
    async with aiohttp.ClientSession() as s:  # ✅ 异步 HTTP
        await s.get(url)

陷阱 3: asyncio.run() 不能嵌套

async def outer():
    asyncio.run(inner())  # ❌ RuntimeError: 事件循环已在运行

    # ✅ 解决方案：直接 await
    await inner()

asyncio.run(outer())

陷阱 4: 修改共享数据没有同步保护

counter = 0

async def increment():
    global counter
    # ❌ 非原子操作，await 点之间可能交错
    temp = counter
    await asyncio.sleep(0)  # 让出控制权
    counter = temp + 1

# ✅ 使用锁
lock = asyncio.Lock()
async def safe_increment():
    global counter
    async with lock:
        counter += 1

陷阱 5: 资源泄漏 — Task 没有被等待

async def main():
    asyncio.create_task(background_work())  # Task 可能被垃圾回收

    # ✅ 正确做法：保留引用，用完 await 或 cancel
    task = asyncio.create_task(background_work())
    await task

实践 说明
使用 asyncio.run() 作为入口 Python 3.7+ 标准做法
用 create_task 实现并发 不要串行 await 多个独立操作
用 TaskGroup 管理任务组 Python 3.11+，结构化并发
阻塞调用放线程池 asyncio.to_thread() 或 run_in_executor()

7. 实战代码模板

7.1 并发 HTTP 请求

import asyncio
import aiohttp

async def fetch(session, url):
    async with session.get(url) as response:
        return await response.text()

async def fetch_all(urls, max_concurrent=10):
    sem = asyncio.Semaphore(max_concurrent)

    async def bounded_fetch(session, url):
        async with sem:
            return await fetch(session, url)

    async with aiohttp.ClientSession() as session:
        tasks = [bounded_fetch(session, url) for url in urls]
        results = await asyncio.gather(*tasks, return_exceptions=True)
        return results

async def main():
    urls = ["https://httpbin.org/get" for _ in range(100)]
    results = await fetch_all(urls)
    print(f"获取了 {len(results)} 个响应")

asyncio.run(main())

7.2 生产者-消费者模式

import asyncio

async def producer(queue):
    for i in range(10):
        await asyncio.sleep(0.1)
        await queue.put(f"item-{i}")
        print(f"生产: item-{i}")
    await queue.put(None)  # 哨兵值，通知结束

async def consumer(queue, name):
    while True:
        item = await queue.get()
        if item is None:
            queue.task_done()
            break
        print(f"{name} 消费: {item}")
        await asyncio.sleep(0.5)
        queue.task_done()

async def main():
    queue = asyncio.Queue()
    producers = [asyncio.create_task(producer(queue))]
    consumers = [asyncio.create_task(consumer(queue, f"C{i}")) for i in range(3)]

    await asyncio.gather(*producers)
    await queue.join()  # 等待所有 item 被处理
    for c in consumers:
        await c

asyncio.run(main())

7.3 带超时和重试的异步操作

import asyncio

async def fetch_with_retry(url, max_retries=3, timeout=10.0):
    for attempt in range(max_retries):
        try:
            async with asyncio.timeout(timeout):
                result = await do_fetch(url)
                return result
        except asyncio.TimeoutError:
            print(f"第 {attempt+1} 次超时")
        except Exception as e:
            print(f"第 {attempt+1} 次失败: {e}")
            if attempt < max_retries - 1:
                await asyncio.sleep(2 ** attempt)  # 指数退避
    raise RuntimeError(f"重试 {max_retries} 次后仍然失败")

async def do_fetch(url):
    await asyncio.sleep(1)
    return f"data from {url}"

8. 进阶话题

8.1 asyncio 底层实现原理

  1. 协程本质：基于生成器扩展，await 类似于 yield from
  2. 事件循环：基于 selectors 模块，使用 OS I/O 多路复用（Linux epoll, macOS kqueue, Windows IOCP）
  3. 调度方式：协作式调度，协程必须主动让出控制权（通过 await）
  4. 状态管理：每个协程有自己的调用栈，挂起时保存，恢复时还原

8.2 结构化并发 (Structured Concurrency)

Python 3.11+ 的 TaskGroup 实现了结构化并发：

async def main():
    async with asyncio.TaskGroup() as tg:
        t1 = tg.create_task(fetch_user(id=1))
        t2 = tg.create_task(fetch_orders(user_id=1))
        t3 = tg.create_task(fetch_payments(user_id=1))
    # 此处 t1, t2, t3 都已完成
    # 任一任务抛异常，其他任务自动取消

优势：子任务生命周期有明确范围；异常传播更可靠；无"孤儿"任务。

1. 异步迭代器

class AsyncRange:
    def __init__(self, n):
        self.n = n
        self.i = 0

    def __aiter__(self):
        return self

    async def __anext__(self):
        self.i += 1
        if self.i > self.n:
            raise StopAsyncIteration
        return self.i

async for i in AsyncRange(5):
    print(i)

async def async_range(n):

一句话总结（面试收尾用）

Python 的异步编程通过 async/await 语法和事件循环机制，在单线程内实现了高效的 I/O 并发。核心思想是协程在遇到 I/O 等待时主动让出控制权，事件循环在等待期间调度其他协程执行。相比多线程，协程开销极低，能轻松支撑数万级并发连接。适合 Web 服务、网络爬虫、API 网关等 I/O 密集型场景。
