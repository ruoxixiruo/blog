操作系统原理

一、操作系统概述

1.1 什么是操作系统？

操作系统是硬件之上的第一层软件，负责管理 CPU、内存、磁盘、外设等硬件资源，向上为应用程序提供统一接口。

四大职能：

  • 进程管理：调度 CPU，决定谁先运行
  • 内存管理：分配与回收内存，虚拟内存映射
  • 文件管理：组织磁盘数据，提供文件读写接口
  • 设备管理：统一管理键盘、鼠标、网卡等外设

常见操作系统：Windows、Linux、macOS、Android（基于 Linux）、iOS（基于 Darwin/XNU）

1.2 用户态与内核态

用户态：应用程序运行的级别，权限受限，不能直接操作硬件或访问内核内存。
内核态：操作系统内核运行的级别，拥有最高权限，可执行任何指令。

为什么分两态？ 防止用户程序直接操作硬件造成灾难——所有危险操作必须通过内核审批。CPU 通过状态寄存器的一个 bit 来区分当前所处模式。

  • 用户态 → 内核态：系统调用、中断、异常
  • 内核态 → 用户态：设置状态寄存器后返回

1.3 系统调用

系统调用是用户程序请求内核服务的唯一入口。

程序调用 open("test.txt")
  → 触发系统调用（int 0x80 / syscall 指令）
  → CPU 切换到内核态，内核检查权限
  → 内核执行文件打开操作，返回文件描述符
  → 切回用户态，程序拿到 fd

常见系统调用：

类别 系统调用 说明
进程管理 fork() 复制当前进程，创建子进程
执行程序 exec() 用新程序替换当前进程映像
文件 I/O read() / write() 读写文件描述符
等待进程 wait() 父进程等待子进程终止
内存映射 mmap() 映射文件或匿名内存到虚拟地址

二、进程管理

2.1 程序 vs 进程

  • 程序：静态的指令和数据的集合，存储在磁盘上（如 .exe、.elf）
  • 进程：程序的一次执行实例，包含代码段、数据段、堆栈、PCB（进程控制块）

关系：一个程序可启动多个进程（如打开两个记事本），每个进程有独立的地址空间。

2.2 进程的一生：五种状态

进程在生命周期中经历五种状态，由调度器管理状态转换。


                    ┌──────────┐
         创建成功    │  就绪态  │◄────────────────────────────┐
  创建态 ──────────► │ (Ready) │                              │
  (New)              └────┬─────┘                              │
                          │                                    │
                调度器选中  │  时间片耗尽                        │
                          ▼                                    │
                    ┌──────────┐    等待 I/O/事件      ┌───────┴───┐
                    │  运行态  │ ───────────────────► │  阻塞态   │
                    │ (Running)│                       │ (Blocked) │
                    └────┬─────┘                       └─────┬─────┘
                         │                                   │
                         │ 执行完毕                   事件就绪 │
                         ▼                                   │
                    ┌──────────┐                             │
                    │  终止态  │        ◄────────────────────┘
                    │(Terminated)│       (唤醒后回到就绪，而非直接运行)
                    └──────────┘

    转换规则:
      就绪 → 运行:  被调度器 (scheduler) 选中
      运行 → 就绪:  时间片 (time slice) 耗尽，或被更高优先级进程抢占
      运行 → 阻塞:  发起 I/O 请求 / 等待信号 / sleep()
      阻塞 → 就绪:  I/O 完成 / 事件到达 / 信号到来
      运行 → 终止:  正常退出 / 异常终止 / 被 kill

2.3 fork() —— 细胞的自我复制

fork() 是 Linux 创建新进程的核心机制——把当前进程复制一份作为子进程，父子进程从 fork() 的下一条指令继续执行。区别在于返回值：父进程拿到子进程 PID，子进程拿到 0。

写时拷贝（COW, Copy-On-Write）：fork 后父子共享同一份物理内存页，均标记为只读。当任一方写入时，触发缺页中断，系统才真正复制该页。这使得 fork 极快——多数子进程紧接着 exec()，根本不修改原内存。

fork 瞬间完成（只复制页表），真正的内存拷贝延迟到写入时才发生。

2.4 线程 —— 同一屋檐下的室友

进程是资源分配单位，线程是 CPU 调度单位。同一进程的多个线程共享代码段、数据段、堆、文件描述符，但各自拥有独立的栈和寄存器上下文。

进程 线程
资源 独立地址空间 共享进程地址空间
通信 IPC（管道、共享内存、消息队列） 直接读写共享变量
创建开销 大（复制页表、分配 PCB） 小（只需栈和 TCB）
隔离性 强（一个进程崩溃不影响其他） 弱（一个线程奔溃全进程终止）
上下文切换 慢（切换地址空间，刷 TLB） 快（同进程内不需切换页表）

2.5 协程 —— 用户态轻量级并发

协程是用户态控制的执行单元，自己决定何时让出 CPU（协作式），而非操作系统抢占。

线程 协程
调度者 操作系统（抢占式） 用户代码（协作式）
切换开销 进入内核，~1-10us 纯用户态，~几十 ns
栈大小 通常 1-8 MB 通常几 KB
并发量 数百到数千 数万到数十万

Go 语言的 goroutine 是协程的工业化实现，通过 GPM 模型将大量 goroutine 映射到少量内核线程上。

三、CPU 调度

3.1 调度层次

CPU 调度的核心问题：就绪队列里有多个进程，下一个让谁上 CPU？

三级调度：

  • 高级调度（作业调度）：决定哪些程序从磁盘加载到内存——频率低
  • 中级调度（内存调度）：内存不足时挂起/换出部分进程——频率中等
  • 低级调度（进程调度）：从就绪队列中选进程上 CPU——每几毫秒一次

3.2 常见调度算法

FCFS（先来先服务）

非抢占，按到达顺序执行。缺点：长作业在前则短作业全被堵——护航效应（Convoy Effect）。

SJF（最短作业优先）

优先执行 CPU 需求最短的作业。平均等待时间最优，但需要预知作业长度（实际靠指数平均估计），且长作业可能饥饿。

RR（时间片轮转）

每个进程分配固定时间片（通常 10-100ms），用完排到队尾。交互式系统的基础——保证响应时间。

  • 时间片太大 → 退化为 FCFS
  • 时间片太小 → 上下文切换开销占大头（一般要求切换开销 < 1% 时间片）

多级反馈队列（MLFQ）—— 现代 OS 的实用方案

无需预知作业长度，融合多种算法优势：

优先级 1（最高）: [时间片 10ms]  ← 新进程、I/O 密集型
优先级 2:        [时间片 20ms]
优先级 3:        [时间片 40ms]
优先级 4（最低）: [时间片 80ms]  ← CPU 密集型长作业

规则：高优先级优先调度；同优先级 RR；用完时间片降级。短作业在高优先级快速完成；长作业逐步降级但不会被饿死。

Linux CFS（完全公平调度）

核心思想：如果 CPU 能分身，每个进程分一个。维护 vruntime（虚拟运行时间）——已运行时间按优先级加权。每次选 vruntime 最小的进程运行，用红黑树维护（O(log n) 插入/查找）。优先级高的进程 vruntime 增长慢，自然调度次数多。

四、进程同步与互斥

4.1 临界区

临界区：访问共享资源的代码段。同一时刻只能有一个线程在执行临界区代码，否则产生竞态条件（race condition）。

互斥（Mutual Exclusion）：同一时刻最多一个线程在临界区。
同步（Synchronization）：协调线程间的执行顺序。

临界区访问的四条铁律：

  1. 空闲让进：无人在临界区时，申请者可直接进入
  2. 忙则等待：临界区被占用时，其他线程在入口等待
  3. 有限等待：等待时间必须有上界（防止饥饿）
  4. 让权等待：进不去时应释放 CPU（防止忙等浪费）

4.2 怎么实现互斥？

软件方法：Peterson 算法

两个进程通过共享标志位和 turn 变量协商进入临界区。缺点：仅适用于两个进程，在多核 CPU 上因内存重排序可能失效。

硬件方法：原子指令

CPU 提供不可分割的原子指令，执行期间不会被中断。

CAS（Compare-And-Swap）是最核心的原子原语：

// 原子操作：如果 *ptr == oldVal，则 *ptr = newVal 并返回 true
//          否则返回 false，不修改 *ptr
bool CAS(int *ptr, int oldVal, int newVal) {
    if (*ptr == oldVal) {
        *ptr = newVal;
        return true;
    }
    return false;
}

Java 的 AtomicInteger、Go 的 sync/atomic 包、C++ 的 std::atomic 底层均基于 CAS。自旋锁、无锁队列等高级并发结构也由 CAS 构建。

4.3 信号量

信号量是一个整数计数器，代表可用资源数。两个原子操作：

P(sem)  // wait: 若 sem > 0 则 sem--；否则阻塞直到 sem > 0
V(sem)  // signal: sem++，唤醒一个等待的线程

三类信号量：

类型 初值 用途
互斥信号量 1 临界区互斥（二进制信号量）
计数信号量 N 管理 N 个同类资源
同步信号量 0 约束执行顺序（先 V 后 P 可继续）

生产者-消费者问题：empty=N（空缓冲数），full=0（满缓冲数），mutex=1（缓冲区互斥）。

哲学家进餐：5 位哲学家围坐，每人一根筷子，需两根才能吃。同时拿左侧筷子则全部死锁。解法：限制最多 4 人同时上桌，或奇数编号先左后右、偶数先右后左。

4.4 互斥锁 vs 自旋锁

互斥锁（Mutex） 自旋锁（Spinlock）
等待方式 阻塞（调用者 sleep，释放 CPU） 忙等（循环检测，不释放 CPU）
CPU 消耗 无（睡眠期间不消耗） 高（持续自旋消耗 CPU）
适用场景 临界区长（> 几次上下文切换开销），用户态 临界区极短（几条指令），内核态
开销 上下文切换开销（~us 级） 无切换，但浪费 CPU 周期

内核为什么偏爱自旋锁？ 内核很多路径不能睡眠（如中断上下文），且临界区通常极短——自旋等待比 sleep/wakeup 更快。

五、死锁

5.1 什么是死锁？

死锁：两个或多个进程无限期等待对方释放资源，形成循环等待。

四个必要条件（缺一不可）：

条件 解释
互斥 资源一次只能分配一个进程
持有并等待 持有已有资源，同时等待新资源
不可抢占 已分配的资源不能被强制收回
循环等待 进程间形成资源等待环

5.2 怎么处理死锁？

预防：破坏四个条件之一

  • 一次申请所有资源（破坏持有并等待）：开始时一次性申请全部，拿不齐则一个不拿
  • 资源顺序编号（破坏循环等待）：规定申请顺序，必须从小到大申请
  • 互斥和不可抢占一般难以破坏

避免：银行家算法

每次分配前做模拟：如果按这个方案分配后，是否存在一个「安全序列」让所有进程都能执行完毕？不存在则拒绝分配。算法复杂度 O(mn^2)，实际系统很少用。

检测与恢复

允许死锁发生，定期检测（资源分配图找环），发现后强行 kill 进程或回滚。

鸵鸟策略 —— 大多数 OS 的默认选择

假装死锁不会发生。Linux 和 Windows 默认都不做死锁处理——因为死锁概率低，而预防和避免的运行时开销太大。用户手动 kill 即可。

六、内存管理

6.1 虚拟内存：每个程序都以为自己独占了整台电脑

虚拟内存是操作系统最核心的抽象之一。每个进程看到的是完整、连续、私有的地址空间（32 位即 4GB），但实际物理内存可能更小、碎片化、且被多个进程共享。

     • 虚拟页 (VP)  →  物理帧 (PF)  映射由页表维护
     • 每个进程有独立的页表 → 地址空间隔离
     • 页表项包含: 物理帧号、有效位(在内存?)、权限位(R/W/X)、脏位、访问位

虚拟内存四大好处：

  1. 隔离：进程 A 的页表看不到进程 B 的物理帧——天然沙箱
  2. 扩展：虚拟地址空间可远超物理内存（磁盘作后援）
  3. 简化：编译器和链接器只需处理统一的虚拟地址布局
  4. 共享：DLL/.so 共享库在物理内存只存一份，多进程页表指向同一帧

6.2 分页 —— 把面包切成片

分页将虚拟地址空间和物理内存都切为固定大小的块（通常 4KB），消除外部碎片。

虚拟地址 = 页号 (20 bits) + 页内偏移 (12 bits)    // 32位系统，4KB 页
            │
            │ 查页表 (Page Table)
            ▼
物理地址 = 帧号              + 页内偏移 (不变)

页表的本质：以页号为索引的数组，存储该页对应的物理帧号 + 标志位。

多级页表：32 位用两级（页目录 + 页表），64 位用四级（PGD → PUD → PMD → PTE）。多级页表按需分配中间页，大幅节省页表本身的内存开销。

6.3 TLB —— 翻译快表

页表存在内存中，每次内存访问需先查页表再取数据——两次访存，翻倍开销。

TLB（Translation Lookaside Buffer）是 MMU 内部的小型硬件缓存，存储最近翻译过的页表项。利用局部性原理，TLB 命中率通常 > 99%。

TLB 命中:   1 个时钟周期拿到物理地址
TLB 未命中: 查内存页表 (多级走 4 次访存)，可能数百周期
上下文切换:  切换进程时通常刷新 TLB（或使用 ASID 避免刷新）

6.4 缺页中断

当访问的虚拟页不在物理内存中（页表项有效位 = 0），触发缺页中断（Page Fault）：

  1. CPU 暂停当前指令，保存上下文
  2. 操作系统查找该页在磁盘的位置（swap 区或文件映射）
  3. 选择一个空闲物理帧（若没有则触发页面置换）
  4. 从磁盘读入页面到该帧
  5. 更新页表项（帧号 + 有效位置 1）
  6. 从断点恢复执行——整个过程对程序透明

缺页是操作系统「偷梁换柱」魔术的核心机制。偶尔缺页（如加载新 DLL）是正常的，频繁缺页则可能是内存不足（颠簸）。

                    │   置换算法选受害者    │
                    │                     │
                    │  OPT  → 将来最晚用到  │ ← 理论最优，不可实现
                    │  FIFO → 最早进入的   │ ← 简单但有 Belady 异常
                    │  LRU  → 最久未使用的  │ ← 近似 OPT，实现开销大
                    │  Clock→ LRU 近似版   │ ← 实际系统首选
                    └──────────┬──────────┘
                               │
                               ▼
                    选中的页是否被修改过？
                               │
                        ┌──────┴──────┐
                        │ 是 (脏页)   │ 否 (干净页)
                        ▼             ▼
                   写回磁盘         直接丢弃
                   (慢，耗IO)       (快，无IO)
                        │             │
                        └──────┬──────┘
                               ▼
                    新页加载到该帧，更新页表

各算法对比：

算法 策略 特点
OPT 换出将来最晚被访问的页 理论最优但需预知未来，作为性能标杆
FIFO 换出最先进入的页 简单但存在 Belady 异常（分配更多帧反而缺页增加）
LRU 换出最久未被访问的页 很好近似 OPT，但每次访问需更新链表，开销大
Clock 环形扫描，遇访问位=0则换出 LRU 的硬件友好近似：每页一个访问位，时钟指针循环检查

Clock 算法（二次机会）详解：

  物理帧排成环形链表，指针 (hand) 指向最老的页。
  每页有一个 R 位 (Reference bit = 访问位)。

  需要换页时:
    while (true):
      检查指针所指的页:
        if R == 0:
          淘汰该页 (换出)
          break
        else:
          R = 0          // 给第二次机会 (Second Chance)
          指针向前移动

  效果: 最近被访问过的页 (R=1) 免于被淘汰，
       只有两次扫描之间都没被访问的页才被换出。

Linux 的做法：改进的 Clock（基于 LRU 链表，区分活跃/非活跃链表、文件页/匿名页），配合后台 kswapd 守护进程异步回收页面。

6.6 颠簸（Thrashing）

颠簸：进程的工作集超出物理内存，导致系统频繁缺页换页，CPU 大部分时间花在等待磁盘 I/O 上，吞吐量断崖式下降。CPU 利用率看似高，实则全在内核换页代码中空转。

  • 检测：缺页率飙升 + CPU 利用率急降
  • 解决：减少并发进程数（中级调度换出整进程）、增大物理内存、优化程序局部性

6.7 mmap —— 文件当内存用

mmap() 将磁盘文件映射到进程的虚拟地址空间，之后用指针直接访问文件内容，如同访问内存。

数据路径对比：

传统 read():  磁盘 → 内核页缓存 → 用户缓冲区    (2 次拷贝)
mmap:         磁盘 → 内核页缓存 (用户直接读写)   (1 次拷贝)

数据库（MongoDB、LMDB）、消息队列（Kafka 的零拷贝依赖 mmap）广泛使用。

6.8 malloc 背后的秘密

void *p = malloc(1024 * 1024 * 10);  // 申请 10 MB
// 此时: 虚拟地址空间标记了 10MB，但物理内存一页未分配
p[0] = 42;   // 第一次写入 → 缺页中断 → 实际分配第一页
p[4096] = 42;  // 第二页的第一次写入 → 缺页中断 → 分配第二页
// ...

这就是惰性分配（Lazy Allocation / Overcommit）。malloc 只修改虚拟地址空间的 VMA 结构体（vm_area_struct），物理页延迟到实际访问时才通过缺页中断分配。这使得程序可以「申请」远超物理内存的空间，只要不同时写入即可。

ptmalloc / jemalloc / tcmalloc：不同的用户态内存分配器实现，在减少碎片、多线程性能等方面各有优化。

七、文件系统

7.1 文件系统架构

Linux 文件系统采用分层设计，VFS（虚拟文件系统）作为统一抽象层：

用户程序 (open / read / write)
          ↓
    VFS (虚拟文件系统) —— 统一接口，屏蔽底层差异
          ↓
    具体文件系统: ext4 / XFS / NTFS / FAT32 / btrfs
          ↓
    通用块层 (BIO, 合并/排序 IO 请求)
          ↓
    IO 调度层 (mq-deadline / kyber / bfq)
          ↓
    磁盘驱动 / 磁盘硬件

VFS 的四个核心对象：super_block（文件系统元信息）、inode（文件实体）、dentry（目录项）、file（打开的文件实例）。

7.2 inode —— 文件的身份证

inode（索引节点）存储文件除文件名外的所有元数据：

  • 类型（普通文件 / 目录 / 符号链接）、权限（rwx）
  • 所有者 ID、组 ID、文件大小
  • 三个时间戳：atime（访问）、mtime（修改）、ctime（元数据变更）
  • 数据块指针：12 个直接指针 + 1 个一级间接 + 1 个二级间接 + 1 个三级间接
  • 链接计数（指向此 inode 的硬链接数）
  • 不含文件名——文件名存在目录项的 dentry 中，指向 inode 编号

inode 数据块寻址：12 个直接块覆盖 48KB（12 x 4KB），一级间接再覆盖 4MB（1024 x 4KB），二级间接覆盖 4GB，三级间接覆盖 4TB。95% 的文件 < 48KB，直接用 12 个指针即够，无需间接开销。

7.3 硬链接 vs 软链接

硬链接 软链接（符号链接）
本质 多个目录项指向同一 inode 一个存有目标路径的特殊文件
删原文件后 不影响（inode 仍存在，链接计数减 1） 变为悬空断链（路径已无效）
跨文件系统 不可（inode 号仅在本 FS 有效） 可（存的是路径字符串）
目录 不支持（防环路） 支持
创建命令 ln source target ln -s source target

7.4 日志文件系统

问题：写文件涉及多步操作（分配数据块、更新 inode、更新位图），中途断电会导致文件系统不一致。

日志（Journaling） 解决办法：操作前先记日志——

  1. 将「即将执行的操作」写入日志区
  2. 日志提交（commit），标记为有效
  3. 执行实际操作（checkpoint）
  4. 操作完成后清除日志

重启恢复：已提交的日志重放（保证完整），未提交的丢弃（操作从不曾发生）。

ext4 默认 ordered 模式：数据内容先写入，元数据的日志后提交——兼顾数据完整性和性能。

Copy-on-Write 文件系统（btrfs、ZFS）：不原地覆写，新数据写新位置后原子切换指针。天然防断电损坏，同时支持快照。

八、I/O 系统

8.1 CPU 与设备的三种通信方式

方式 数据传输 CPU 参与 吞吐
轮询（Polling） CPU 反复读设备状态寄存器 全程占用，忙等 低
中断（Interrupt） 设备就绪后发中断通知 CPU 仅在中断处理时介入 中
DMA DMA 控制器直接设备↔内存搬运 仅配置 DMA 时介入，传输完成发中断 高

DMA 流程：CPU 配置 DMA 控制器（源地址、目标地址、字节数）→ DMA 执行传输 → 完成后中断通知 CPU。大块数据传输（磁盘 I/O、网络包）全靠 DMA 释放 CPU。

8.2 磁盘调度

机械硬盘（HDD）的核心瓶颈是寻道时间（磁头移动到目标磁道，~数 ms）。调度目标：最小化磁头移动距离。

SCAN（电梯算法）：磁头单向扫描到头再折返，顺路处理请求。
C-SCAN：仅单向处理，到头后快速归零再开始——内外圈请求公平。
LOOK / C-LOOK：SCAN/C-SCAN 的优化，不再走到尽头而是在最后一个请求处折返。

SSD 无机械寻道，但仍有批量合并、排序请求的优化价值（减少 NAND 擦写）。

8.3 零拷贝（Zero-Copy）

传统 sendfile 路径（无零拷贝优化）：

磁盘 → 内核页缓存 → 用户缓冲区 → 内核 Socket 缓冲区 → 网卡
        (DMA)        (CPU 拷贝)      (CPU 拷贝)        (DMA)
→ 4 次上下文切换 + 4 次数据拷贝（2 次 DMA + 2 次 CPU）

零拷贝 sendfile（DMA Scatter/Gather）：

磁盘 → 内核页缓存 ────────────────────────────→ 网卡
        (DMA)           (DMA Gather，直接传输)     (DMA)
→ 2 次上下文切换 + 2 次数据拷贝（全是 DMA，无 CPU 拷贝）

数据根本不进入用户态。Nginx、Kafka 的高吞吐核心原因之一就是大量使用 sendfile()。前提：数据无需用户态修改（如静态文件服务、消息转发）。

九、中断 —— 操作系统的「手机通知」

9.1 中断是什么？

中断是 CPU 对异步事件的响应机制——外部事件或内部异常发生时，CPU 暂停当前执行流，转到中断处理程序，完成后恢复。

  • 硬中断：来自硬件设备（键盘、网卡、定时器）
  • 软中断 / 异常：来自 CPU 内部（除零、缺页、系统调用）

9.2 中断处理的分工

Linux 将中断处理拆为上半部和下半部：

  • 上半部（Top Half）：中断发生时立即执行，屏蔽其他中断。只做最关键、最简短的操作（如记录数据到缓冲区、应答中断控制器）
  • 下半部（Bottom Half）：延后执行的非紧急处理（如协议栈解析数据包）。实现方式：softirq、tasklet、工作队列（workqueue）

目的：上半部尽可能短，减少中断屏蔽时间，提升系统响应性。

十、常见面试题

10.1 基础篇

1. 进程和线程的区别？

进程是资源分配单位，线程是 CPU 调度单位。

  • 进程间地址空间隔离；线程共享进程地址空间
  • 进程通信需 IPC；线程可直接读写共享变量（需同步）
  • 创建/切换进程开销大（地址空间、页表）；线程轻量（同进程内不切换页表）
  • 进程崩溃互不影响；线程崩溃通常导致全进程终止

2. fork() 之后发生了什么？什么是写时拷贝？

fork 复制当前进程产生子进程。父子共享同一份物理内存页（标记只读），任一写入时触发缺页中断，由内核单独复制该页（COW）。fork + exec 组合中，子进程往往 fork 后立刻 exec，COW 使 fork 几乎零开销。

3. 孤儿进程和僵尸进程是什么？

  • 孤儿进程：父进程先于子进程终止。init 进程（PID=1）自动收养，子进程终止时 init 负责回收
  • 僵尸进程：子进程已终止但父进程未调用 wait() 获取退出状态。PCB 仍在，占用 PID。大量僵尸会耗尽 PID 导致无法创建新进程

4. 进程间通信（IPC）有哪些方式？

方式 特点 典型场景
管道（Pipe） 单向，字节流，父子/兄弟进程 ls | grep txt
命名管道（FIFO） 有文件名，任意进程可用 无关进程通信
共享内存 最快（零拷贝），需配合信号量 大数据量共享
信号量 计数器，控制资源访问 配合共享内存的互斥/同步
消息队列 有类型的消息包，异步 解耦生产者-消费者
信号（Signal） 异步通知，携带最少信息 kill -9、SIGINT、SIGCHLD
Socket 跨主机通信 网络编程、分布式系统

10.2 同步与死锁篇

5. 死锁是什么？如何防止？

死锁 = 两个以上进程循环等待对方持有的资源。四个必要条件：互斥、持有并等待、不可抢占、循环等待。破坏任一条件即可预防死锁。常见手段：一次性申请全部资源、按编号顺序申请。

6. 优先级反转是怎么回事？

高优先级 H 等低优先级 L 释放锁；L 被中优先级 M 抢占，L 无法运行释放锁；H 被 M 无限阻塞——明明 H 优先级最高却在等待。

解决：优先级继承——L 持有锁期间，临时将其优先级提升到等待者中最高级别（H），释放锁后恢复。

7. 生产者-消费者问题怎么用信号量解？

三个信号量：mutex=1（缓冲区互斥），empty=N（空槽数），full=0（已填充数）。

生产者: P(empty) → P(mutex) → 放入数据 → V(mutex) → V(full)
消费者: P(full)  → P(mutex) → 取出数据 → V(mutex) → V(empty)

10.3 内存管理篇

8. 虚拟内存到底是什么？有什么好处？

每个进程看到的是独立、连续的虚拟地址空间；背后由 MMU+页表映射到碎片化的物理内存（或磁盘）。好处：隔离保护、突破物理内存上限、简化开发、方便共享库。

9. 什么是缺页中断？

访问虚拟页不在物理内存中时触发。OS 暂停进程，从磁盘读入页面，更新页表，恢复执行。整个过程对程序透明，是虚拟内存实现的关键机制。

10. 页面置换算法有哪些？LRU 怎么实现？

  • OPT（最优，不可实现），FIFO（简单但有 Belady 异常），LRU（近似 OPT，实现开销大），Clock（LRU 近似，实际系统首选）

LRU 实现困难：需记录每次访问的顺序（链表），每次内存访问都要更新，开销太大。Clock 算法用硬件支持的访问位 + 循环指针近似 LRU，Linux、FreeBSD 均采用此方案。

11. malloc(1MB) 真的马上分了 1MB 吗？

不。malloc 仅在虚拟地址空间标记区域，物理页延迟到实际写入时才通过缺页中断分配。这称为「惰性分配」。因此进程的 VSS（虚拟内存）可远大于 RSS（常驻物理内存）。

12. 内部碎片 vs 外部碎片

  • 内部碎片：分配单位内未使用的空间（如分配 4KB 页只用 500 字节，剩余 3.5KB 浪费）
  • 外部碎片：分散的空闲空间总和足够，但每块都不够大。分页机制消除了外部碎片

10.4 调度篇

13. 时间片轮转（RR）中时间片设多大合适？

权衡：太大 → 退化为 FCFS，交互响应差；太小 → 上下文切换开销占比过高。经验公式：切换开销 < 1% 时间片，通常 10-100ms。

14. 多级反馈队列好在哪里？

无需预知作业长短，自适应：短作业在高优先级短时间片快速完成，长作业逐步降级不会被饿死。兼具交互响应与吞吐量，是现代 OS 的实用方案。

15. Linux CFS 的 vruntime 是什么意思？

vruntime（虚拟运行时间）= 实际运行时间 x (基准优先级 / 当前进程优先级)。优先级高的增长慢，调度次数多。CFS 用红黑树维护 vruntime，每次选最小的运行，使各进程「虚拟时间」趋于一致，实现公平调度。

10.5 文件系统篇

16. inode 是什么？

inode（索引节点）是 Unix 文件系统中描述文件的数据结构，存储权限、大小、时间戳、数据块位置等元数据——唯独不含文件名（文件名在目录项中指向 inode 号）。

17. 硬链接和软链接的区别？

硬链接：多目录项指向同一 inode。删原文件后硬链接仍有效（inode 链接计数 > 0）。软链接：独立文件，内容为目标路径字符串。原文件删除后为断链。硬链接不可跨文件系统，软链接可以。

18. 什么是日志文件系统？

操作前先向日志区（journal）写入「即将做什么」，提交后再执行实际操作。崩溃后：已提交日志重放，未提交丢弃。ext4 默认 ordered 模式：数据先写，元数据日志后记，兼顾完整性与性能。

10.6 综合篇

19. select / poll / epoll 有什么区别？

select poll epoll
原理 每次拷贝全部 fd 进内核，遍历检查 同 select，但用动态数组 内核维护红黑树 + 就绪链表，事件驱动
fd 上限 1024（FD_SETSIZE） 无限制 无限制
找到就绪 fd O(n)，需遍历全部 O(n) O(1)（直接返回就绪链表中的 fd）

高并发场景（C10K/C100K）必须用 epoll。Nginx、Redis、Netty 的高并发能力都离不开 epoll / kqueue / IOCP 这类 IO 多路复用。

20. 零拷贝是什么意思？为什么重要？

零拷贝：数据从磁盘到网卡不经过用户态缓冲区，省去 CPU 拷贝。传统 send 路径 4 次拷贝（2 DMA + 2 CPU），sendfile 仅 2 次（全 DMA）。高吞吐 Web 服务器和消息队列的基础。

21. 从输入网址到页面渲染，OS 参与了多少？

全程参与：DNS 查询（内核协议栈封装 UDP）→ 建立 TCP 连接（三次握手由内核完成）→ 发送 HTTP 请求（TCP 分段、IP 路由、ARP 查询 MAC 均由内核处理）→ 接收数据（网卡中断 → DMA → 协议栈解包 → socket 接口返回）。浏览器不直接碰硬件，OS 在每一层提供服务。

22. Go 的 GPM 模型是什么？

G（Goroutine）→ P（Processor，逻辑处理器，持有 G 的本地队列）→ M（Machine，内核线程）。P 是调度核心：P 将本地队列中的 G 分配给 M 执行；G 阻塞时 M 被换下，P 带着其他 G 迁移到新 M，CPU 不空转。

23. 操作系统启动过程是怎样的？

BIOS/UEFI 自检 → 加载引导扇区（MBR/GPT）→ 引导程序（GRUB）→ 加载内核镜像到内存 → 内核初始化（中断描述符表、页表、调度器）→ 创建 init 进程（PID=1）→ systemd/init 启动用户态服务 → 登录界面。整个过程从固件到内核再到用户态，层层初始化。
