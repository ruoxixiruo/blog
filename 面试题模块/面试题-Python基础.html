Python

1. Python 的 GIL 是什么?如何规避?

GIL 是全局解释器锁,同一时刻只允许一个线程执行 Python 字节码。CPU 密集型多线程无法并行,IO 密集型在等待时自动释放 GIL 可并发。

CPU 密集:开多进程
IO 密集:多线程 / 协程即可
绕开 GIL:用 C 扩展 / Jython / 子进程
  • CPU 密集任务 → 多进程
  • IO 密集任务 → 多线程/协程
  • C 扩展可绕开 GIL
  • Jython 无 GIL,PyPy 有优化计划

扩展:Python 3.13 PEP 703 计划逐步移除 GIL;NumPy 等 C 扩展内部释放 GIL 可实现真正并行。

2. *args 和 **kwargs 的区别?

*args 接收位置参数打包为元组,**kwargs 接收关键字参数打包为字典。

def order(main, *sides, **extras):
    print(f"主食: {main}")     # 必须的
    print(f"小菜: {sides}")    # 多余的没名字参数
    print(f"加料: {extras}")   # 有名字的参数
# order("拉面", "煎蛋", "小菜", 加辣=True, 多加葱=True)

扩展:* 可用于解包赋值 a, *mid, c = [1,2,3,4,5];** 可合并字典 {**d1, **d2}。

3. 装饰器的原理与使用场景?

装饰器是接收函数、返回新函数的高阶函数,不修改原函数代码即可增强功能。

用户请求 → 装饰器(校验权限)→ 原函数(业务逻辑)→ 返回结果

场景:日志记录、权限检查、计时(@timer)、缓存(@lru_cache)、路由注册(@app.get("/"))。

扩展:带参数装饰器本质是柯里化;functools.wraps 保留原函数元信息,写装饰器必加。

4. 生成器与迭代器的区别?

迭代器实现 __iter__ 和 __next__,只能向前逐个访问。生成器是用 yield 的函数,自动成为迭代器,按需惰性求值,内存占用恒定。

生成器数据流:
yield → 暂停,返回数据 → 外部处理 → next() 唤醒 → 继续从 yield 后执行

扩展:yield from 委托子生成器;3.6+ 支持异步生成器 async def + yield。

5. Python 的垃圾回收机制?

Python GC 分三层:

引用计数(主力,立刻回收)
    ↓ 解决不了的循环引用
标记清除(定期扫描,找出循环引用垃圾)
    ↓ 优化性能
分代回收(新对象扫得勤,老对象扫得少,省力)
  • 引用计数:引用归零立即回收,无法处理循环引用
  • 标记清除:定期扫描标记存活对象,清除不可达对象
  • 分代回收:第0代扫最频,第1代次之,第2代最少

核心:新生对象频繁扫描,老对象少扫描,节省开销。

扩展:gc.collect() 手动触发,gc.disable() 关闭自动GC;tracemalloc 追踪内存分配,objgraph 可视化引用关系。

6. is 和 == 的区别?

  • is:比较对象身份(内存地址是否相同)
  • ==:比较对象值是否相等

注意:小整数(-5~256)和短字符串有缓存,a=100; b=100 时 a is b 为 True,但不应依赖此优化。

扩展:与 None 比较永远用 is(O(1)地址比较,不会被重载);id() 可查看对象地址。

7. 深拷贝与浅拷贝?

浅拷贝只复制第一层,内层对象仍共享引用;深拷贝递归复制所有层级,新旧对象完全独立。

浅拷贝:  [外层新容器] → [同内层对象]
深拷贝:  [外层新容器] → [新内层对象]

import copy
a = [1, [2, 3]]
b = copy.copy(a)      # 浅拷贝:b[1] 和 a[1] 指向同一个列表
c = copy.deepcopy(a)  # 深拷贝:c 完全独立

扩展:a[:]/list(a)/a.copy() 均为浅拷贝;自定义类可实现 __copy__/__deepcopy__ 控制行为。

8. 列表与元组的区别?

列表:可增删改,动态扩容,有预留空间 → 频繁修改用
元组:创建后锁定,无预留空间,内存更小 → 只读数据、dict key 用

元组不可变,可作字典key,省内存且创建更快。

扩展:namedtuple 支持字段名访问;3.9+ 支持 list[int] 类型标注。

9. Python 中的多线程、多进程、协程?

并发方式 适用场景 GIL 影响
多进程 CPU 密集(计算) 不受影响
多线程 IO 密集(网络/文件) 受影响
协程 高并发 IO 单线程不受影响 
多进程:多核并行,内存独立,进程间通信成本高
多线程:共享内存,切换快,GIL 限制并行
协程: 用户态切换,几乎零开销,需要 await 配合

扩展:concurrent.futures 统一线程池/进程池API;asyncio + aiohttp 做异步网络;3.11+ TaskGroup 更安全。

10. with 语句的原理?

with 确保资源用完自动释放,即使抛异常也会执行 __exit__。

with obj:
  进入 → obj.__enter__()
  执行 → 代码块
  退出 → obj.__exit__()  ← 即使抛异常也会执行

with open("file.txt") as f:  # 自动调 __enter__
    data = f.read()
# 离开 with 块自动调 __exit__,文件关了,不管上面报没报错

扩展:contextlib.contextmanager 用生成器写上下文管理器;3.7+ asynccontextmanager;3.14 with(a,b,c): 多上下文简写。

11. __new__ 和 __init__ 的区别?

__new__(cls)  →  创建实例(分配内存,返回 self)
__init__(self) →  初始化实例(给属性赋值)

先 __new__ 创建对象,再 __init__ 初始化属性。自定义 __new__ 主要用于单例模式。

扩展:__new__ 返回非当前类实例则 __init__ 不调用;单例替代方案:模块级全局变量或依赖注入。

12. 什么是元类(metaclass)?

元类是类的类--类定义了一个对象怎么创建,元类定义了一个类怎么创建。

元类(type) → 创建 → 类(Class) → 创建 → 实例(instance)

通俗比喻:工厂生产产品(类 → 对象),那工厂本身是谁造的?元类就是"造工厂的工厂"。

普通开发基本不需要写元类。什么时候用?ORM(自动把类属性映射成数据库字段)、API 自动注册、框架底层才用得上。

扩展:Python 底层就是用 type() 作为默认元类:type('MyClass', (Base,), {'x': 1}) 等价于 class MyClass(Base): x = 1。__init_subclass__ 钩子是比元类更轻量的定制方案--子类被创建时自动调用,Django ORM 大量使用了它。

13. __slots__ 的作用?

普通 Python 对象背后有个 __dict__ 字典存所有属性,灵活但占地方。加了 __slots__ 之后,属性就是固定槽位,不能随便加新属性,但省内存。

__dict__ 方式:  obj → __dict__ → {key: value}  (灵活,内存大)
__slots__ 方式: obj → [slot0, slot1, slot2]   (固定,内存小 40-50%)

就像:__dict__ 是随便租的仓库(灵活但贵),__slots__ 是固定储物柜(只能放规定的但便宜)。大量创建对象时(百万级),省的内存很可观。

扩展:__slots__ 定义的类默认没有 __dict__ 和 __weakref__,除非显式加上。用了 __slots__ 后不能再动态添加属性。对 ORM 模型、dataclass 等大量实例化的场景特别有用。

14. lambda 函数是什么?与 def 的区别?

lambda 是一次性函数--没名字,只能写一行表达式,用完就扔。

def:   def func(x): return x*2   → 有名字,可以有 docstring、多行逻辑
lambda: lambda x: x*2            → 没名字,只能一行表达式,用完就扔

lambda 适合简单场景如 sorted(lst, key=lambda x: x.score),不能写多行逻辑。

扩展:不要 f = lambda x: x*2,应直接 def;复杂逻辑用生成器表达式或列表推导。

15. Python 的 MRO(方法解析顺序)?

MRO 是多继承时方法查找的顺序,Python 3 用 C3 算法保证子类优先、从左到右、每类只出现一次。

钻石继承问题(Diamond Problem):
      A
     / \
    B   C
     \ /
      D

D 的 MRO:D → B → C → A → object
(子类优先,从左到右,每个类只出现一次)

用 类名.__mro__ 查看顺序。

扩展:super() 按 MRO 找下一个类,非直接父类;Mixin 靠 MRO 实现功能组合。

16. finally 中的 return 会覆盖 try 中的 return 吗?

会的。finally 的 return 会覆盖 try 中的返回值。

def demo():
    try:
        return "try 的 return"
    finally:
        return "finally 的 return"  # 最终返回这个!

禁止在 finally 中写 return,只做清理操作。

扩展:3.8+ except* 捕获 ExceptionGroup;with 的 __exit__ 比 finally 更安全。

17. Python 的 typing 模块(类型注解)有什么用?

类型注解提升可读性,配合 MyPy/Pyright 在编码阶段发现类型错误。

def greet(name: str, age: int = 18) -> str:
    return f"Hello {name}, you are {age}"

3.10+ 支持 X | Y 代替 Union,3.11+ 支持 Self 类型。

18. Python dict 的底层实现是什么?

dict 底层是哈希表,通过 hash(key) 映射到数组位置,O(1) 查找。

3.6 前(稀疏表):一个数组存 (hash, key, value),空槽位也占空间,负载因子≈2/3。

3.6+(紧凑字典,省内存25-30%):

indices(稀疏索引表):[3] [-] [1] [-] [0] [-] [2] [-]
entries(紧凑数据表):[e0] [e1] [e2] [e3]  ← 按插入顺序

3.7+ dict 天然有序。

key 必须不可变:key 变则 hash 变,原位置找不到。list/dict/set 不可作 key,int/str/tuple 可以。

哈希冲突:开放寻址法,冲突时探测下一个空位:

perturb = hash_value
index = perturb & mask
while slot_is_occupied(index):
    perturb >>= 5
    index = (5 * index + perturb + 1) & mask

扩容:负载因子>2/3 触发,新容量为下一个2的幂,rehash O(n) 摊还 O(1)。

各操作时间复杂度:

操作 平均 最坏(全冲突)
查找 d[key] O(1) O(n)
插入 O(1) O(n)
删除 O(1) O(n)
key in d O(1) O(n)

OrderedDict vs dict:3.7+ dict 已有序,但 OrderedDict 有 move_to_end()、popitem(last=False)、顺序敏感的相等比较。

扩展:set 底层也是哈希表(只存key),frozenset 是其不可变版。

19. Python 的元类能解决什么实际问题?

元类是"创建类的类"。type 是 Python 内置的元类,所有 class 都是 type 的实例。自定义元类可以在类创建时注入方法、修改属性、注册类。

# 元类自动注册所有子类到 registry
class PluginMeta(type):
    registry = {}
    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(name, bases, namespace)
        if name != 'Plugin':  # 跳过基类
            mcs.registry[name.lower()] = cls
        return cls

class Plugin(metaclass=PluginMeta):
    pass

class AuthPlugin(Plugin):  # 自动注册到 registry
    pass

print(PluginMeta.registry)  # {'authplugin': <class 'AuthPlugin'>}

典型应用:ORM 映射注册(Django Model)、插件系统、自动接口实现。不要为了炫技而用元类,优先考虑装饰器或 __init_subclass__。

扩展:Python 3.6+ 用 __init_subclass__ 替代简单元类场景;Django ORM 用元类将类属性转为数据库字段描述符。

20. Python 内存管理中 __slots__ 的作用?

__slots__ 限制实例属性,用固定数组替代动态字典 __dict__,省内存 40%-60%。

# 不用 __slots__:每个实例一个 __dict__
class Normal:
    def __init__(self, x, y):
        self.x = x
        self.y = y

# 用 __slots__:固定属性槽位,无 __dict__
class Optimized:
    __slots__ = ('x', 'y')
    def __init__(self, x, y):
        self.x = x
        self.y = y

# 内存对比(10万实例):
# Normal:     ~16 MB
# Optimized:  ~6 MB  (省 60%)

代价:无法动态添加属性、不支持多继承混用 __slots__。适用于大量小对象的场景(如游戏角色、ORM 模型)。

扩展:Django Model 默认用 __slots__;dataclass 的 __slots__=True(Python 3.10+)也能获得此优化。

21. Python 的 functools.lru_cache 原理?

lru_cache 用字典+双向链表实现 LRU(最近最少使用)缓存,自动淘汰老数据。

from functools import lru_cache

@lru_cache(maxsize=128)
def fib(n):
    if n < 2: return n
    return fib(n-1) + fib(n-2)

# 不缓存:fib(40) 递归调用 2亿次+
# 缓存后:fib(40) 仅调用 41 次

核心数据结构:字典存缓存(key→value),双向链表维护访问顺序。命中时移到链表头部,满时淘汰尾部。O(1) 查找和更新。

扩展:Python 3.9+ @cache 是无界版本;@lru_cache 参数 maxsize=None 同样无界但不推荐生产用;注意参数必须可哈希。

22. asyncio 的事件循环是怎么实现的？

事件循环是 asyncio 的核心——它不断从队列取协程/任务，按顺序调度执行，直到队列空。

任务入队:
  async def fetch(): ...
  asyncio.create_task(fetch())  → 放入任务队列

事件循环逻辑(简化):
  while True:
    1. 检查 IO 就绪事件(如 socket 可读)
    2. 从队列取待执行协程
    3. 执行到下一个 await(暂停点)
    4. 将 IO 请求注册到 selector/epoll
    5. 阻塞等待，直到有事件就绪
    6. 唤醒对应协程，继续执行

底层依赖：Linux 用 epoll，macOS 用 kqueue，Windows 用 select（效率最低）。

关键点：await 是暂停点，暂停时释放 GIL，事件循环自动切换。协程不是线程，不占用 OS 栈，由 Python 自己调度。

扩展：asyncio.run() 会新建事件循环；生产环境中 uvloop（C 扩展实现的超快事件循环，性能接近 libuv）可将 asyncio 吞吐量提升 2-4 倍。asyncio.gather() 并发执行多个协程，asyncio.wait() 更灵活（可控制超时）。
