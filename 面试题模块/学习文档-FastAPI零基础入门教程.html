1. FastAPI 核心定位

FastAPI 是一个现代 Python Web 框架，专为构建 API 设计。三大核心卖点：

  • 自动文档：写完接口即生成 Swagger UI（/docs）和 ReDoc（/redoc），可在线交互测试。
  • 类型即校验：用 Python 类型提示声明参数 → Pydantic 自动校验 → 不合法直接返回 422 + 详细错误。
  • 原生异步：async/await 语法糖，单线程处理上千并发，性能逼近 Node/Go。

和 Flask / Django 对比

特性 Flask Django FastAPI
类型 微框架（极简） 全栈框架（笨重） 现代异步框架
异步支持 需插件 半吊子 原生 async/await
自动文档 需手写 需装 DRF 自带 Swagger / ReDoc
数据校验 手动 手动 Pydantic 自动
性能 一般 一般 逼近 Node/Go
学习曲线 低 高 低

面试必提的 3 个亮点

亮点1：自动 API 文档
  → 写完接口打开 /docs，Swagger UI 自动生成
  → 前端可在线调试，告别"接口参数是什么格式"的沟通成本

亮点2：类型即校验
  → def create(user: User) → 入参不符合 User 定义？
  → 自动返回 422 + 逐字段错误详情，一行校验代码都不用写

亮点3：原生异步
  → async/await 协程，单线程处理上千并发
  → 底层 Starlette + Uvicorn，单机 8 核纯 CRUD 轻松过万 QPS

面试话术："FastAPI 三个核心能力——自动文档省沟通成本、Pydantic 校验省代码量、原生异步提性能。和 Flask 比，它更适合高并发 API；和 Django 比，它更轻量、学习成本更低。"

3. FastAPI 请求生命周期

理解一个 HTTP 请求从进来到出去的完整流程，是区分"会用"和"真懂"的分水岭。


                    FastAPI 请求生命周期
===========================================================

  客户端                    FastAPI 服务端
    |                           |
    |  GET /users/1?page=1      |
    |-------------------------->|
    |                           |
    |                    ┌──────┴──────┐
    |                    │  Middleware  │  ← 中间件层（CORS, 计时, 日志）
    |                    └──────┬──────┘
    |                           |
    |                    ┌──────┴──────┐
    |                    │   路由匹配   │  ← 匹配 @app.get("/users/{user_id}")
    |                    └──────┬──────┘
    |                           |
    |                    ┌──────┴──────┐
    |                    │  依赖解析    │  ← Depends(get_db), Depends(get_current_user)
    |                    │  (嵌套执行)  │     嵌套依赖按拓扑序依次执行
    |                    └──────┬──────┘
    |                           |
    |                    ┌──────┴──────┐
    |                    │  参数解析    │  ← 路径参数 {user_id} → int
    |                    │  + 校验      │     查询参数 page → int
    |                    │  (Pydantic)  │     不合法 → 立即 422
    |                    └──────┬──────┘
    |                           |
    |                    ┌──────┴──────┐
    |                    │  业务逻辑    │  ← 你的函数体
    |                    │  (端点函数)  │     async def get_user(...)
    |                    └──────┬──────┘
    |                           |
    |                    ┌──────┴──────┐
    |                    │  响应处理    │  ← response_model 过滤字段
    |                    │  (序列化)    │     dict/ORM对象 → JSON
    |                    └──────┬──────┘
    |                           |
    |                    ┌──────┴──────┐
    |                    │  依赖清理    │  ← yield 后的 finally 块
    |                    │  (释放资源)  │     关闭 DB 连接等
    |                    └──────┬──────┘
    |                           |
    |  200 OK  {"id":1,...}    |
    |<--------------------------|
    |                           |

关键时序：
  Middleware.in  →  依赖执行  →  参数校验  →  端点函数  →  响应序列化  →  依赖清理  →  Middleware.out

面试话术："FastAPI 的请求处理是分层的——中间件先拦截，接着解析路由、执行依赖链、校验参数，然后才进入业务函数。响应阶段用 response_model 过滤字段，最后在依赖的 finally 块里释放资源。这套流程保证了每个请求的资源生命周期是确定性的。"

4. 三种参数（路径 / 查询 / 请求体）

FastAPI 根据参数声明位置自动判断参数类型，无需注解。

4.1 路径参数 Path Parameter

# {user_id} 写在 URL 路径里 → 路径参数
@app.get("/users/{user_id}")
def get_user(user_id: int):          # 声明类型 = 自动校验
    return {"user_id": user_id}

# GET /users/abc  → 422（"abc" 不是 int）
# GET /users/123  → {"user_id": 123}

# 枚举约束
from enum import Enum

class Category(str, Enum):
    phone = "phone"
    laptop = "laptop"

@app.get("/products/{category}")
def list_products(category: Category):
    return {"category": category}

# GET /products/tablet  → 422（不在枚举里）
# GET /products/phone   → {"category": "phone"}

4.2 查询参数 Query Parameter

# 不在路径里的函数参数 → 自动当作查询参数
@app.get("/search")
def search(
    keyword: str,                     # 必填
    page: int = 1,                    # 有默认值 → 选填
    size: int = 20,                   # 有默认值 → 选填
    sort: str | None = None           # Optional → 选填
):
    return {"keyword": keyword, "page": page, "size": size, "sort": sort}

# GET /search?keyword=手机              → page=1, size=20, sort=null
# GET /search?keyword=手机&page=2&size=10 → 参数全覆盖

4.3 请求体 Request Body

from pydantic import BaseModel

class ProductCreate(BaseModel):
    name: str
    price: float
    stock: int = 0
    tags: list[str] = []

@app.post("/products")
def create_product(product: ProductCreate):   # Pydantic 模型 → 请求体
    return {"created": product.name, "price": product.price}

# POST /products  Body: {"name": "iPhone", "price": 9999}
# → {"created": "iPhone", "price": 9999.0}

# POST /products  Body: {"name": "iPhone"}   ← 缺少 price
# → 422: price field required（逐字段报错）

4.4 三种参数混用

@app.put("/products/{product_id}")              # 路径参数：product_id
def update_product(
    product_id: int,                            # ← 路径里捕获
    product: ProductCreate,                     # ← 请求体（Pydantic = body）
    force: bool = False                         # ← 查询参数
):
    return {
        "product_id": product_id,
        "update": product.name,
        "force": force
    }

# PUT /products/123?force=true
# Body: {"name": "iPhone 15", "price": 7999}

5. Pydantic：类型即校验

Pydantic 在 FastAPI 中承担双重角色：入参校验 + 出参过滤。你写一个 Pydantic 模型，FastAPI 自动用它校验请求体，不符合返回 422 + 逐字段错误；同时所有约束会自动生成到 Swagger 文档。

5.1 Field 基础校验

from pydantic import BaseModel, Field

class UserCreate(BaseModel):
    name: str = Field(..., min_length=2, max_length=50, description="用户名")
    age: int = Field(ge=18, le=120, description="年龄")
    email: str = Field(..., pattern=r"^\S+@\S+\.\S+$", description="邮箱")
    score: float = Field(default=0.0, ge=0, le=100)
    tags: list[str] = Field(
        default_factory=list,
        max_length=10,
        description="标签列表"
    )

# 请求体不符合？→ 422，逐字段错误详情
# 去 /docs 看 Swagger？→ 所有字段说明、约束、示例自动展示

5.2 嵌套模型

class Address(BaseModel):
    city: str
    street: str
    zip_code: str

class UserFull(BaseModel):
    name: str
    address: Address          # 嵌套对象
    addresses: list[Address]  # 嵌套对象数组

# 请求体示例：
# {
#   "name": "张三",
#   "address": {"city": "北京", "street": "长安街", "zip_code": "100000"},
#   "addresses": [...]
# }

5.3 response_model 出参过滤

class UserInDB(BaseModel):
    id: int
    name: str
    password_hash: str       # 数据库里有，绝不能返回给前端

class UserOut(BaseModel):
    id: int
    name: str
    # 没有 password_hash → 接口响应里不会出现

@app.get("/users/{user_id}", response_model=UserOut)
def get_user(user_id: int):
    user = UserInDB(id=1, name="张三", password_hash="xxx")
    return user
    # FastAPI 自动过滤 password_hash，只返回 UserOut 定义的字段

面试话术："Pydantic 在 FastAPI 里是双重角色——入参校验 + 出参过滤。response_model 自动过滤敏感字段，Field 约束配合 Swagger 自动生成文档，前后端协作体验极好。"

5.4 Field 约束速查表

约束 示例 作用
min_length / max_length Field(min_length=2) 字符串长度限制
ge / le / gt / lt Field(ge=0, le=100) 数值范围（>=, <=, >, <）
pattern Field(pattern=r"^1[3-9]\d{9}$") 正则校验
default / default_factory Field(default_factory=list) 默认值
description Field(description="用户名") Swagger 文档说明
example Field(examples=["张三"]) Swagger 示例值

6. 依赖注入

FastAPI 的依赖注入系统将公共逻辑（鉴权、DB 连接、参数校验）抽成可复用函数，通过 Depends() 自动执行并注入结果。支持 yield 管理资源生命周期，支持嵌套依赖链。

依赖注入执行流程


                   FastAPI 依赖注入流程
===========================================================

  请求进入
      |
      v
  ┌───────────────────────────────────────┐
  │  FastAPI 分析端点函数签名              │
  │  发现 Depends(get_db)                 │
  │  发现 Depends(get_current_user)       │
  └───────────────────┬───────────────────┘
                      |
                      v
  ┌───────────────────────────────────────┐
  │  构建依赖图（Dependency Graph）        │
  │                                       │
  │  get_db ──────────┐                   │
  │                   │                   │
  │  get_current_user─┼── 依赖 db         │
  │                   │                   │
  │  端点函数 ────────┼── 依赖 db + user  │
  └───────────────────┬───────────────────┘
                      |
                      v
  ┌───────────────────────────────────────┐
  │  按拓扑序执行依赖（子依赖先执行）      │
  │                                       │
  │  1. get_db()       → 创建 DB 会话     │
  │  2. get_current_user(db) → 解析 Token │
  │  3. 端点函数(db, user)  → 执行业务    │
  └───────────────────┬───────────────────┘
                      |
                      v
  ┌───────────────────────────────────────┐
  │  响应返回后，逆序执行清理              │
  │                                       │
  │  1. 端点清理                          │
  │  2. get_current_user finally          │
  │  3. get_db finally → 关闭 DB 连接     │
  └───────────────────────────────────────┘
                      |
                      v
                  响应返回

  关键点：
  - 同一请求内，同一依赖只执行一次（结果缓存）
  - yield 之前的代码在请求时执行，finally 在响应后执行
  - 依赖图自动检测循环依赖，报错提示

6.1 公共参数复用

from fastapi import Depends

def common_params(page: int = 1, size: int = 20):
    return {"page": page, "size": size}

@app.get("/products")
def list_products(params: dict = Depends(common_params)):
    return params  # {"page": 1, "size": 20}

@app.get("/orders")
def list_orders(params: dict = Depends(common_params)):
    return params  # 同一个依赖复用，不写重复代码

6.2 数据库连接管理

# database.py
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker

DATABASE_URL = "sqlite+aiosqlite:///./test.db"
engine = create_async_engine(DATABASE_URL)
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)

async def get_db():
    async with AsyncSessionLocal() as session:
        try:
            yield session           # 把连接"借"给业务代码
        finally:
            await session.close()   # 请求结束自动关闭

# main.py
@app.get("/users")
async def get_users(db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(UserModel))
    return result.scalars().all()
    # 连接创建和关闭全自动

6.3 认证依赖

from fastapi import Header, HTTPException

async def get_current_user(token: str = Header(alias="Authorization")):
    if not token.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="未登录")
    user = decode_token(token[7:])
    if user is None:
        raise HTTPException(status_code=401, detail="Token 无效")
    return user

@app.get("/me")
async def read_me(current_user = Depends(get_current_user)):
    return {"user": current_user}

# 20 个需要登录的接口？每个加一句 Depends(get_current_user) 即可

6.4 依赖嵌套

# get_db → get_current_user(依赖 db) → 业务函数(依赖 user)
# 依赖可以层层嵌套，FastAPI 自动按拓扑序解套，结果注入下一层

面试话术："FastAPI 的依赖注入系统是我最喜欢的特性。用 Depends 把鉴权、DB 连接、参数校验等公共逻辑抽成可复用函数，yield 管理资源释放。和 Flask 装饰器、Django 中间件比，依赖注入更灵活——可在函数级别精确控制，还支持嵌套依赖链。"

7. 数据库操作（异步 SQLAlchemy）

SQLAlchemy 2.0 异步模式通过 create_async_engine + AsyncSession 实现非阻塞数据库访问。FastAPI 用 Depends 注入 session，请求结束自动关闭。

7.1 数据模型

# models.py
from sqlalchemy import Column, Integer, String, Float, DateTime
from sqlalchemy.ext.declarative import declarative_base
import datetime

Base = declarative_base()

class Product(Base):
    __tablename__ = "products"

    id = Column(Integer, primary_key=True, index=True)
    name = Column(String(100), nullable=False)
    price = Column(Float, nullable=False)
    stock = Column(Integer, default=0)
    created_at = Column(DateTime, default=datetime.datetime.utcnow)

7.2 Schema 校验层

# schemas.py
from pydantic import BaseModel
from datetime import datetime

class ProductCreate(BaseModel):
    name: str
    price: float
    stock: int = 0

class ProductResponse(BaseModel):
    id: int
    name: str
    price: float
    stock: int
    created_at: datetime

    class Config:
        from_attributes = True    # ORM 对象 → Pydantic 对象

7.3 完整 CRUD

# main.py
from fastapi import FastAPI, Depends, HTTPException
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

app = FastAPI()

@app.post("/products", response_model=ProductResponse, status_code=201)
async def create_product(product: ProductCreate, db: AsyncSession = Depends(get_db)):
    db_product = Product(**product.model_dump())
    db.add(db_product)
    await db.commit()
    await db.refresh(db_product)
    return db_product

@app.get("/products", response_model=list[ProductResponse])
async def list_products(
    skip: int = 0,
    limit: int = 20,
    db: AsyncSession = Depends(get_db)
):
    result = await db.execute(select(Product).offset(skip).limit(limit))
    return result.scalars().all()

@app.get("/products/{product_id}", response_model=ProductResponse)
async def get_product(product_id: int, db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(Product).where(Product.id == product_id))
    product = result.scalar_one_or_none()
    if not product:
        raise HTTPException(status_code=404, detail="商品不存在")
    return product

@app.put("/products/{product_id}", response_model=ProductResponse)
async def update_product(
    product_id: int,
    product: ProductCreate,
    db: AsyncSession = Depends(get_db)
):
    result = await db.execute(select(Product).where(Product.id == product_id))
    db_product = result.scalar_one_or_none()
    if not db_product:
        raise HTTPException(status_code=404, detail="商品不存在")
    for key, value in product.model_dump().items():
        setattr(db_product, key, value)
    await db.commit()
    await db.refresh(db_product)
    return db_product

@app.delete("/products/{product_id}", status_code=204)
async def delete_product(product_id: int, db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(Product).where(Product.id == product_id))
    product = result.scalar_one_or_none()
    if not product:
        raise HTTPException(status_code=404, detail="商品不存在")
    await db.delete(product)
    await db.commit()
    return None

打开 http://localhost:8000/docs —— 5 个接口全都能直接在 Swagger 页面测试。

8. JWT 登录认证

JWT（JSON Web Token）是无状态认证方案：登录成功后签发 Token，后续请求携带 Token 即可识别用户身份，无需服务端存储 Session。

JWT 认证流程


                      JWT 认证流程
===========================================================

  客户端                              FastAPI 服务端
    |                                      |
    |                                      |
    |  [注册/登录]                          |
    |                                      |
    |  POST /login                         |
    |  Body: {username, password}          |
    |------------------------------------->|
    |                                      |
    |                    ┌─────────────────┴─────────────────┐
    |                    │  1. 查数据库，验证用户名密码        │
    |                    │  2. passlib.verify(明文, 哈希)     │
    |                    │  3. 失败 → 401                    │
    |                    │  4. 成功 → 签发 JWT                │
    |                    │     Header:  {"alg": "HS256"}     │
    |                    │     Payload: {"sub": user_id,     │
    |                    │               "exp": 过期时间}     │
    |                    │     Signature: HMAC-SHA256        │
    |                    └─────────────────┬─────────────────┘
    |                                      |
    |  200 OK                              |
    |  {"access_token": "eyJ...",          |
    |   "token_type": "bearer"}            |
    |<-------------------------------------|
    |                                      |
    |  [后续请求 — 携带 Token]              |
    |                                      |
    |  GET /me                             |
    |  Authorization: Bearer eyJ...        |
    |------------------------------------->|
    |                                      |
    |                    ┌─────────────────┴─────────────────┐
    |                    │  1. OAuth2PasswordBearer 提取 Token│
    |                    │  2. jwt.decode(Token, SECRET_KEY)  │
    |                    │  3. 校验 exp（过期时间）            │
    |                    │  4. 提取 payload["sub"] → user_id │
    |                    │  5. 注入到端点函数                  │
    |                    └─────────────────┬─────────────────┘
    |                                      |
    |  200 OK  {"username": "zhangsan"}   |
    |<-------------------------------------|
    |                                      |

  关键点：
  - Token 分三段：Header.Payload.Signature（Base64 编码，用 "." 分隔）
  - 服务端无需存储 Token 状态（无状态认证）
  - 过期时间写在 Payload.exp 里，jwt.decode() 自动校验
  - SECRET_KEY 是签名的核心，生产环境必须使用强随机值
  - Swagger /docs 页面的 Authorize 按钮可直接粘贴 Token 测试

8.1 JWT 工具代码

# auth.py
from datetime import datetime, timedelta
from jose import jwt, JWTError          # pip install python-jose[cryptography]
from passlib.context import CryptContext  # pip install passlib[bcrypt]
from fastapi import Depends, HTTPException
from fastapi.security import OAuth2PasswordBearer

SECRET_KEY = "your-secret-key-change-in-production"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="login")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)

def create_access_token(data: dict):
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)

async def get_current_user(token: str = Depends(oauth2_scheme)):
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        user_id: int = payload.get("sub")
        if user_id is None:
            raise HTTPException(401, "无效凭证")
        return {"user_id": user_id}
    except JWTError:
        raise HTTPException(401, "凭证已过期或无效")

8.2 登录接口 + 受保护接口

# main.py
from fastapi.security import OAuth2PasswordRequestForm

@app.post("/login")
async def login(form_data: OAuth2PasswordRequestForm = Depends()):
    # 实际应查数据库验证用户
    token = create_access_token(data={"sub": form_data.username})
    return {"access_token": token, "token_type": "bearer"}

@app.get("/me")
async def read_me(current_user = Depends(get_current_user)):
    return {"username": current_user["user_id"]}

9.1 请求计时中间件

import time
from fastapi import Request

@app.middleware("http")
async def add_process_time_header(request: Request, call_next):
    start = time.time()
    response = await call_next(request)
    process_time = time.time() - start
    response.headers["X-Process-Time"] = str(process_time)
    return response

9.3 统一异常处理

from fastapi import Request
from fastapi.responses import JSONResponse

class BusinessError(Exception):
    def __init__(self, message: str, code: int = 400):
        self.message = message
        self.code = code

@app.exception_handler(BusinessError)
async def business_exception_handler(request: Request, exc: BusinessError):
    return JSONResponse(
        status_code=exc.code,
        content={"error": exc.message}
    )

@app.exception_handler(404)
async def not_found_handler(request: Request, exc):
    return JSONResponse(status_code=404, content={"error": "资源不存在"})

# 业务代码直接抛异常
@app.get("/items/{item_id}")
async def get_item(item_id: int):
    if item_id == 0:
        raise BusinessError("ID 不能为 0", code=400)
    return {"item_id": item_id}

10. 面试高频 20 问

基础概念

Q1: FastAPI 和 Flask 有什么本质区别？

FastAPI 原生异步（async/await），Flask 同步。FastAPI 用 Pydantic 自动校验和生成文档，Flask 手动处理。FastAPI 基于 ASGI（Starlette），性能逼近 Node.js；Flask 基于 WSGI，传统同步模型。

Q2: FastAPI 为什么这么快？

底层 Starlette（最快 ASGI 框架之一）+ Uvicorn（uvloop 驱动）。Pydantic 核心校验逻辑用 Rust 实现。异步 I/O 不阻塞线程。三个引擎叠加，单机轻松过万 QPS。

Q3: ASGI 和 WSGI 的区别？

WSGI 是同步接口（Django/Flask），一个请求处理完才能处理下一个。ASGI 是异步接口，支持 WebSocket、HTTP/2，FastAPI 基于 ASGI。简单说：WSGI 单车道，ASGI 多车道。

Q4: 路径参数、查询参数、请求体怎么区分？

路径里 {param} 是路径参数，URL 后 ?key=value 是查询参数，函数参数里的 Pydantic 模型自动被当作请求体。FastAPI 靠参数声明位置自动判断，无需额外注解。

Pydantic & 校验

Q5: Pydantic 是什么？FastAPI 怎么用它？

Pydantic 是基于 Python 类型提示的数据校验库。FastAPI 做两件事：请求进来自动校验（不符合返回 422 + 详细错误），响应出去用 response_model 过滤敏感字段。一套模型定义，两头受益。

Q6: response_model 有什么用？

自动过滤返回字段——数据库模型有 20 个字段，response_model 只定义 5 个，就只返回 5 个。密码哈希永远不漏。还能自动转换数据类型、生成响应文档。

Q7: 怎么自定义校验？

Field 约束（min_length、ge/le、pattern）覆盖 80% 场景。复杂逻辑用 @field_validator（Pydantic v2）或 @validator（v1）写自定义校验函数。

Q8: Optional 类型怎么写？

name: str | None = None（Python 3.10+）。FastAPI 自动识别为选填参数，Swagger 文档标记为 optional。

依赖注入

Q9: Depends 是什么？解决了什么问题？

依赖注入系统。把公共逻辑（鉴权、DB 连接、参数校验）抽成函数，通过 Depends() 自动执行并注入结果。消除重复代码，函数签名干净，资源生命周期自动管理。

Q10: yield 在依赖里怎么用？

yield 之前获取资源（如数据库连接），yield 把资源给业务代码用，finally 块在请求结束后自动释放。本质是 Python 的 context manager，FastAPI 做得更优雅。

数据库 & 异步

Q11: FastAPI 怎么连数据库？

SQLAlchemy 2.0 async 模式（create_async_engine + AsyncSession）。用 Depends 注入 session，请求结束自动关闭。一行 Depends(get_db) 搞定。

Q12: async 函数里调同步代码会怎样？

阻塞事件循环，拖慢整个服务。同步耗时操作必须用 run_in_executor 扔到线程池，或直接用异步库。数据库操作用 async SQLAlchemy，HTTP 调用用 httpx。

Q13: 怎么管数据库迁移？

Alembic。alembic init → alembic revision --autogenerate 生成迁移脚本 → alembic upgrade head 执行迁移。

生产环境

Q14: 生产环境怎么部署？

gunicorn -k uvicorn.workers.UvicornWorker main:app，前面挂 Nginx 反向代理。容器化用 Docker + K8s。uvicorn 单跑适合开发，生产必须配 gunicorn 多 worker。

Q15: 后台任务怎么搞？

BackgroundTasks 处理轻量后台任务（接口先返回）。重任务（不允许丢失）用 Celery，别用 BackgroundTasks 扛重活。

Q16: 大文件上传怎么处理？

UploadFile 类型，流式读取不占满内存。配合 shutil.copyfileobj 分块写入磁盘。

Q17: WebSocket 支持吗？

原生支持。from fastapi import WebSocket，@app.websocket("/ws") 几行代码起一个 WebSocket 服务。

对比 & 场景

Q18: 什么场景用 FastAPI，什么场景用 Django？

API 服务、微服务、高并发 → FastAPI。全栈 CMS、Admin 后台（需自带 ORM + Admin 面板）→ Django。做接口用 FastAPI，做网站用 Django。

Q19: FastAPI 有什么缺点？

不自带 ORM（需自己集成 SQLAlchemy），生态不如 Django 成熟，异步编程对初学者有门槛。但不自带 ORM 也是优点——选型灵活。
