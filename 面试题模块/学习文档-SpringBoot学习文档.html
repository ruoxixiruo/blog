Spring Boot 的理念：约定大于配置，开箱即用。只需 SpringApplication.run() 一行代码，Web 服务、数据库连接、安全认证全部自动装配到位。

1. Spring Boot 是什么

1.1 痛点

传统 Spring 项目需要手写大量 XML 配置：web.xml、applicationContext.xml、spring-mvc.xml，还要手动管理依赖版本冲突、打成 WAR 包部署到外部 Tomcat。大部分配置在每个项目里都是重复的。

1.2 技术定义

  • 开箱即用：starter 依赖自动引入关联库
  • 内嵌服务器：Jar 包直接运行（内嵌 Tomcat/Jetty/Undertow）
  • 自动配置：自动装配 Spring 和第三方库
  • 生产就绪：内置 Actuator 健康检查、metrics、外部化配置

1.3 Spring Boot vs Spring MVC

对比项 Spring MVC Spring Boot
配置 XML 或 Java Config，大量手动配置 自动配置，零 XML
依赖管理 手动管理版本和依赖冲突 starter 自动管理
部署 WAR 包到外部 Tomcat Jar 内嵌服务器，独立运行
开发体验 配置繁琐 快速启动，立即运行
监控 无内置 Actuator 端点
外部配置 手动读取 @ConfigurationProperties 自动绑定

本质：Spring Boot 把常见的"如果引入了某依赖就自动配好"的逻辑写在了 spring-boot-autoconfigure 包里。启动时逐个检查条件，满足就装配。

2.2 @SpringBootApplication -- 三合一注解

@SpringBootApplication  // 等价于以下三个：
// @SpringBootConfiguration  -- 继承 @Configuration（标注配置类）
// @EnableAutoConfiguration  -- 启用自动配置（核心）
// @ComponentScan            -- 扫描同包及子包下的 @Component/@Service 等
public class Application { ... }

2.3 自动配置源码追踪

@EnableAutoConfiguration
  → @Import(AutoConfigurationImportSelector.class)
    → AutoConfigurationImportSelector.selectImports()
      → SpringFactoriesLoader.loadFactoryNames()
        → 读取 spring.factories 中的 EnableAutoConfiguration 配置
      → 用 @Conditional 过滤器筛选
      → 返回最终要导入的配置类列表

2.4 条件装配注解

注解 条件 白话
@ConditionalOnClass classpath 存在指定类时生效 "有这个依赖才配"
@ConditionalOnMissingClass classpath 不存在指定类时生效 "没有这个依赖才配"
@ConditionalOnBean 容器中存在指定 Bean 时生效 "有别人先干活了我再干"
@ConditionalOnMissingBean 容器中不存在指定 Bean 时生效 "没人干我才干"
@ConditionalOnProperty 配置属性满足条件时生效 "配置文件里写了这个才配"
@ConditionalOnApplication 在特定应用类型中生效 "是 Web 应用才配"

面试话术：自动配置是面试必问题。核心三步：SpringFactoriesLoader 加载 spring.factories 中注册的配置类 → @Conditional 系列注解按条件过滤 → 满足条件的装配为 Bean。举例：DataSourceAutoConfiguration 检查 classpath 是否有数据源驱动，有则自动创建 DataSource Bean。

// 统一响应包装类
public class ApiResponse<T> {
    private int code;
    private String message;
    private T data;

    public static <T> ApiResponse<T> success(T data) {
        return ApiResponse.<T>builder()
            .code(200).message("成功").data(data).build();
    }

    public static <T> ApiResponse<T> error(int code, String msg) {
        return ApiResponse.<T>builder()
            .code(code).message(msg).build();
    }
}

// 全局异常统一处理
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ApiResponse<Void> handleValidException(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining("; "));
        return ApiResponse.error(400, msg);
    }

    @ExceptionHandler(BusinessException.class)
    public ApiResponse<Void> handleBusinessException(BusinessException e) {
        return ApiResponse.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    public ApiResponse<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return ApiResponse.error(500, "系统内部错误");
    }
}

5. 事务管理 -- 要么全做要么全不做

5.1 核心原则

事务保证一组操作原子性。典型场景：转账（A 扣钱 + B 加钱必须同时成功），Spring 通过 @Transactional 实现声明式事务：方法内所有数据库操作共享一个事务，任何 RuntimeException 触发自动回滚。

5.2 @Transactional 用法

@Service
public class UserService {

    @Transactional
    public void transfer(Long fromId, Long toId, BigDecimal amount) {
        Account from = accountRepository.findById(fromId).orElseThrow();
        Account to = accountRepository.findById(toId).orElseThrow();

        from.setBalance(from.getBalance().subtract(amount));
        to.setBalance(to.getBalance().add(amount));

        accountRepository.save(from);
        accountRepository.save(to);
        // 异常时自动回滚
    }

    @Transactional(rollbackFor = Exception.class)   // 手动设置回滚条件
    public void createUser(UserDTO dto) { ... }

    @Transactional(noRollbackFor = BusinessException.class)  // 不回滚
    public void processOrder(OrderDTO dto) { ... }

    @Transactional(readOnly = true)                 // 只读事务
    public List<User> listUsers() { ... }

    @Transactional(isolation = Isolation.READ_COMMITTED)  // 隔离级别
    public void updateUser(Long id, String name) { ... }

    @Transactional(propagation = Propagation.REQUIRES_NEW)  // 传播行为
    public void sendNotification(Long userId, String message) { ... }
}

5.3 事务隔离级别 -- 4 个等级

级别 说明 脏读 不可重复读 幻读
READ_UNCOMMITTED 未提交读 可能 可能 可能
READ_COMMITTED 已提交读 否 可能 可能
REPEATABLE_READ 可重复读 否 否 可能
SERIALIZABLE 串行化 否 否 否

默认：MySQL 是 REPEATABLE_READ；@Transactional 不指定时用数据库默认值。

5.4 事务传播行为

传播行为 说明
REQUIRED 默认，有事务则加入，无则创建新事务
REQUIRES_NEW 挂起当前事务，创建新事务
SUPPORTS 有事务则加入，无则无事务执行
MANDATORY 必须有事务，否则抛异常
NOT_SUPPORTED 无事务执行，挂起当前事务
NEVER 必须无事务，否则抛异常
NESTED 在当前事务内嵌套执行（Savepoint）

@Service

    public void createOrder(OrderDTO dto) {
        TransactionDefinition def = new DefaultTransactionDefinition();

6.4 JWT 认证实现

@Service
public class JwtService {

    @Value("${jwt.secret}")
    private String secret;

    @Value("${jwt.expiration}")
    private Long expiration;

    // 生成 Token
    public String generateToken(Authentication auth) {
        Map<String, Object> claims = new HashMap<>();
        claims.put("roles", auth.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .collect(Collectors.toList()));

        return Jwts.builder()
            .claims(claims)
            .subject(auth.getUsername())
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + expiration))
            .signWith(Keys.hmacShaKeyFor(secret.getBytes()))
            .compact();
    }

    // 验证并解析 Token
    public Claims parseToken(String token) {
        return Jwts.parser()
            .verifyWith(Keys.hmacShaKeyFor(secret.getBytes()))
            .build()
            .parseSignedClaims(token)
            .getPayload();
    }

    public String getUsernameFromToken(String token) {
        return parseToken(token).getSubject();
    }
}

// 过滤器
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Autowired
    private JwtService jwtService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String header = request.getHeader("Authorization");

        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            try {
                String username = jwtService.getUsernameFromToken(token);
                if (username != null) {
                    UserDetails userDetails = userDetailsService.loadUserByUsername(username);
                    UsernamePasswordAuthenticationToken auth =
                        new UsernamePasswordAuthenticationToken(
                            userDetails, null, userDetails.getAuthorities());
                    auth.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                    SecurityContextHolder.getContext().setAuthentication(auth);
                }
            } catch (JwtException e) {
                response.setStatus(401);
                response.getWriter().write("{\"error\":\"无效的 Token\"}");
                return;
            }
        }
        chain.doFilter(request, response);
    }
}

17. 高频面试题

Q1：Spring Boot 的自动配置原理？

第一高频题。 回答抓住"加载 → 过滤 → 装配"三部曲。

Spring Boot 通过 @EnableAutoConfiguration 触发自动装配： 1. SpringFactoriesLoader 加载 META-INF/spring.factories 2. 读取所有 AutoConfiguration 类 3. 通过 @Conditional* 系列注解过滤 4. 将满足条件的配置类注册为 Bean

关键包：spring-boot-autoconfigure 包含大量自动配置类（如 DataSourceAutoConfiguration、WebMvcAutoConfiguration）。

Q2：@SpringBootApplication 包含哪些注解？

@SpringBootApplication  // = 三合一
// @SpringBootConfiguration   -- 继承 @Configuration
// @EnableAutoConfiguration   -- 启用自动配置
// @ComponentScan             -- 扫描主类所在包及子包

Q3：Spring MVC 的请求处理流程？

请求 → Filter → DispatcherServlet
  → HandlerMapping 匹配 Controller
  → HandlerAdapter 执行（经过 Interceptor）
  → ViewResolver  / @ResponseBody 序列化
  → Filter → 响应

Q4：@Controller 和 @RestController 的区别？

  • @Controller：返回视图名，配合 @ResponseBody 可返回数据
  • @RestController = @Controller + @ResponseBody，直接返回 JSON

Q5：Spring Boot 如何做参数校验？

// 1. DTO 加校验注解
public class UserDTO {
    @NotBlank @Size(min=3, max=20) private String username;
    @Email private String email;
}

// 2. Controller 加 @Valid
@PostMapping("/users")
public User create(@RequestBody @Valid UserDTO dto, BindingResult result) { ... }

// 3. 全局异常处理
@ExceptionHandler(MethodArgumentNotValidException.class)
public ApiResponse<Void> handle(MethodArgumentNotValidException e) { ... }

Q6：Spring Boot 如何实现事务？

声明式事务（最常用）：

@Transactional
public void transfer(Long from, Long to, BigDecimal amount) {
    // 异常时自动回滚（默认仅 RuntimeException）
}

编程式事务：

@Autowired
private PlatformTransactionManager txManager;

public void transfer(...) {
    TransactionStatus status = txManager.getTransaction(def);
    try {
        // 业务逻辑
        txManager.commit(status);
    } catch (Exception e) {
        txManager.rollback(status);
        throw e;
    }
}

Q7：Spring Security 的认证流程？

请求 → SecurityFilterChain
  → UsernamePasswordAuthenticationFilter
  → AuthenticationManager（调用 UserDetailsService）
  → UserDetailsService.loadUserByUsername()
  → 验证密码
  → 返回 Authentication（Principal + Authorities）
  → SecurityContextHolder 保存

Q8：JWT 在 Spring Boot 中的实现流程？

登录 → 验证用户名密码 → JwtService.generateToken(user)
  → 返回 access_token + refresh_token

后续请求 → Authorization: Bearer <token>
  → JwtAuthenticationFilter 拦截
  → JwtService.parseToken(token)
  → 验证签名和过期时间 → 提取用户信息
  → SecurityContextHolder.setAuthentication(auth)

Q9：Spring Boot 如何防止 SQL 注入？

  • JPA/Spring Data：自动使用参数化查询
  • MyBatis：使用 #{} 占位符（参数化），避免 ${}（直接拼接） ```xml ```

Q10：MySQL 的事务隔离级别在 Spring 中如何配置？

Q15：Spring Boot 如何集成 MyBatis？

  1. 添加依赖：mybatis-spring-boot-starter
  2. 配置 mybatis.mapper-locations、mybatis.type-aliases-package
  3. @Mapper 注解标记 Mapper 接口
  4. 在启动类加 @MapperScan("包路径")

Q16：@Value 和 @ConfigurationProperties 的区别？

对比项 @Value @ConfigurationProperties
类型 单个值注入 批量绑定到对象
松散绑定 不支持 支持（maxSize / max-size 均可）
元数据 无 支持 IDE 自动提示
校验 需手动加 @Validated 直接加 @Validated
适用场景 单个简单值 多相关配置项

Q17：Spring Boot 的启动流程？

main() → SpringApplication.run()
  → createApplicationContext()           创建上下文
  → prepareEnvironment()                 准备环境
  → printBanner()                       打印 Banner
  → refreshContext(context)              *** 核心步骤 ***
    → invokeBeanFactoryPostProcessors()    调用 BeanFactory 后置处理器
    → registerBeanPostProcessors()        注册 Bean 后置处理器
    → initMessageSource()                初始化消息源
    → initApplicationEventMulticaster()   初始化事件广播器
    → onRefresh()                        创建内嵌 Web 服务器
    → registerListeners()                注册监听器
    → finishBeanFactoryInitialization()   实例化所有非懒加载单例 Bean
  → callRunners()                        执行 ApplicationRunner / CommandLineRunner

Q18：如何定位 Spring Boot 应用的性能瓶颈？

  1. Actuator + Micrometer：监控接口响应时间
  2. Profiler：JVM 性能分析工具
  3. Arthas：在线诊断工具，不重启应用
  4. 数据库：开启慢查询日志，分析 EXPLAIN
  5. @Timed 注解：记录方法执行时间
