1. Rancher 概述

1.1 什么是 Rancher

Rancher 是一个开源的企业级多集群 Kubernetes 管理平台，由 SUSE 维护。它提供统一的控制面来管理部署在任何位置（数据中心、云、边缘）的 Kubernetes 集群，解决"多个 K8s 集群分散管理"的痛点。

核心定位：不只是一个 UI 工具，而是包含集群创建/导入、RBAC 统一管理、应用商店、监控告警、CI/CD 等一站式管理平台。

面试话术：Rancher 的价值体现在"Kubernetes 集群的管理面而非数据面"——它本身不运行用户业务容器，而是提供统一入口管理所有集群。它既可以用 RKE/RKE2 创建新集群，也可以导入已有集群（包括云厂商托管集群）。

1.2 Rancher vs OpenShift vs KubeSphere

对比项 Rancher OpenShift KubeSphere
厂商 SUSE（开源） Red Hat（商业） 青云（开源）
定位 多集群管理平台 企业级 K8s 发行版 容器混合云 PaaS
集群创建 ✅ RKE/RKE2 ✅ 内置安装器 ✅ KubeKey
多集群管理 ✅ 核心能力 ✅（ACM） ✅ 企业版
内置存储 Longhorn OpenShift Data Foundation 无/LocalPV
内置 DevOps Fleet + Jenkins Jenkins + Tekton Jenkins + S2I
服务网格 Istio 可选 内置 内置 Istio
学习曲线 中 高 中

1.3 核心特性

  • 多集群统一管理：一个控制面管理数百个 K8s 集群
  • 一键集群部署：RKE/RKE2 快速创建生产级集群
  • 统一 RBAC：跨集群的用户权限集中管理
  • 应用商店：Helm Chart 目录一键部署
  • 监控告警：集成 Prometheus + Grafana
  • 日志收集：集成 Elasticsearch + Fluentd + Kibana
  • CI/CD：Fleet 持续部署 + 流水线
  • 安全扫描：镜像安全扫描

3. 部署方式

3.1 Docker 单节点部署（快速体验）

# 单节点快速部署（仅用于测试）
docker run -d --restart=unless-stopped \
  -p 80:80 -p 443:443 \
  --privileged \
  --name rancher-server \
  rancher/rancher:v2.8.1

# 访问 https://<server-ip>/ 获取初始密码
docker logs rancher-server 2>&1 | grep "Bootstrap Password:"

3.2 Helm 高可用部署（生产推荐）

# 前提：已有 K8s 集群（可用 kubeadm 或托管集群）

# 1. 添加 Helm 仓库
helm repo add rancher-stable https://releases.rancher.com/server-charts/stable
helm repo update

# 2. 创建 Namespace
kubectl create namespace cattle-system

# 3. 安装 SSL 证书（使用 cert-manager）
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.0/cert-manager.yaml

# 4. 安装 Rancher
helm install rancher rancher-stable/rancher \
  --namespace cattle-system \
  --set hostname=rancher.example.com \
  --set bootstrapPassword=admin123 \
  --set replicas=3 \
  --set ingress.tls.source=letsEncrypt \
  --set letsEncrypt.email=admin@example.com

# 5. 验证
kubectl -n cattle-system rollout status deploy/rancher

3.3 部署选项对比

部署方式 适合场景 高可用 推荐
Docker 单节点 开发测试、PoC ❌ ❌ 不推荐生产
Helm on K8s 生产环境 ✅ ✅ 推荐
Air-Gap 离线 内网环境 ✅ ✅ 需提前准备镜像
RancherD 边缘/轻量场景 ⚠️ 单点 已弃用

4. 集群管理

4.1 集群类型

集群类型 说明 控制面管理
RKE 集群 Rancher 自研 K8s 安装工具（Docker 驱动） Rancher 管理控制面
RKE2 集群 Rancher 下一代 K8s 发行版（containerd 驱动） Rancher 管理控制面
K3s 集群 轻量级 K8s 发行版（边缘场景） Rancher 管理控制面
导入集群 已有集群（任何方式创建） 用户自行管理

4.2 导入已有集群

# 在 Rancher UI 中获取导入命令
# Cluster Management -> Import Existing Cluster

# 在目标集群执行（注册集群）
kubectl apply -f https://<rancher-server>/v3/import/<token>.yaml

# 验证：Rancher 中集群状态变为 Active
# 原理：该 YAML 会创建 Cluster Agent 和 Node Agent

导入流程：
  1. Rancher 生成导入 YAML（包含 clusterID 和 token）
  2. 在目标集群应用该 YAML
  3. 创建 cattle-system Namespace
  4. 启动 cattle-cluster-agent Deployment
  5. Agent 与 Rancher Server 建立反向隧道连接
  6. Rancher 通过 agent 管理下游集群

4.3 创建新集群

# RKE2 集群配置示例 (Rancher UI 或 API)
apiVersion: provisioning.cattle.io/v1
kind: Cluster
metadata:
  name: production-cluster
  namespace: fleet-default
spec:
  rkeConfig:
    machinePools:
      - name: master
        controlPlaneRole: true
        quantity: 3
        machineConfigRef:
          kind: MachineConfig
          name: node-template
      - name: worker
        workerRole: true
        quantity: 5
        machineConfigRef:
          kind: MachineConfig
          name: node-template
    etcd:
      backupConfig:
        enabled: true
        intervalHours: 12
        retention: 30
    kubernetesVersion: v1.28.7+rke2r1

4.4 RKE2 集群原理

RKE2 (Rancher Kubernetes Engine 2):
  - 基于 containerd（无需 Docker）
  - 通过 etcd 实现控制面高可用
  - 内置 ingress-nginx + Calico/Canal
  - 支持 air-gap 安装
  - 符合 CIS 安全基准

RKE (一代，已逐渐被 RKE2 替代):
  - 基于 Docker (dockershim)
  - 每个组件运行在容器中
  - 通过 SSH 连接节点执行操作

K3s:
  - 二进制单文件，不到 100MB
  - 默认使用 embedded etcd 或 SQLite
  - 适用边缘计算 / IoT

5. 项目管理

5.1 Project 概念

Project 是 Rancher 的顶层资源隔离单元，包含一组 Namespace。一个集群可以包含多个 Project，Project 可以跨团队共享。

+----------------------------------------------+
|               K8s Cluster                     |
|                                               |
|  +------------------+  +------------------+  |
|  | Project A        |  | Project B        |  |
|  | (开发团队)        |  | (测试团队)        |  |
|  |                  |  |                  |  |
|  | Namespace: dev-a |  | Namespace: test  |  |
|  | Namespace: dev-b |  | (resources:      |  |
|  | (resources:      |  |  5C/10G)         |  |
|  |  10C/20G)        |  +------------------+  |
|  +------------------+                         |
+----------------------------------------------+

5.2 资源配额

# Project 级资源配额（影响 Project 内所有 Namespace）
apiVersion: management.cattle.io/v3
kind: Project
metadata:
  name: dev-project
  namespace: c-xxxxx
spec:
  resourceQuota:
    limit:
      limitsCpu: "20"
      limitsMemory: "40Gi"
      requestsCpu: "10"
      requestsMemory: "20Gi"
      persistentvolumeclaims: "10"
      servicesNodePorts: "0"  # 禁用 NodePort
  namespaceDefaultResourceQuota:
    limit:
      limitsCpu: "5"
      limitsMemory: "10Gi"

6.2 RBAC 模型

Rancher 将 RBAC 分为三个层级：

Global (全局)
  |
  |-- Cluster Owner       : 管理所有集群
  |-- Cluster Member      : 查看所有集群
  |-- User Base           : 基本登录权限
  |
  +--> Cluster (集群)
       |
       |-- Cluster Owner   : 管理集群节点/存储/网络
       |-- Cluster Member  : 查看集群资源
       |
       +--> Project (项目)
            |
            |-- Project Owner  : 管理项目内应用/配置
            |-- Project Member : 部署和管理应用
            |-- Read Only      : 只读

6.3 角色继承关系

Global Role (创建用户时分配)
  - Administrator     : 完全控制
  - Cluster Owner     : 创建/管理集群
  - User              : 基本权限

Cluster Role (用户添加到集群时分配)
  - Owner             : 集群完全控制
  - Member            : 查看和操作集群资源
  - Custom Role       : 自定义权限集

Project Role (用户添加到项目时分配)
  - Owner             : 项目完全控制
  - Member            : 操作项目资源
  - Read Only         : 只读访问
  - Custom Role       : 自定义权限集

7.3 持续部署（Continuous Delivery）

Rancher 内置 Fleet 引擎，实现 GitOps 持续部署：

+------------------+       +----------------+       +----------------+
|  Git Repo        |       |  Fleet Manager  |       |   Target       |
|  (应用 Manifests)  |------>|  (Rancher)      |------>|   Clusters     |
+------------------+       +----------------+       +----------------+
  apps/
    nginx/
      deployment.yaml
      service.yaml
    monitoring/
      prometheus.yaml

Fleet 特性:
  - 多集群分发 (同一应用部署到 N 个集群)
  - GitOps (自动同步 Git 仓库状态)
  - 差异化配置 (不同集群使用不同 values)
  - 健康状态追踪
  - 策略控制 (蓝绿/金丝雀发布)

# Fleet GitRepo 示例
apiVersion: fleet.cattle.io/v1alpha1
kind: GitRepo
metadata:
  name: my-app
  namespace: fleet-default
spec:
  repo: https://github.com/team/app-manifests.git
  branch: main
  paths:
    - apps/nginx
  targets:
    - clusterSelector:
        matchLabels:
          env: production

8.1 监控集成

Rancher 通过集成 Prometheus Operator 实现一键部署监控。

启用监控后自动部署:
  - prometheus-operator (Deployment)
  - Prometheus (StatefulSet)

8.2 告警规则

# Rancher UI 或 PrometheusRule
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: k8s-alerts
  namespace: cattle-monitoring-system
spec:
  groups:
    - name: kubernetes
      rules:
        - alert: PodCrashLooping
          expr: rate(kube_pod_container_status_restarts_total[5m]) > 0
          for: 5m
          labels:
            severity: warning
          annotations:
            summary: "Pod {{ $labels.pod }} is crash looping"

        - alert: NodeNotReady
          expr: kube_node_status_condition{condition="Ready",status="true"} == 0
          for: 5m
          labels:
            severity: critical
          annotations:
            summary: "Node {{ $labels.node }} is not ready"

11. Rancher 安全

11.1 Pod 安全策略

# Rancher PSP 模板 (Pod Security Policy)
apiVersion: policy/v1beta1
kind: PodSecurityPolicy
metadata:
  name: restricted
spec:
  privileged: false
  seLinux:
    rule: RunAsAny
  runAsUser:
    rule: MustRunAsNonRoot
  fsGroup:
    rule: RunAsAny
  volumes:
    - "configMap"
    - "emptyDir"
    - "secret"
    - "persistentVolumeClaim"

注意：K8s v1.25+ 中 PSP 已被 Pod Security Admission（PSA）取代，Rancher 也已迁移到 PSA。

11.2 安全扫描

Rancher 集成了安全扫描功能，基于 kube-bench 和 kube-hunter：

  • CIS 基准扫描：检查集群是否符合 CIS Kubernetes Benchmark
  • 镜像扫描：扫描容器镜像中的漏洞（需集成第三方扫描器）
  • 合规报告：生成集群合规性报告

15. 高频面试题

Q1：Rancher 是什么？主要用途？

Rancher 是一个开源的多集群 Kubernetes 管理平台。其核心价值在于用一个控制面管理任意位置（数据中心、云、边缘）的所有 K8s 集群，提供集群创建/导入、统一 RBAC、应用商店、监控、日志、CI/CD 等一站式能力。

Q2：Rancher Server 高可用如何部署？

生产环境推荐使用 Helm 部署在 K8s 集群上（3 副本），前端配置负载均衡器。数据存储在 etcd 中，通过 Rancher Backups App 定期备份。Rancher Server 本身也运行在 K8s 上，可获得 K8s 自愈和滚动更新能力。

Q3：Rancher 的 RBAC 模型？

分三层：Global（全局角色：管理员/用户）、Cluster（集群角色：Owner/Member）、Project（项目角色：Owner/Member/ReadOnly）。权限从上到下继承。支持自定义角色和绑定外部认证系统（LDAP/OIDC）。

Q4：Rancher 支持哪些集群类型？

四类：RKE 集群（一代引擎，Docker 驱动）、RKE2 集群（二代，containerd，推荐）、K3s 集群（边缘/轻量）、导入集群（已有任意集群）。

Q5：Rancher 如何导入现有集群？

1. Rancher UI → Cluster Management → Import Existing Cluster
2. 获取导入 YAML（包含 token 和 clusterID）
3. 在目标集群执行 kubectl apply -f 导入 YAML
4. 目标集群创建 cattle-system Namespace 和 cattle-cluster-agent
5. Agent 通过反向隧道连接 Rancher Server
6. 验证：集群状态变为 Active

Q6：Project 和 Namespace 的关系？

Project 是 Rancher 的概念，包含一组 Namespace。一个集群可以有多个 Project，每个 Project 有独立资源配额。Project 内的 Namespace 共享配额限制。多个团队可以在同一集群中通过 Project 实现隔离。

Q7：Rancher 的监控方案？

基于 Prometheus Operator + Grafana。一键部署后提供 Cluster/Pod/Node/Etcd 级别的预置仪表盘。告警通过 AlertManager 发送到邮件/Slack/Webhook。日志方面支持集成 EFK 或 Loki。

Q8：Rancher 如何实现多集群管理？

通过 Cluster Agent 机制。每个被管集群部署 cattle-cluster-agent（Rancher -> 集群方向）和 cattle-node-agent（集群 -> Rancher 方向），通过 WebSocket 反向隧道通信。Fleet 引擎实现应用的多集群 GitOps 分发。

Q9：Longhorn 是什么？

Rancher 开源的分布式块存储系统，无需外部存储依赖，利用集群节点本地磁盘提供高可用持久卷。支持快照、备份、自动故障迁移、加密和 QoS。

Q10：Rancher 和 OpenShift 的区别？

Rancher 是多集群管理平台，不修改上游 K8s，管理已存在的集群；OpenShift 是企业 K8s 发行版，在 K8s 之上有大量自研组件和 Operator。Rancher 更轻量灵活，OpenShift 更重但开箱即用。
